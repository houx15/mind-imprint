# routebench · 分级路由的实测台

**这是一件工具，不是服务的一部分。** 它不连数据库，不被 `cmd/api` 引用，永远不在
请求路径上。你在想「现在这套路由还是最好的吗」的时候把它跑一遍，它给你一张表和一份
推荐绑定；**改 `models.json` 的是人，不是它**。

这样分开是它存在的理由本身：路由策略还会再改——明年，对着今天还不存在的模型——
那时候重做这件事应该是**一条命令**，而不是重新推导一遍。

```bash
cd apps/api
DASHSCOPE_API_KEY=… go run ./cmd/routebench -out report.md

# 先看一眼要跑什么，一个字也不花：
go run ./cmd/routebench -list

# 只跑一档，一次只动一条才可归因：
go run ./cmd/routebench -cases dialogue -samples 5 -out dialogue.md
```

## 它测四件事，按这个顺序

| 指标 | 怎么来的 | 为什么可信 |
|---|---|---|
| **结构合法性** | 输出喂给该调用点**真实的生产解析函数** | 免费、客观、没得争：解析器不收，生产环境就是给学生弹一个错。这一项不合格的模型直接出局，别的分再高也没用 |
| **延迟** | 首字时间 + 总时长，n 次取中位数 | 单次采样上下浮动三分之一。2026-09-02 就是这样凭空造出过一个并不存在的「档位控制」 |
| **token** | 含 `reasoning_tokens` | 一个「便宜」模型放在会思考的路线上，就是在这一列上不再便宜 |
| **质量** | 判官模型盲评 1–5 | 只给读不出好坏的用例跑。一轮陪练接得好不好，没有任何解析器能告诉你 |

推荐规则按顺序：① 任何一次调用失败、或解析器拒收过一次的，出局；
② 质量比最好的低超过一整分的，出局（一分的带宽足够吸收判官噪声，又窄到能排掉真的更差的）；
③ 剩下的里选输出 token 最少的（含推理），并列时选快的。

## 用例从哪来

用例**跟着 prompt 走，不跟着工具走**：

- `internal/agent/benchcases.go`
- `internal/pbl/benchcases.go`
- `internal/api/benchcases.go`

它们写在这些包里，是因为要测的 system prompt 是**未导出的常量**。抄一份出来放到
工具里，prompt 一改这里就悄悄过时了——而拿一个过时 prompt 测出来的路由决定，
读起来像证据，其实一文不值。

加一个用例＝在 prompt 旁边加一个 `benchcase.Case`，不是在这里加。

用例内容用的是 AGENTS.md 里那条验收主动脉（Phoebe / 中国是否让地球变得更可持续），
不是 lorem ipsum：一个模型在**真的中文论证**上的失败方式，和它在填充文字上的失败方式
不是一回事。而且每个用例都**故意留了一处破绽**——一段跳过了「投入 ≠ 结果」的推理、
一份资源写着「上网查」的框架、一句直接要答案的「那我这段该怎么改？」——
没有破绽的用例，所有模型都会满分，而那张表什么也没说。

## 改实验

`routebench.json`。候选列表是「在位的那个，加上在**这一档的约束下**有可能赢它的那几个」，
不是全量横扫：20 个模型 × 10 个用例 × 3 次是 600 次调用，答不出比 6 个候选更多的东西。

`reflex` / `dialogue` / `digest` 要求关思考，所以 `glm-5.3*` 和 `kimi-k2.7-code`
天然不在候选里——目录会当场拒绝这个绑定，报告里写成「目录拒绝：…」，
而不是假装从来没考虑过它们。

`judgeModel` 必须是旗舰，且**不能同时是候选**：一个模型给自己判卷，不是测量。

## 成本这一列现在是空的

目录里 DashScope 那批模型 `priceUsd` 全是空的，所以排序按 **token 量**，不是按钱。
宁可记成本为空，也不能编一个数字——否则这份目录存在的意义（比成本）当场就废了。
把百炼控制台的费率填进 `models.json`，同一份结果**不用重跑**就能换算成钱。
