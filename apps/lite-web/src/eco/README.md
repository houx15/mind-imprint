# PBL 网页生成与审改原型

本目录承载 LITE PBL 网页制作阶段的交互迁移，不替代现有 `Review` 流程。

## 本地运行

1. 启动真实 AI Gateway，默认地址为 `http://127.0.0.1:8787`。
2. 在仓库根目录安装依赖：

   ```powershell
   corepack pnpm install --frozen-lockfile
   ```

3. 在 `apps/lite-web` 启动 Vite。Gateway 当前允许 8765 端口的本地来源：

   ```powershell
   corepack pnpm dev -- --host 127.0.0.1 --port 8765
   ```

4. 打开：

   ```text
   http://127.0.0.1:8765/src/eco/index.html
   ```

如需使用其他 Gateway 地址，可设置 `VITE_WEB_DESIGN_API_BASE_URL`。密钥只保留在 Gateway，不能写入前端或提交到仓库。

## AI 与演示数据

- 正常流程只使用 Gateway 返回的真实 AI 结果。
- 连接失败时页面明确显示错误，不会自动伪装成 AI 继续执行。
- 本地预设只能由用户点击“使用明确标记的演示数据”后启用，且界面持续标记为演示数据。

## 当前编辑能力

- 拖动组件可在区块内排序，也可移动到其他区块。
- 选中组件后可拖动右侧和下侧把手，分别调整 12 栏宽度与像素高度。
- 选中位置显示快捷批注框，并与左侧主对话框双向同步。
- 每个区块内都可打开组件面板，新增标题、文本框、按钮、纯色块、图片和卡片；图片支持选择本地文件预览。
- 支持删除组件，删除后批注历史仍保留原组件 ID。
- 支持整页纯色背景替换和整页背景批注。
- 页面设计区提供背景、文字、强调色三项调色板，并内置纸张、极简、海岸、夜间和展览五组配色；配色会同步到编辑区与上线检查。
- 标题、正文、按钮和卡片文字支持在模拟页面中直接编辑；修改保留组件 ID，并自动写入左侧操作记录。
- 明确的颜色、宽高、移动、新增和删除要求作为“交互指令”执行；开放性的文案和表达优化继续交给真实 AI。

## 正式主页项目对齐

原型按正式 Lite 主页项目的五关呈现位置：受众、参考站、风格、内容、上线。受众与已有参考结论作为前置资料带入；进入风格关后不再设置单独的“进入白板”步骤，而是在“确认主题和想法”工作面同时展示内容分析、生成要求、参考网站入口和白板。逐区块批注与直接编辑属于内容关；最后提供只读的上线检查页面。原型不会调用正式发布接口或生成公开链接，真正发布仍由主项目的 `Ship` 工具完成。

## 初始模板适配

生成前会根据用户原始要求识别网站类型，目前覆盖个人主页/作品集、研究或 PBL 项目、团队/社团、活动/招募、博客/知识页。识别结果决定站点名称、导航、区块结构和内容槽位；三个 AI 方向再从 17 套语义模板中匹配，并分别使用主项目的 `essay`、`ledger`、`magazine` 真实版式进行比较。个人主页使用“个人首屏 → 关于我 → 作品与经历 → 联系”，不会继续复用研究项目结构。

模板库位于 `web-layout/templateLibrary.ts`。它参考 Hexo 常见的长文阅读、分类卡片和时间归档，GitHub 式开发者项目索引，以及设计师主页常见的大字自述、精选作品网格和案例叙事。模板不复制第三方源码或品牌视觉，只保存网站类型、内容关键词、结构标签和主项目三色 `SitePalette`。匹配过程使用原始 prompt、AI brief 和必要内容共同评分；因此“开发者 + GitHub + 开源项目”和“摄影师 + 作品集 + 案例”会得到不同的优先方向。

## 可选白板

轻量白板直接显示在第一个工作面中，不需要进入或跳过。白板支持区块、文本、图片占位、按钮、分隔线和画笔；结构化组件可以拖动、缩放、改名、删除，并支持撤销和重做。

## 主题与参考资料

左侧对话可以继续补充主题、结构与风格意见，记录后会同步追加到生成要求。参考网站入口支持完整网址、网页 HTML 文件和 PNG/JPG/WebP 截图：HTML 会提取标题、描述、导航、标题层级、页面区块、媒体数量、交互线索和可见配色；截图会分析主色、明暗、对比、视觉密度、长宽比与横向视觉分区。结果统一成为结构化参考约束，并与白板 DSL 一起传给真实 AI，同时参与模板排序。由于浏览器跨域限制，单独添加的网址仍只作为来源线索，界面不会伪装成已读取网页内容。

白板组件被选中后可以在画布内直接修改文字，也可以使用下方属性输入框。白板会编译为可读、可解析的 `MindPage DSL v1`。坐标和尺寸统一归一化到 `1000 × 1000`，每个 `NODE` 保存稳定 ID、类型、父区块、`x/y/w/h` 和内容。生成时，同一份 DSL 一方面作为 Gateway 的结构约束，另一方面由前端确定性地转换为 `PageDocument`；因此三个方向只改变主项目模板的视觉语言，不会覆盖用户画出的区块、组件顺序和版面比例。原始要求仍单独用于网站类型识别。
