# 北京 ECS 能不能拉到科学新闻源 —— 实测（2026-09-03）

**结论：能。GO。** 科学类新闻源没有被墙级别地挡住；失败的几个都是**站点自己的
反爬**或我写错的 URL，不是网络层的问题。所以 P4 的 ingest 可以直接在
`apps/api` 里跑，不需要代理、不需要中转。

实测机器：生产 ECS `47.93.151.131`（Aliyun，Beijing，AS37963）。命令是只读的
`curl`，跑在部署账号下。

## 能连上，但**内容是死的**（⚠️ 比连不上更危险）

| 源 | 状态 | 最新条目 | |
|---|---|---|---|
| WHO news-english | 200 | **2026-02-25** | 半年没更新 |
| ESA · Our_Activities/Space_News | 200 | **2026-01-21** | 八个月没更新 |

🚨 这两个是这次实测里最有价值的发现：**HTTP 200 不等于这个源还活着。** 一个只
检查状态码的健康检查会一直报绿，而星图上会出现半年前的「今日新闻」。所以采集
器必须按**最新条目的日期**判断一个源是否可用，而不是按状态码。ESA 要用
`/rssfeed/science` 那条，不要用 `Our_Activities/Space_News`。

## 拉不到

| 源 | 状态 | 原因 |
|---|---|---|
| Science (AAAS) | 403 | 站点反爬，返回一段 JS 挑战页 |
| EurekAlert | 403 | 同上 |
| NASA（`/feed/`、`/news-release/feed/`、`/rss/dyn/breaking_news.rss` 三条都试过） | 429 | 对这个 IP 限流，换 URL 无效 |
| IEA | 404 | 几个 URL 猜测都不对，需要另找；返回的是 217 KB 的 404 HTML 页 |

三个 403/429 都不值得绕过：反爬是对方明确表达的意愿，而上面能用的十二个源已经
足够撑起一天五颗星。**不做绕过反爬的事。**

## 这对 P4 的设计意味着什么

1. **源清单写在代码里**（像 `disciplines.json` 一样是内容不是用户数据），每条带
   一个 `field` 倾向，方便一天的五颗星覆盖不同主枝。
2. **健康判据是「最新条目的日期」，不是状态码。** 超过 N 天没有新条目的源，
   当天直接跳过，并记一条 warn。
3. **arXiv 要限量**：414 KB、每天全量，只取前若干条。
4. **Quanta 慢（11 秒）**：抓取要有 per-source 超时并且并行，不能串行等它。
5. 抓取失败**不能让那一屏空着**：先用还能用的源凑够五颗，凑不够就诚实少放几颗，
   绝不用昨天的冒充今天的。
