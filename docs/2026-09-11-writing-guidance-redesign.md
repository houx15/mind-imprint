# 写作怎么带：三步不动，把每一步里那件「她动手的事」补上

2026-09-11。上一次（`docs/2026-09-10-reading-guidance-redesign.md`）把带读从「先讲一遍」
改成「先摆一张地图」。这一次是同一件事在写作面上做一遍。

产品负责人的话划定了边界：

> the currently built writing part including structure map, snippet writing are good.
> we follow this big steps, we use that map. but every interaction and other things,
> are possible to iterate.

所以**三步不动**：结构（规划对话 + 思维导图）→ 段落（每块一个引导框 + 她自己写）→
成稿。改的是每一步里发生的事。

## 诊断：四个缺口，每一步都缺同样的四个

### 一 · 整个房间里，她没有一样东西可以用手摆

写作面的 `src/writings/` 里 **`pointer`、`drag`、重新排序，一处都没有**。
思维导图是照着 `writing_outline` 的 `depth`+`position` 画出来的，
她只能打字，画由系统替她画；段落是 textarea；成稿是 textarea；
引导框是四段文字；反馈是一列可以点的要点。

对照阅读室：那边已经有两块能拖的板，走的是一条闭好的回路
（印记在回复里给一张 → 她摆 → 摆完的结果**原样变成一条真的学生消息** → 下一轮印记对着它说话）。

🚨 **这不是要把 2026-08-27 删掉的工具卡搬回来。** 那次删的是**卡片货架**——
一排摆在那儿等她挑、挑了要填表的东西，产品负责人的原话是
「in pro edition we don't really use any card, we only use snippet box」。
板不是货架：它由印记在**这一轮的回复里**递出来，一次一块，摆完就没了，
和阅读室 2026-09-10 上线的那两块是同一种东西、同一条回路。

### 二 · 反馈没有优先级，所以它说的是它先看见的那一条

四份互不相干的材料收敛到同一句话：

| 出处 | 原话 |
|---|---|
| qifeng `technique-router.md` | **高层问题没有解决时，低层润色必须让位。** |
| master-writing `scoring-rubric.md` | **先看观点和材料，最后才看语言。观点没立住的时候去改句子，是在给房子刷漆。** |
| cap-writing-coach | 題意 → 材料 → 段落 → 字句，且明写「**是回饋順序，不是官方配分**」 |
| draft-review-kit `revision` | developmental → line → copy，"polishing prose in a scene you'll later cut is wasted effort" |

四条独立地撞在一起，这就是规矩本身。我们现在**一条都没有**：
`writing_comment.go` 让模型自己挑几条要点，没有任何一处说该先说哪一条。
于是一篇主张还没立住的文章，可能收到的第一条意见是某个词不准。

### 三 · 一条意见落下去之后，什么都不会发生

她收到要点，然后呢？没有「再写一版」的入口，没有第二版，
没有任何地方比较过前后两版，也没有任何地方记得她被教过哪个方法、后来用没用。

master-writing 把这件事写成了硬性的一步：

> 二稿：**逐项对比**——观点是否更早出现、材料是否更具体、结构有没有推进、
> 语言改动是否在为内容服务、**有没有冒出新问题**。

story-coach 把缺了这一步的那种回复直接命名成一个反模式：
**"Diagnostic Without Return"**——
> Every coaching exchange should end with a specific prompt to write.

### 四 · 结构那一步没有停下来的判据，只有模型的感觉

`ready` 完全由模型判断。一个话少的学生（营地走查里的林知遥就是这一种）
可以一直答下去，一直到她自己放弃。阅读室在 2026-09-10 栽过同一个跟头
（「通读那一步会变成审问」，连七轮），修法是**数轮数**，不是让模型更小心。

## 调研

十六个开源写作 skill，浅克隆在 `docs/reference/writing-skills/`（gitignore 掉的），
逐条笔记在 `notes/`。下面只留能落到我们结构上的。

### 一 · 诊断 → 技法：一张有「可观察信号」的表

qifeng 的 `references/technique-router.md` 是整份调研里最值钱的一件：
17 个症状，每一个都配一条**看得见的信号**，而不是一个形容词。

> **论证像观点清单** —— 信号：每段都是一个判断，没有证据与解释；**段落可以任意换序**。
> **信息很多，但全文松散** —— 信号：每段都相关，却不知道为什么按这个顺序；**中间可以任意调换**。
> **人物扁平** —— 信号：依靠「勇敢、努力、善良」等形容词；人物没有选择和矛盾。
> **句子拖沓** —— 信号：主干被「进行、实现、对于、在……方面」掩盖。

它内部选出来的东西长这样，而**最后一行是一句祈使**：

```text
位置：开头第二段
问题：场景与全文主旨没有连接
主技法：核心段／主旨区
风险：一次说尽全部结论
执行：用一段连接人物经历与文章核心问题
```

### 二 · 示范该怎么给，才不算替她写

这是这次调研真正解决的一个老问题。master-writing 的第三步是「只改一句作示范」——
我们禁止。但它示范之后的那句话才是教学发生的地方：

> 「**我只做了两件事**：删掉两个情绪词，加一个和她无关的具体东西。」

🔑 **把「改写后的那句」换成「那两件事」，教学价值全留下，可粘贴的散文一个字都不给。**
draft-review-kit 的编辑角色独立地收敛到同一个形状：意见必须是
「把第5段移到第3段前面」这种**落在已有单位上的操作**，而不是「加强逻辑性」，
更不是一段替她写好的话。

`education-agent-skills` 又给了「什么时候可以真的示范」的四个条件：
**换一个话题、结构同构、故意不写完、明说这是示范**。
我们的 `VocabExamples` 本来就是预先写好、话题和学生无关的，
缺的只有「故意不写完」和一条代码断言。

### 三 · 什么时候别聊了，让她去写

`skill-my-literary-moment` 给了一个**数得出来**的答案，三条满足任一即停：

> 1. **完整性**：三层信息（经历/感受/感悟）均已具象（即使用户回答简短）。
> 2. **意愿**：用户说「就这些」「帮我写吧」。
> 3. **效率**：在经历层和感受层都已完成后，**若连续两次提问用户都只给出极简无实质内容回答**
>    （如「嗯」「没啥」），停止提问。

配套的还有三条同样重要的：**每一层最多补问一次**；
**她一次给了多层，就跳过已有层，只问缺的**；
回答「不知道」「没感觉」→ **接受原话，不反复追问**。

### 四 · 英文那一层：13 个能力，闭表

`ielts-writing-coach` 的 `references/exercise-contracts.md` 给了一张闭表，
四个维度十三个 id，并明写 **"Unsupported issues remain in feedback. Do not invent an ID."**：

| 维度 | skill_id |
|---|---|
| 语法 GRA | `complete_comparison` · `verb_form_trigger` · `sentence_boundary` · `subject_verb_agreement` · `article_control` |
| 词汇 LR | `collocation_perspective` · `word_form_precision` |
| 任务 TR | `task_instruction_coverage` · `mechanism_chain` · `development_relevance` · `weighing_qualification` |
| 连贯 CC | `paragraph_function_order` · `reference_linking` |

它的障碍分类里有一条是给中文母语者的，我们尤其需要：
**`l1_information_structure`——词和内容都对，但整句是按中文语序拼的。**
这既不是语法错，也不是搭配错，我们现在没有任何地方说得出这件事。

它的教学顺序是三步，而且顺序本身有判据：
**保义修复 →（换一个语境）自己再写一次 → 并回段落**，
并且 **"A Version 2 written with assistance cannot prove retention."**

### 五 · 拿她自己的东西当卡片，这件事已经有人做过

`language-learning-sop-kit` 里的 `paragraph-labeler`：学生**划出一段文字、给它贴一个标签**，
标签是闭表六个，系统由标签组合反推这一段的角色。这正是阅读室 `label_roles` 那块板，
只是对象换成**她自己写的句子**。

🔑 换成她自己的文字之后，铁律①反而**变得可以机械验证**：
板上每一张卡片的文字都必须是她自己那一段的**字面子串**，
模型编一句就核对不上，整张板丢掉。阅读室那条「每个 quote 必须逐字抄自文章」
在这里变成「每张卡必须逐字抄自她自己写的东西」。

## 这一次做什么

### 1 · 反馈优先级，写进 schema，代码来守

一条意见（point）的信封加三个字段，全部闭表：

```json
{"layer": 1, "symptom": "claim_list_no_evidence", "quote": "她写的原话",
 "note": "问题是什么", "action": "一句祈使，产出她的下一次尝试"}
```

- `layer` **1=立意 / 2=材料 / 3=结构与段落 / 4=字句**。
  代码：一次回复里若同时存在高层和低层的 point，**低层的全部丢掉**——
  一轮只说最上面那一层。
- `symptom` 取自 qifeng 那 17 条的闭表，编不出来的 id 丢掉这一条。
- `action` **为空就丢掉这一条**。这是 "Diagnostic Without Return" 那个反模式的代码版。
- `quote` 沿用已有的字面子串核对。
- 语气：**对着文字说，别对着人说**。`note`/`action` 里命中「你很/你太/你不够/你没有认真」
  这类对人的评价 → 丢掉这一条。
- **不给分数。** cap-writing-coach 明写不许把几个维度打分加总；
  `education-agent-skills` 给了理由：分数一旦出现在形成性反馈旁边，
  学生只看分数，不看话。

### 2 · 结构那一步：状态由服务端算，停下来由代码判

- 服务端从 `writing_outline` 直接算出**计划现在有什么**（中心论点有没有、
  几条分论点、哪几条底下挂着她自己的材料），当作事实写进 prompt，
  不再让模型从 16 轮对话里重新推一遍。
- **每个槽最多补问一次。**
- **机械停止**：连续两轮低实质回答 → 强制 `ready=true`，不管模型怎么说。
  低实质＝字数低于阈值，或整句落在闭表里（嗯 / 还行 / 不知道 / 没有 / 随便 / 都行 / ok）。
- 她说想开始写 → 立即 ready（已有，保留）。

### 3 · 三块板

卡片从零种变成三种，全部是**她自己的话**，全部逐字核对：

| 板 | 卡片是什么 | 格子是什么 | 它测的是什么 |
|---|---|---|---|
| `material_board` 材料板 | 她在对话里说过的具体事、例子、数据 | 提纲上的各个分论点 + 「先不用」 | **哪一条分论点底下是空的**——她自己看得见，不用谁去说 |
| `order_board` 顺序板 | 她自己的提纲块 | 一条从前到后的位置 | 顺序**由她定**，不由 AI 定。定完印记对着她定的顺序说话 |
| `role_board` 角色板 | 她某一段里的 2–5 句原话 | 主张 / 证据 / 解释 / 让步 / 背景（闭表，服务端填） | 摆不出「证据」这一格，就是这一段没有证据，而她一个字都不用写 |

三条写死在代码里：
- **格子是闭表且由服务端填**，模型只给卡片内容。
- **每张卡的文字必须是她自己文本的字面子串**，核不上就整张板丢掉。
- 摆完之后**不要紧接着再给一块板**（沿用阅读室那条）。

交互沿用 `CoachBoards` 的 `useBoard`：拖是主要动词，**点也能用**
（先点卡、再点格子）——一只手扶着手机的人拖不动卡片。

### 4 · 改一版，并且比一比

- 每条 point 后面跟一个「再写一版」的入口，写完存成这一段的新版本。
- 比对沿用 master-writing 那五条轴，输出**只说变化**，不重新评一遍。
- 掌握度记成 `diagnosed → practicing → applied`，
  🚨 **有印记帮着写出来的第二版不算掌握**——这条来自 IELTS coach，
  它把「被扶着做对」和「自己做对」分开记，我们现在两者不分。

### 5 · 带一篇已经写好的进来

写作 landing 多一个入口：粘贴或上传一篇写完的文章。
建一条 writing，直接落在 `draft`，标记 `origin='brought'`，走成稿那一侧的通篇审阅。

🚨 **报告里要如实说这一篇是带进来的**，结构和段落两步没有发生过。
这不是元数据洁癖：过程评估的全部意义就是分清哪些是她在这里想出来的。

### 6 · 英文那一层

- 13 个 `skill_id` 闭表进 `packages/contracts/vocab/`，与现有 `en_*` 方法挂钩。
- 障碍七分类，含 `l1_information_structure`。
- 一条英文意见的处理顺序：保义修复 → 换一个语境再写一次 → 并回段落。
- **示范必须换话题**：`demo_topic != piece_topic`，代码断言，不是 prompt 里的请求。
- 🚨 **不逐条批改她的每一句英文。** `grammar-skill` 要求
  "Every English user message gets a grammar check, no exceptions"——
  那会把结构那一步的思考变成一场默写。

### 7 · 方法库补两件

- 每个方法加 **`when_not`（什么时候别用）**。没有它，模型会给每一段都配一个比喻。
- 一篇文章有 **1–2 个焦点方法**（master-writing：「一次集中练 1–2 个方法」）。
  现在每块给 1–3 个，六块下来能到十八个——那不是练，是列表。

## 这一次不做，以及为什么

- **逐句语法批改。** 见上，它会杀掉思考那一步。
- **打分 / band。** IELTS 的 0–9、cap 的 0–6 都是别人的考纲，
  而且分数一出现，反馈就没人看了。
- **间隔重复 / 到期任务。** IELTS coach 的 D1/D5/D14 是一件独立的学习产品，
  采它的能力表不等于要建一套排程。
- **多角色评审团。** draft-review-kit 的 panel/debate 很好，但那是给成书用的排场。
- **AI 给候选句、候选开头、候选标题。** 哪怕包装成「你可以参考」，
  它就是可粘贴的正文。story-coach 给这种东西起了个准确的名字：**"Disguised Writing"**。

## 这一轮实际落了什么（2026-09-11 收尾时补）

上面「这一次做什么」是设计。实际进 main 的是其中五件：

| # | 做了没有 | 说明 |
|---|---|---|
| 1 · 反馈优先级 | ✅ | 四层 + 中文 18 / 英文 13 两张闭表 + `action` 必填 + 对人评价过滤。一段一条、整篇三条同层。 |
| 2 · 规划的停止判据 | ✅ | 计划形状由服务端数并当事实喂进 prompt；连续两轮低实质回答强制 `ready`（图上至少有一块）。 |
| 3 · 三块板 | ⬜ 只落了**标注板** | 顺序板、材料板设计在上面，没做。 |
| 4 · 改一版 + 二稿对比 | ❌ | 没做。 |
| 5 · 带一篇进来 | ✅ | `writing.origin`（0146）+ 落地页入口 + 成稿页那行说明。 |
| 6 · 英文那一层 | ◐ 一半 | 13 个能力 id 已经在诊断表里、按语言选表、实测走通；**修复→换语境再写→并回段落**那条序列没做。 |
| 7 · 方法库 `when_not` / 一篇 1–2 个焦点方法 | ❌ | 没做。 |

### 实测（`LIVE_LLM=1`，中英各一篇）

- 中文那篇故意同时埋了第 1 层和第 4 层的毛病，模型把唯一那一刀花在了第 1 层。
- 英文那篇挑的是英文表里的 id，而且**用中文跟她讲、正文保持英文**。
- 🚨 实测当场抓出一个单元测试永远绿的 bug：提示词写着「method 从【可用的方法】
  里挑」，而那张表**从来没进过 prompt**，模型一直在造 id。见对应 commit。

### 走查（模拟学生，`e2e/writewalk/`）

🚨 头四个「发现」里有三个是**走查自己的毛病**，不是产品的 —— 和
`camp-simulated-students-2026-09-04` 记的是同一个坑：**判据字段写错，
会把一个走通了的产品记成走不通。**

1. 屏幕只渲染 placeholder 命中白名单的输入框 ⇒ 落地页那个框在学生眼里不存在，
   她连着十步报「没有输入框」。
2. `write` 用在对话框上只填不发 ⇒ 印记一轮都不回。
3. 结构那一步是全屏的 `PlanningView`，**它有自己的 Composer**
   （「说说你的想法」），第一版的对话框识别只认房间里那个。
4. 学生模型自己的输出被 token 上限截断，她反复去补同一段 —— 也不是产品的事。
