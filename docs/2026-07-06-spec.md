> 配套：《思维印记_Demo_PRD.md》（v0.1，底座细节）《思维印记_设计Brief.md》（待随本文更新）

## 0. 相对 v0.1 变了什么（给读过 v0.1 的人）

1. **定位升级**：从「带引导工具卡的 AI 工具」→「**AI 原生教育平台**」，核心价值是教好**批判性思维**与**产品思维**。原来的工具卡体系，只是批判性思维的一部分。
2. **两大支柱**：新增「**课程**」支柱（系统地学）；原来的「工具」重命名为「**工作台 / Working Portal**」（用所学去做真实的事）。
3. **工具卡彻底重做**：从「填表单」→「**材料锚定的交互**」。卡的模板不再直接呈现给学生填，而是作为**给 AI 的输入**；AI 结合学生正在读/写的具体材料，给出**指向原文的具体问题**，并邀请学生从不同角度提出自己的问题。抽象的卡结构只在**收口/用完之后**呈现。
4. **信息架构**：顶层导航变为 **课程 / 工作台 / 记录**；工具卡库不再是顶层，而是**归入个人数据（一种收藏）**。
5. **统一引擎**：课程里的「挑战」与工作台里的「工具卡」是**同一种原子单元**（材料锚定的交互组件），共用一套运行时——重构不因此翻倍工作量。

## 1. 新定位

**思维印记是一个 AI 原生教育平台，教好两件最稀缺的事：批判性思维、产品思维。**

它不是视频课，不是题库，也不只是一个 AI 工具。它由两个咬合的支柱构成：

- **课程（Course）= 学**：AI 交互式课程，系统地把一套思维方式 / 工具教给学生。
- **工作台（Working Portal）= 用**：学生带自己的真实任务进来，在引导下运用所学的工具去思考。

一句话：**课程是带教练的健身房，工作台是真实的举重。** 两者之间由「个人工具卡收藏」桥接——课程里学会的工具，在工作台里可被调用。

四条设计铁律（沿用 v0.1，不变）：AI 克制不替学生定论 · 不操纵（不做上瘾式机制、不强制弹窗）· 一次只问一个 · 过程即数据。

---

## 2. 统一的原子单元：交互组件（先立这条，后面都靠它）

**课程里的「挑战」与工作台里的「工具卡」，本质是同一个东西**——一个材料锚定、框架驱动的交互组件（下称「交互组件」/ Interactive Component）。区别只是语境：

- 在**课程**里，它是一个被教学内容包裹、有脚手架的「挑战」。
- 在**工作台**里，它由 AI 在恰当时机召唤到学生自己的材料上，是一张「工具卡」。

因此工程只建**一套交互组件运行时**（沿用并扩展 v0.1 的 schema 驱动运行时），同时驱动两个支柱。这是整个重构的成本控制点，务必守住。

---

## 3. 信息架构 / 导航

顶层三个 tab：**课程 / 工作台 / 记录**。

- **课程**：课程卡网格 → 进入某课 = 课程播放器（§6）。
- **工作台**：门户切换器 —— **批判性思维与写作**（本期做）、**产品设计**（未来，占位锁定）。进入门户 = 任务目录 + 任务工作区（§5，即 v0.1 的「任务」页演化而来）。
- **记录**：学习记录（GitHub 式活动日历 + 成长回顾）+ **工具卡收藏**（个人数据的一部分，见 §7）。

刻意**不**做常驻左侧会话列表（区别于聊天 App，强调「任务」与专注）。工具卡库**不是**顶层项，它是「记录」里的个人收藏。

## 4. 工具卡新模型：材料锚定的交互（本次重构的核心）

### 4.1 核心转变：模板是给 AI 的输入，不是给学生的表单

旧模型（v0.1）把 CRAAP 的五个维度渲染成表单让学生填——低影响、无聊，训练的是「填格子」而不是思考。

**新模型**：卡的模板（维度、追问意图）**不直接呈现给学生**，而是**作为 AI 的输入（一把镜头 / rubric）**。AI 把这把镜头对准学生**正在读或写的具体材料**，产出**指向原文具体位置的问题**，并**邀请学生从不同角度提出自己的问题**。

真实老师就是这么做的：不是发一张 CRAAP 表，而是把学生正读的文章摊开、圈出某句话、问「这句『美航局发现』——微信转载是权威吗？背后的原始出处是谁？」，再请学生自己圈、自己问。

### 4.2 一次材料锚定卡的运行流程（以 CRAAP × Phoebe 的公众号文章为例）

1. **载入材料**：把学生正读/正写的文本带 span 索引载入。
2. **AI 施加镜头**：AI 用卡的维度逐条审视材料，生成**锚定到具体 span 的问题** → 原文对应处高亮、问题浮在旁注（如「Authority：这处『美航局发现』——转载者是权威，还是另有原始来源？」）。
3. **学生交互**：学生回答这些锚定问题；**并可自己划线、提出自己的问题/判断**（「我不信这句，因为……」），甚至从卡未覆盖的角度提问。
4. **收口时才显抽象结构**：用完之后（或收尾阶段），才把卡的抽象框架（CRAAP 五维长什么样）呈现给学生，让他从「刚才这段具体经历」抽象出**可迁移的框架**。框架是**收获**，不是入口表单。

### 4.3 「镜头对准文本」可同时用于读与写

同一机制，两种用法：

- **对准别人的材料 → 评估它**（CRAAP / SIFT：这来源可信吗）。
- **对准学生自己的草稿 → 改进它**（让步段 / 论证结构：高亮学生的段落，「这段只断言没让步——把最强的反方证据划出来」）。

所以卡永远是「**一把思维框架，作为标注层，覆盖在一段文本上**」——主动阅读 + 主动写作，而非填表。

### 4.4 卡契约的扩展（在 v0.1 基础上）

- 新增 `mode`：本期**统一为 `annotation`（材料锚定）**。`form`（无材料的纯推理脚手架）作为少数例外保留字段，但本期默认不用。
- 卡 spec 现在装的是：`dimensions`（每维的追问意图，喂 AI）、`invite_student_questions`（邀请学生提问的策略）、`summary_view`（收口时呈现的抽象框架）。
- **标准信封扩展**：除原字段外，新增 `anchors`（AI 与学生的标注：span、来源方=AI/学生、维度、问题、回答）。这套锚定数据仍然序列化进同一个标准信封，喂过程树与评估。
- 单一真相源不变：卡 spec 在 registry；决策层目录从它派生。

### 4.5 材料从哪来

- **工作台**：学生粘入 / 引用他正在读的材料，或他自己的草稿。
- **课程**：材料由课程内容提供（预置的样例文本）。

## 5. 工作台规格（批判性思维与写作）

> 即 v0.1「任务」页的演化。产品设计门户为未来，本期只做批判性思维与写作门户。

### 5.1 门户与任务目录
- 进入工作台 → 门户切换器（批判性思维与写作【可用】/ 产品设计【锁定·敬请期待】）。
- 门户内 = 任务目录：所有任务网格，每张含标题、状态、上次活动、迷你进度；顶部「+ 新任务」入口，文案「你想搞懂什么？」。

### 5.2 任务工作区（核心，专注全屏）
- **中央**：对话主轴 + **材料区**。当任务涉及具体材料/写作时，材料在此展示，并可被高亮、标注（这是新模型的落点）。
- **工具卡 = 材料上的标注层**：AI 在恰当时机召唤卡（沿用 `summon_card`，§见 v0.1），卡以**锚定问题 + 高亮**的形式作用在材料上，而非底部表单。
  - 交互形态请设计师重点设计：AI 锚定问题（旁注）、学生自划线自提问、收口抽象框架三个环节。
- **右侧**：过程树（只读，边做边长，可折叠）。
- **顶部**：「← 返回所有任务」。

### 5.3 「工具卡列表页」= 暂缺，走数据收藏
- 工作台内**不需要**一个独立的卡列表页给学生挑卡——卡由 AI 按语境召唤。
- 学生「有哪些卡」体现在**记录 → 工具卡收藏**（§7）。
- 【给设计师的开放问题】工作台内是否需要一个轻量的「可用工具」提示条？倾向不需要，避免学生「挑工具」而非「被引导」。

### 5.4 过程树与评估（沿用 v0.1）
- 过程树七类节点：任务根 / 子问题 / 工具卡使用 / 尝试草稿 / 关键知识 / 让步修订 / 反身收口。
- 评估那一刀（旗舰、异步）产出 rubric 评级（SOLO L1–L4）+ 过程叙述，本期**只呈现给学生**（教师端不做）。

## 6. 课程规格（AI 交互式课程）

### 6.1 课程 tab / 课程卡
课程卡网格。每张课程卡展示**概览信息**：
- 这是什么（课程主题 / 教什么思维方式或工具）；
- 你会经历什么、学到什么；
- 包含多少个 task、多少个 tool；
- 预计耗时区间（range）。

### 6.2 课程播放器（点进某课后）
- **顶部**：阶段状态可视化（stage / challenge 的总体进度：已完成 / 当前 / 未解锁）。课程由若干 **stage** 与 **challenge** 组成。
- **主体（教学内容）**：像一份**交互式 PPT，但不是 PPT，而是前端代码驱动**，因此高度灵活、可交互。每一页是一个「场景」，有两类：
  1. **讲授场景**：文字 + 图像讲解某个知识点；AI 以**语音 + 字幕**讲述。
  2. **挑战场景**：需要学生参与的交互 —— **复用 §2 的交互组件运行时**（即工具卡的同一套引擎），只是这里被教学脚手架包裹。
- **右侧**：随时向 AI 提问的面板，**携带当前课程页的上下文**；学生也可按一个按钮，**用语音**把问题发给 AI 老师。

### 6.3 课程新增的技术能力
- **语音**：AI 老师的 **TTS**（语音讲述 + 字幕）与学生的 **STT**（语音提问）。这是相对 v0.1 唯一实质新增的技术栈，请工程预留。
- 其余（挑战场景、标准信封、评估）复用现有运行时。

### 6.4 课程与工作台的关系
- 课程系统地教一套工具 / 思维方式；工作台是学生把它用在自己真实材料上的地方。
- 桥接 = 工具卡收藏：课程里学会的工具，进入个人收藏，在工作台可被 AI 召唤。

## 7. 数据模型变化

在 v0.1 数据模型（task / message / card_instance / process_node / evaluation）基础上：

- **card_instance / 标准信封**：新增 `anchors`（材料标注：span、author=AI/student、dimension、question、answer）与 `summary_fill`（收口时的抽象框架填充）。
- **material**（新）：一段被卡作用的文本（学生粘入的阅读材料 / 自己的草稿 / 课程预置素材），带 span 索引。`card_instance` 通过 material_id + anchors 绑定它。
- **工具卡收藏（个人数据，非顶层）**：从 `card_instance` 聚合派生——学生学过 / 用过哪些卡、各用了几次、最近使用。呈现在「记录」里。
- **课程侧（新）**：`course`（元数据：主题、简介、task 数、tool 数、耗时区间）、`stage` / `challenge`、`course_progress`（学生在某课的阶段状态）。挑战产生的交互仍落进标准信封（与工作台同构）。

配置（静态文件）：卡 spec registry、rubric 维度、决策层目录、**课程内容包**（每门课的场景序列 + 预置素材）。

## 8. 承接不变项（v0.1 仍然成立）

Web 端 · 前后端分离（后端薄：LLM 网关 + 持久化 + 异步评估）· 客户端绝不直连模型 · schema 驱动的交互组件运行时（现扩展为材料锚定）· 单一函数 + enum 的 `summon_card` 调用 · 标准信封为数据脊椎 · 过程树 · 评估陪练/评估分离与模型路由 · 不是聊天 App · 不是编辑器（不做撰写/排版/提交）· 不做游戏化上瘾机制。

技术栈建议不变：前端 React + Vite + TS + Tailwind；后端 Node + Express（TS）；SQLite；模型走 Anthropic API（需用户 key）。课程新增 TTS / STT。

## 9. 范围与排期建议

**本次交付物 = 规格文档，不写代码。** 设计师据此（+ 本文）先出设计，工程随后实现。

建议排期：

1. **P0 · 工作台（批判性思维与写作）+ 材料锚定卡**：这是重构最核心、最能证明新价值的一条。把交互组件运行时扩展成材料锚定，把 CRAAP / SIFT / 让步段做成锚定式交互。
2. **P1 · 课程支柱**：课程卡、课程播放器（讲授 + 挑战场景）、语音 TTS/STT、阶段进度。挑战复用 P0 的运行时。
3. **P2 · 产品设计门户**：第二个工作台门户，未来。
4. 教师端：仍不做（评估数据照跑，只给学生）。

## 10. 给设计师的重点与开放问题

**重点设计（新东西）：**
- **材料锚定卡的三环节交互**：AI 锚定问题（原文高亮 + 旁注）→ 学生自划线 / 自提问 / 多角度提问 → 收口时呈现抽象框架。这是全场最重要的新交互，值得最多打磨。
- **课程播放器**：交互式（非 PPT）代码驱动的场景；讲授场景（AI 语音 + 字幕 + 图文）与挑战场景（复用交互组件）；右侧携上下文的随时提问 + 语音按钮；顶部阶段进度。
- **课程卡**：概览信息（是什么 / 经历与收获 / task 数 tool 数 / 耗时区间）。

**开放问题（请与产品对齐）：**
1. 工作台内是否要一个「可用工具」提示条？（倾向不要，避免学生挑工具而非被引导。）
2. 材料锚定卡在工作台里的呈现——是覆盖在中央材料区，还是独立面板？（v0.1 的「底部大窗」在有材料时可能不再合适。）
3. 收口时的「抽象框架」呈现，是每张卡用完即弹，还是攒到任务收尾统一回顾？

## 11. 风格（承接《设计Brief》）

Toddle 那类的亲和与清晰，但**调低活泼、加冷静专注的智识感**：沉稳靛蓝主色、大量留白、动效轻、少强提示。与「不靠多巴胺留人」的铁律自洽。设计 Brief 将据本文同步更新。
