# 上下文这一侧的三根杠杆：顺序、渐进披露、压缩

2026-09-20。承接 `2026-09-20-lite-ai-cost-and-routing.md`（那一份讲价格和选型）。
这一份只讲**同一个模型下，怎么少花钱而不动教学效果**。

前提先纠一个我自己写错的判断。

## 0 · 纠正：缓存不等于「文章白发」

上一份里我写过「重发全文只花票面的五分之一，所以裁剪不是主要杠杆」。
**前半句对，后半句错。** 算一下实测那一轮（deepseek-v4-pro，7,872 入 / 7,168 命中 / 142 出）：

| | ¥ | 占一轮 |
|---|---|---|
| 未命中的输入 | 0.0084 | 29% |
| **命中的输入（主要是文章）** | **0.0172** | **59%** |
| 输出 | 0.0034 | 12% |
| 合计 | 0.0291 | |

文章占了 prompt 的九成，**即便按两折计价，它仍然是一轮里最大的一笔**。
所以裁剪是**第一等**的杠杆，不是边角料。只送当前这个「部分」（约省 5,500 token）
算出来是 **−45%**。

## 1 · 顺序（已做，已实测）

通道按**公共前缀**打折。所以块的排法就是价格：最稳的排前面，每轮都变的排后面。

- **阅读室本来就是对的**：system → 标题 → 导读 → 体裁 → 分部分 → 正文 → 步骤 →
  对话 → 她刚说的话。实测第二轮起命中 **91%–99%**。
- **写作室本来是反的**：`BuildProjectCoachContext` 排的是
  「房间 → 对话 → 状态投影」，而
  ① 对话是一个**滑动窗口**（第 13 轮把第 1 轮挤掉 ⇒ 整个前缀错位），
  ② 状态投影里还有一句**每轮都变**的「她现在 N 字，还差 M 字」，排在提纲和
  她正文的**前面**。
  两件事叠起来的结果：**命中 0%**。她那几千字的正文，每一轮都按全价重买一次。

实测（qwen3.8-flash，4,800 token 的真实尺寸，连着两轮）：

| 排法 | prompt | cached | 命中 |
|---|---|---|---|
| 原来的 | 4,815 | 0 | **0%** |
| 改过的 | 4,810 | 4,096 | **85%** |

改法：投影（含正文）→ 对话 → 她在哪个房间 → 这一轮要做什么；
「还差多少字」挪到投影**最后**。顺带和既有的一条教训对上了：
要它照做的话放在最后最管用（「覆盖段放 prompt 最后」）。

🚨 **这条从此是一条契约**：任何时候往 prompt 前面加一个会变的东西
（计时、计数、板的状态、随机 id），就是把它后面的所有东西改成全价。

## 2 · 渐进披露（建议，未做）

**现在**：每一轮都发整篇文章（上限 9,000 字），哪怕这一步只管第 3 段。
**而服务端已经知道这一步管哪几段**——`outline.Parts` 就是为此算的，
prompt 里甚至已经写着「当前这一步只管它标明的那几段」。

**建议**：当前这个「部分」的段落给全文；其余部分只给
`[b7] （第三部分·第7–9段，讲反例）` 这样一行。整篇仍然「在场」，
只是没展开——和现在超预算时写「（这一段没放进来，但它存在）」是同一套做法。

- 省：约 5,500 token/轮 ⇒ **−45%**，与换模型**叠加**。
- 风险：
  - `connect` 这类跨部分的步骤需要看到两处 ⇒ **按步骤类型决定展开哪几部分**，
    不是一刀切。
  - 幻引判据 (`reading_ghostquote.go`) 拿文章当语料。没展开的段落不在语料里 ⇒
    模型引它就会被判失败。这其实是**对的**（它不该引一段它看不见的话），
    但得确认判据读的是「展开了的那份」，不是整篇。
- 🚨 **单独上，单独量。** 和换模型一起上就归因不了。

## 3 · 子 agent（建议，已有先例）

段落分析这类「只看一段、答完就结束」的活，本来就该是一次独立的小调用，
而不是主陪练那一轮的负担。**`reading_block.go` 的 explain 已经是这个形状**：
邻段有预算、结果按 `(block, tool, sentence)` 缓存、命中直接回放、
系统 prompt 只有约 500 字。它是两个房间里最省的调用，可以照抄。

值得照这个形状搬过去的：句子级的语法/查词、单段落体检。
**不该搬的**：需要全局的判断（她这一步算不算走完、下一步领哪儿），
那些正是主陪练存在的理由。

## 4 · 压缩（建议，未做，且有一个坑）

pro 已经有了：`maybeCompactBackstop` + `ComposeDigestMerge`（digest 档），
超预算才触发、不超**一次模型调用都不花**。**lite 两个房间没有**，
用的是固定滑窗（阅读 14 / 写作 12 / 规划 16）。

lite 要不要压缩，取决于压什么：

| 内容 | 压不压 | 为什么 |
|---|---|---|
| 印记自己早先说的话 | **压** | 它的措辞没有证据价值，压成「你已经带她看过 X」不丢东西 |
| 她早先说的话 | **不压** | 她的原话是过程数据，也是幻引判据的语料 |
| 她的正文 / 文章原文 | **绝不压** | 逐字比对全靠它；压了判据就失效 |

🚨 **坑：压缩本身会打碎缓存。** 每轮重新摘要 ⇒ 前缀每轮都变，
既付了一次 digest 调用，又把后面所有东西改成全价——**比不压更贵**。
所以只有**定点压、压完固定不动**才有意义：到阈值压一次、写库、
之后很多轮都复用**同一段字**，让它留在缓存前缀里。
pro 那个 backstop 正好是这个形状（写库 + 只在溢出时触发），可以直接借。

## 建议的上线顺序（一次一条，否则归因不了）

1. **顺序**（已做）：不动语义，只动排法 ⇒ 写作室输入 −68%。
2. **换档**（等实测）：按「最差一项不低于在位」卡住，再让价格决定。
3. **渐进披露**：阅读室 −45%，要按步骤类型决定展开哪几部分。
4. **压缩**：定点压印记自己的话，复用同一段摘要。
