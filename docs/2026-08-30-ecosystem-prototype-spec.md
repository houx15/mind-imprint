# 生态原型 · 世界 / 我的树 / PBL — Static Frontend Prototype Spec

> 2026-08-30 · lite edition (`apps/lite-web/src/eco/`), mounted at `/eco/*`.
> **Pure frontend.** No API, no persistence beyond `sessionStorage`. Every
> screen walks end-to-end on mock data so the flow can be judged before any
> backend is written.

## 关键词
易用 · 清晰 · 有趣 · 科技感。四个词都要能在每一屏上指出来。

## 0 · 一句话
把「思维印记」从两个房间（阅读 / 写作）扩成一个**生态**：
**世界**给她值得好奇的东西，**我的树**把她的好奇长成她自己的样子，
**项目 (PBL)** 让她把它做出来，**我的主页**是这一切的家。

## 1 · 双视图首页 · 世界 ⇄ 我的家

一个开关，两个世界。切换本身是产品的第一个「哇」。

| | 世界 | 我的家 |
|---|---|---|
| 底色 | 暖夜空（近黑暖调 + 星尘） | 暖纸（`--mk-paper`） |
| 隐喻 | 向外 · 未被发现的行星 | 向内 · 正在长的树 |
| 时间 | 换一天 → 换一批新闻 | 拖时间 → 看树怎么长起来的 |

两边都有时间轴，方向相反 —— 这是刻意的对称：**世界随时间流动，我随时间生长。**

## 2 · 世界 · 新闻星图

- **每天正好五颗**。不是信息流，是五件值得知道的事。
- **行星漂浮**：不同轨道半径、大小（大小=重要度）、颜色（=领域）。慢速漂移 + 指针视差。
- **等待被发现**：未点开的行星蒙着一层，只有一个领域符号。点亮后才显示标题。计数写作「你点亮了 2 / 5」——只在当天，**没有连胜、没有排行榜、没有徽章**（铁律②）。
- **钩子问题**：每颗行星有一个问题，不是摘要。悬停时它先出现，标题在后。
- **中 / EN**：标题、摘要、钩子问题都是双语，一键切换。
- **不谈政治**：政治与冲突类**在源头过滤**，并且**明说**——一枚可点开的说明片「已过滤：政治与冲突」，解释我们为什么不在这里讨论它。
- **领域筛选**：科技 / 科学 / 环境 / 太空 / 健康 / 文化 / 经济 / 教育。
- **打开一颗** → 侧面板：钩子问题（最大）、双语摘要、来源与日期、四个出口：
  `读这篇` → 阅读室 ｜ `问印记` → 对话 ｜ `收进我的树` → 长一个关键词 ｜ `做成项目` → PBL。
- **为什么是这五条**：一枚透明度说明，讲清挑选标准。

## 2.1 · 真新闻从哪来（下一步，不在本原型里）

原型里的 25 条是**手写的示例内容**，界面上有「原型数据」标识。接真数据时，
`NewsItem`（`eco/data/types.ts`）的形状不用改 —— 它就是按这条流水线的产物设计的：

```
新闻源 API ──► ① 抓取（每日一次，按领域拉 100~300 条）
              ② 政治/冲突过滤（分类器 + 关键词黑名单；宁可错杀）
              ③ 去重（同一事件多家报道，聚成一条）
              ④ 排序打分 → 取前 5（打分标准 = SELECTION_NOTE 那五条）
              ⑤ LLM 一次调用生成：双语标题/摘要 + 钩子问题 + keywords
              ⑥ 落库缓存（每天一张 5 条的表，供当天所有学生共用）
```

**几个已经能定的决定：**
- **每天一次批处理，不是按人生成。** 五条对全校是同一份，所以是 1 次/天的成本，
  不是 1 次/学生。这也让「今天大家都看过这五条」成为教室里可以讨论的事。
- **钩子问题是 LLM 写的，标题和摘要也是 LLM 译写的**，所以三者都要标注来源：
  卡片上写清楚原始出处（`source`），不冒充原文。走旗舰档模型（评估不降级同理），
  一天 5 条的量，成本可以忽略。
- **政治过滤放在第 ② 步（入库前），不是第 ⑤ 步（渲染前）。** 过滤发生在数据层，
  界面只负责把「我们过滤了什么、为什么」说出来（`POLITICS_NOTE`）。
- **候选源**（待定，需要评估版权与中国大陆可达性）：GNews / NewsAPI /
  Currents / 各机构 RSS（Nature、Science、NASA、ESA、IEA、WHO）。
  科研机构的 RSS 反而最合适 —— 天然少政治、天然有出处、天然「改变了一个事实」。

⏸ 本轮不做：原型的目的是先确认交互与信息结构。数据管线在形态定稿之后再接。

## 3 · 我的家 · 会长大的树

> **视觉定稿（2026-08-31）：抽象，不卡通。** 第一版画了一棵字面意义的树（棕色树干、
> 绿色糖果药丸），像儿童插画。现在：树是**半透明的结构图**（向梢部渐隐的渐变细线、
> 镜像根系、极淡的年轮），退到背景里；关键词是**技术标注** —— 精确落在枝上的菱形
> 标记 + 引线 + 直角标签，标签上是等宽读数（`SRC 3 · STR 4/5`）。结构后退，她的词在前。
> 年轮与「世界」的轨道环刻意呼应：向外是轨道，向内是年轮。

- **主干 = 我**；**主枝 = 领域**（人文与写作 / 科学与自然 / 社会与世界 / 技术与创造 / 艺术与表达 / 自我与成长）。
- **关键词长在枝上**：由她的阅读 / 写作 / 项目 / 活动生成。强度是**读数**（`STR 4/5`）不是等级，来源数同理（`SRC 3`）。
- **高光时刻**：标签上一枚 ✳ 与彩色读数，「那一刻你…」——她做得特别好的一次，钉在它发生的地方。
- **点开一个关键词** → 抽屉：它是什么 · 它从哪来（可点的来源清单：3 篇阅读 / 1 篇写作 / 1 个项目）· 印记看见的证据（她自己的原话）· 四个下一步（继续读 / 写一篇 / 做个项目 / 问印记）。
- **成长回放**：4 个时间点（三月 / 五月 / 七月 / 现在），枝随之伸长、词随之出现。
- **底部行动坞**：读 · 写 · 做 · 聊 —— 四个入口，一直在手边。

## 4 · 印记 · 她自己的 AI

右侧抽屉，任何页面都能叫出来。带上下文（在哪一屏、正看着什么）。
说话方式遵守 [印记 must talk like a teacher]：有利害、有真方法名、给选择、可以给例子。**一次只问一个。**

## 5 · PBL

### 5.0 第一个项目 · 建一个属于你的主页（解锁其余）
不是人为的锁。理由是真的：**之后每一个项目都会发布在这里，所以先把家建好。**

六步，可回退：
1. **看看别人的家** —— 6 个真实优秀个人主页，每个标注「它好在哪」和「你能偷走的那一招」。
2. **学会下清楚的指令** —— 本模块的教学核心。AI 在明确指令下才好用，「明确」= 三样东西：
   - **直接的例子**：你要它像哪一个；
   - **内容的结构**：哪几块、什么顺序；
   - **你想怎么和 AI 合作**：`AI 提问我来答` / `AI 提方案我来定` / `我来写 AI 只整理`。
   三样选完，屏幕**把它编译成一段真的指令**给她看：「这就是你给 AI 的指令」。
3. **选风格** —— 4 张带实时预览的风格卡。
4. **写内容** —— 分块写。**三种合作模式在这里真的不一样**（提问式 / 提案式 / 整理式）。可以从**我读过的**和**我写的**里挑，放上主页。
5. **发布** —— 预览真实页面，拿到链接。
6. **分享** —— 分享卡 + 二维码。主页从此在首页可达。

### 5.1 其他项目
- **五条赛道**：一个设计 · 一个网站 · 一个游戏 · 一份调查报告 · 其他。
- **两个入口**：直接选赛道 ｜ 先和印记聊（它从我的树 + 我收藏的新闻里提议）。
- **为什么（动机）—— 花最多时间的一步**：三层追问（为谁做？不做会怎样？你自己为什么在乎？），印记会对敷衍的回答追一次。产出一张**动机卡**，钉在项目头部，后面反复回来提醒「你当初说…」。
- **AI 排步骤**：学 / 查 / 设计 / 做 / 记录 / 试 / 发布。步骤可改可加可换序（排计划是系统的确定性动作，不需要「防操纵」确认门槛）。
- **一步一个工作台**：印记在侧，中间是这一步专属的工具（迷你课 / 问卷搭建器 + 假回收 / 灵感板 / 文档）。
- **发布** → 项目卡出现在她的个人主页上。闭环。

## 6 · 阅读 / 写作（轻量接入）
原型里是静态书架 + 静态篇目，作用是两条：**喂养树上的关键词**，以及**可被挑到主页上**。

## 7 · 科技感怎么落地（不是霓虹青色）
等宽小字号系统标签（`SIGNAL · 08-30`、`FIELD 04`）· 发丝线 · 点阵 · 轨道环 · 坐标刻度 · 数值读数（权重 0.82 / 来源 3）· 慢漂移与视差 · 逐项错峰入场。暖色底 + 马卡龙辉光，不用赛博霓虹。

### 评审揪出来、已经修掉的（值得记住的两条）

1. **发布项目对学生说了假话。** toast 写「它现在在你的主页上」，而它不在——
   `publishProject` 只翻了状态，主页却只渲染她挑过的东西。**这类缺陷比任何布局
   问题都严重**：这个产品卖的就是诚实。
2. **整理式对着空白框说「读完了」。** 一个字没写，AI 却开始点评。这正是
   [AI errors must surface, never fake] 针对的失败模式，而且它出现在**最强调
   「AI 不代写」的那一屏**上。

### 一条新的不变式（写进了 `data/coach.ts`）
**印记 offer 出去的每一枚 chip，都必须有一条 rule 能接住。** 曾经 19 枚里有 12 枚
点下去只会得到「这句我没有把握答好」——诚实的兜底是对的，但给一颗只会通向兜底的
按钮不是。加 chip 和加 rule 必须在同一个 commit 里。

### 一条布局教训
标注是**固定像素**、舞台是**自适应**的，短窗口下必然叠字——树在 900×700 曾经一半
读不了。`fit.ts` 的 `useFitScale` 把固定尺寸按舞台高度缩放，世界与树共用。

# 修订 v2 · 2026-08-31

用户看过 v1 后的三条反馈，以及由此产生的一次结构性重写。前面 v1 的章节保留为
历史记录；**凡与本节冲突处，以本节为准。**

## A · 世界 → 今日探索地图

| 改动 | 为什么 |
|---|---|
| 底色再暗两档（`#0A0806` + 暗角） | 行星是这一屏唯一的光源。原来的底色亮到和它们抢。 |
| **页面可滚动**，星图只占第一屏 | 原来是锁死的舞台，装不下的东西就直接没了。往下是同样五条的**清单**：图用来「看」，清单用来「读」。 |
| 行星运动幅度约放大三倍 + 表面自转 | 原来的漂移「技术上存在，感知上没有」。 |
| 一个节点 = **一条新闻**（不是一个类别） | 用户确认的结构。 |
| 每条新增 **导读** 与**三个钩子问题** | 导读是唯一为她写的一句：读的时候盯住什么。问题可点，直接带进和 AI 的对话。 |
| 打开一条 = **先读** 的旅程 | 「阅读」是通栏主按钮；问题排在它前面，所以读之前她已经带着问题。 |
| 删掉「编辑权重 0.85」 | 一个没有量纲、没有标尺的小数，学生拿它做不了任何判断。 |

**文案对照：** 今日星图→**今日探索地图** · 你可以拿它做什么→**开始探索**（放大）·
读这篇→**阅读** · 问印记→**与 AI 讨论** · 收进我的树→**先收藏** · 你点亮了 3/5→
**已浏览 3/5** · 换一天换一批→**时间轴** · 世界 向外→**世界 探索** · 我的 向内→
**我的 地图** · 删掉「做成项目」。

**先收藏 → 阅读室的「待读」。** 收藏箱在阅读室的最上方（放在读过的下面等于没有）。
收藏同时仍会在树上长出关键词——收藏本来就是兴趣模型的来源之一。

## B · 我的树 → 我的兴趣树

- 换到**自己的暗色地面**（`.eco-grove` + 上升的光尘）。
- 树**发光**：主枝分三层描边伪造粗细渐变、SVG bloom、每根主枝五条小枝带光点、
  **实心渐细的树干**（原来是 9px 描边，那是桅杆不是树干）。
- 关键词 = **半透明光珠**，直径随强度、颜色随领域、各自周期呼吸。
- **为什么不用生成的图片**：每颗光珠由 `pointOnBranch()` 锚在 SVG 的贝塞尔曲线上。
  一张画出来的树，它的枝干数学不认识，光珠就会飘在旁边——那张图就从「这是你的
  模型」退化成装饰。**这张图必须就是那个数据结构。**
- 顶部两个数字，各带一个可悬停的 `?`：**关键词**（由阅读/收藏/写作/项目自动生成）、
  **成果数**（已完成的阅读+写作+已发布项目；没做完的不算）。删掉「高光时刻」计数。
- 成长回放→**时间轴**。
- 抽屉重写：**摘要**（原「印记 看见的」）· **相关活动**（原「它是从哪来的」，删掉
  「这个词不是猜的…」那句解释——列表本身比解释更有说服力）· **继续深挖**。
- **继续深挖 = 四个具体的气泡**，每个关键词各不相同（`data/dig.ts`）：一个她还
  答不上来的问题、一篇具体该读的、一篇可以写的、一个真能做出来的项目。
  原来那四个空动词（读/写/做/问）在每个词下面都一样，等于什么也没说。

## C · PBL 重写 —— 从「计划 + 打勾」到「工作台」

v1 的项目页**不是 agentic 的**：AI 的全部贡献在开头一次性给完，之后学生独自打勾。

**v2 = 一段持续的对话，AI 在其中召唤工具卡。**

```
项目工作台 /eco/projects/:id
├── 左：对话流 —— 印记的话 · 她的话 · 工具卡（内联，带召唤理由）
├── 右：材料栏 —— 赛道的全部卡片 + 每张已完成卡的一行真实痕迹
│         方法栏 —— 分工约定 + 四条有出处的方法
└── 底：输入框 —— 卡住了、想反驳、想跳过，随时说
```

**工具卡 = tool-use 循环里由人执行的工具。** 14 张，schema 驱动
（`data/cards.ts`），五个字段原语（`text`/`textarea`/`choice`/`multi`/`rows`）。
**新增一张卡 = 新增一份 spec，不改渲染器代码**——`CardSurface.tsx` 里如果出现
`if (spec.id === ...)`，说明这条契约已经破了。

卡片按「有判断力的人真实的动作顺序」排：
**参考搜集**（先看很多个，把喜欢说成具体的一句）→ **拆一个作品** → **命名风格**
（把喜欢变成 AI 必须遵守的规格，含禁令）→ **内容清单**（先看你有什么再定结构）→
**明确指令**（例子 + 结构 + 配合方式，编译成可复制的 prompt）→ **三个版本**
（AI 给选项不给答案）→ **最小可用版本**（先定失败标准）→ **批评会** → **取舍** →
**发布前检查**。调查赛道另有**问题清单 / 找证据 / 问卷体检 / 样本与偏差**。

**回灌必须引用她。** 提交后印记的回话逐条读取她填的值——二十分钟之后收到一句
「很好，继续」，等于告诉她没人看。

**铁律在项目里的读法（用户明确要求的修订）：**
> 印记**可以动手**——写代码、出草图、排版、生成图片。
> 但**判断是她的**：做什么、为谁做、放弃什么，以及为什么选它。
> 说给别人听的话，仍然是她写的。
>
> 「印记可以动手，但不能替你判断。这两件事分开，你才是在做项目，而不是在验收项目。」

这段（`PBL_COVENANT`）印在项目首屏和每个项目的方法栏里，不是藏在系统 prompt 里。

**取消了主页门槛。** v1 把其他赛道锁到主页发布之后。理由虽然真实，效果是一把锁。
现在个人主页只是「一个网站」赛道里最小的一个（并被排在建议第一位），
`/eco/homepage` 退化成纯机械的「挑内容 / 选样子 / 发布」，六步向导删除——
它承载的教学（看例子、命名风格、写明确指令）已经进了卡库，每条赛道都能用。

## D · 方法的出处（`data/method.ts`）

只列**核实过**的四条：PBLWorks Gold Standard 的七个要素 · Ron Berger / EL

第二轮反馈。世界页去掉了清单；PBL 从「一条对话 + 工具卡」变成

  里面，清单就成了上面那一屏的第二份拷贝。**一屏东西说两遍，教的是两遍都不算数。**
- 行星变成**玻璃泡泡**：半透明、边缘吃场域色、左上一处高光（五个共用一个光源）。
  尺寸大约翻倍（236 / 200 / 178 / 158 / 150），因为泡泡现在是**要读字的地方**，
  88px 的圆装不下一句 20 字的中文标题。
- 仍然扣住不放的是**钩子问题**——hover 才浮出来。标题只是让她不用瞎猜；问题才是
  值得留到最后的东西。
- 已读态从「揭示标题」改成「点亮 + 已浏览」。发现感留住了，代价没有了。

## B · PBL：先有计划，再有工作台

### B1 · 空屏就是设计

第一次进「项目」的学生：没有项目、不知道这里的项目是什么、也没有理由相信自己能
做完一个。**最糟的东西是一张五选一的菜单。** 所以空屏只有一句话和一个大按钮——
一个具体的第一个项目（你自己的主页），描述具体到她能想象出最后会存在的那个东西。

主页当第一个项目的理由不是煽情：**它是唯一一个后面每个项目都会汇进去的产出。**

按钮下面、更轻的位置，是第二道门：**我已经有一个想解决的真问题**。它排第二，因为
已经有真问题的学生自己会找到它，而没有的学生不该被要求现编一个。

🚨 `state.projects` 现在**默认为空**——空屏可达，才可能被测到。两个示例项目在那一
屏上一键载入，明确标成原型家具。

### B2 · 计划先行（`data/plan.ts`）

**在任何东西开工之前，印记提一份计划，她改、她排时间、她同意。** 这是 Codex /
Cowork 会做而 v2 没做的事：计划是让她在三周被花掉之前有机会反对的那件东西。

每一步必须写清三件事：**你带来** / **印记做** / **你判断**。
> 一步如果说不出她拥有哪个判断，诚实的做法是让印记默默做掉，而不是把她按在那儿
> 看着，然后管这叫学习。

🚨 **`when` 印记一律不预填。** 快捷词条是键盘，不是建议。你没写过的时间表你不会
当真——更要紧的是，写时间那一刻正是学生发现「我的计划有七步，而我只有两个空下午」
的时刻。为省她三十秒打字把这个发现拿掉，是这个文件里最亏的一笔交易。

个人主页的七步就是用户口述的那条路：动机 → **先写三个词** → 看十个真人的主页 →
印记出三个方案（选一个 + 说清为什么）→ 定内容 → 印记开工、她验收 → 发布。

### B3 · 选路与支线（真问题那道门）

学生带着真问题进来，印记欠她的第一件东西**不是**方案，是「这事不止一种解法」。

1. **澄清**（`frame` 卡）：谁碰到、什么时候什么地方、现在怎么应付、你亲眼见过几次。
2. **选路**：印记给 2 条，**每条自己写清代价**，然后停住。
   > 看不到代价的选项，等于已经替她选了。
   两条必须是**不同种类的答案**——一条活在屏幕上、错了一分钟能改；一条拧在柱子
   上、对就是对不对就是不对。两种配色之间的选择什么也教不了。
3. **支线**：每条路都是钩子。点开 = 一场**只谈这一条**的旁支对话，问完写下
   **「我带回去的判断」**。没有这一栏，点开一个选项只是阅读；有了它，点开一个选项
   是一趟她跑回来的差事。
   🚨 支线里的脚本答案**诚实地承认边界**：好几条直接说「去问一个真在那儿待过的人，
   他随口一句比我这段有用」。关于某个具体花园和某个具体物业的问题，这就是实话。
4. **决定**：选一条 **+ 为什么 + 你知道自己放弃了什么**。三样齐了按钮才亮，理由
   之后一直钉在面板上。

选完印记才按那条路排计划（走一遍画图 → 定几个点 → 印记做网页 → 印码去现场试 →
去找物业谈 → 交付）。

### B4 · 工作台的形状 = Cowork

两栏，**哪一栏宽就是全部的交互模型**：

- **在说话** → 对话是主屏，右侧是窄的「全景」：走到计划第几步、已经有什么材料、
  谁做什么。
- **在动手或在看东西** → 那件东西接管右侧并**变宽**，对话缩成旁边一条，继续跑。

舞台上能出现四样：工具卡 · 印记做出来的东西 · 某条路的支线对话 · 计划本身。

### B5 · 印记做的东西（`data/artifacts.ts`）

工具卡是**她**干的活；artifact 是**印记**干完交出来给她判断的活——三个方案、
从她自己的库里拟的内容草稿、做出来的页面。**这就是产品负责人要的铁律②修订：
项目里印记可以真的动手。**

每个 artifact 都向她收三样：读它 · 对它做决定 · **说为什么**。
🚨 **没有理由，什么都不落地。**「就用这个」按钮一旦能自己生效，这东西就变成
「一台生成的机器 + 一个点同意的学生」，而那正是这个产品存在的目的的反面。

两个必须保持的习惯：
- **交付时说清自己猜了什么**（每个 `note` 都写）。藏起假设的交付只能被接受，
  没法被审查。
- **主动承认自己做的东西哪儿不对**（`admits`）。只报成功的 AI 教会学生别再看了。

## C · 新加的四张卡（且没动一行渲染器代码）

`frame` 把问题问准 · `keywords` 先写三个词 · `recon` 实地踏勘 · `talk` 去谈一次。
这是 schema 驱动契约的一次真实压力测试，通过了。

`CardField` 长出 `optional`，取代原来硬编码的 `f.id === "result"`：有些栏她只能
**去过现场之后**才填得了（测试结果、物业到底说了什么、三个词看完十个还剩几个）。
拿这些栏卡住提交，等于整张卡要等整趟差事跑完才能回灌，那就没有回灌了。

## D · 这一轮修掉的四个真 bug

1. **支线问了等于没问。** `Roads` 从来没调用过 `openBranch`，`askInBranch` 又只
   `map` 已存在的支线——于是整个支线界面开得好好的，问题一个都不落地。改成**写入
   即创建**（`upsertBranch`），修的是这一类，不是这一个。
2. **印记说它按 A 方案做的，而她选的是 B。** 构建轮次的文案把版本号写死了。
   在一个以诚实为卖点的产品里，**假状态声明的优先级高于任何布局问题**。
3. **还没选路，就问「你放弃了『第一条路』的什么」。** `pick` 为 null 时
   `find(a => a.id !== pick)` 命中第一条。
4. **`因为：因为它错了可以改`。** 面板给理由加了「因为：」的句头，而她的理由本来
   就以「因为」开头。改成标签。

- 新闻管线（见 §2.1）。
- 真问题那道门只为**一个**示例问题写好了印记的路，界面上明说了，并挂着「原型数据」。
  真产品里这一步是模型读她写的东西现场提路。

# 修订 v4 · 2026-08-31（晚）

第三轮反馈，三件事：**印记要先开口再弹面板** · **每个面板都要说清「我在哪一步、
填完会发生什么」** · **加一个真的会发出去的问卷**。

## A · 面板之前先有一句话（`PlanStep.says`）

一个不打招呼就出现的面板，读起来是软件在要东西；同一个面板，前面加一句
**「接下来我需要你…，因为…」**，读起来是同事在提要求。同样的像素，相反的体验，
一行文案。

所以每一步现在都带 `says`：印记先说它需要什么、为什么需要，然后卡片/面板才出现。
分隔线不够用——它给这一步贴了个标签，但它没有在跟她说话。

没有手写旅程的赛道，`planForTrack` 会按卡的 `reason` 生成一句。

## B · 每个工作面顶上的三件事（`StepBanner`）

一堆输入框，单看和作业没有区别。学生盯着四个 textarea，无从判断自己在做一件要紧
的事还是在填表——而「我为什么在打这些字」的答案**每张卡都不一样**，所以它没法用
界面上某处的一句通用安慰来解决。

于是每个工作面（卡 / artifact / 问卷）都以同样三件事开头：

1. **你在这里** — 你自己批准的那份计划里的第 N / M 步，写出步骤名。不是进度条：
   是名字，这样这个面板才明显属于一条她同意过的路，而不是凭空出现的东西。
   顺带把她自己排的时间也印出来。
2. **这一步你判断** — `PlanStep.decide`。
3. **填完它会发生什么** — 🚨 `CardSpec.payoff` / `ArtifactSpec.payoff`。**这一条
   是重点。** 它必须写出这个项目里一个**真实的下游后果**（「第三栏会变成我检查
   自己工作的依据」），永远不许写「这会帮助你思考」。
   > 知道自己的答案是干什么用的学生，写出来的答案不一样。

18 张卡、6 个 artifact 全部补了 `payoff`。

## C · 问卷：印记拟稿 → 她修 → 真的发出去（`FormSurface`）

项目里别的东西都能返工。**问卷不能**：发出去之后，一道坏题收回来的就是坏数据，
之后再用心也补不回来。所以这是唯一一个「发之前必须修好」不是关于勤奋、而是唯一
选项的地方。面板上方的 `payoff` 就是这么写的。

### 做教学的那一步

🚨 **印记给自己的草稿打标记。** 它写五道题，然后说：*这道在问两件事；这道已经把
我想要的答案塞给对方了。* 一份自带标记的草稿把评审从客套变成活儿——她没法回一句
「挺好的」——而且它是在她**马上要发给认识的人**的题目上，教那两个有名字的坏问法
（双重问题 / 引导性问法，出处见 `METHODS`，来自 Pew）。

**我标的题不处理掉（改写或删掉）就不能发。** 这是这个文件里唯一的硬门禁。

### 邀请语必须她写

印记拟一版，并且直说这版别原样发——它被灰着显示，当反例用。一条用她的名字、发给
她的邻居、却是 AI 口气的消息，是这个项目里唯一一处「印记替她写」会构成谎言的
地方。

### 回来之后

印记只报**数**和**意外**：几个人填了、哪道题上三个人写到了同一个地方、哪一条是
她没料到的。然后它明说 **「4 份不足以说『大家都』」**。最后一栏是她的：
> 我只会数。这些答案说明了什么，是你的活。

这一步插在花园项目的「走一遍画下来」和「定几个点」之间——她一个人的观察是一个
样本，问卷发出去她才有资格说「不止我一个」。

## D · 回得去的空屏

PBL 的空屏是一个专门设计过的界面，而在此之前，看到它的唯一办法是一个从没打开过
原型的浏览器标签页。点进一个项目，它就永远消失了——**这让整个产品里最有野心的
那部分的第一屏事实上无法评审。** 项目页头部现在有一行
「原型：清空，回到第一次进来的样子」。

## E · `CardField.optional`

有些栏她只能**去过现场之后**才填得了：测试结果、物业到底说了什么、三个词看完十个
还剩几个。拿这些栏卡住提交，等于整张卡要等整趟差事跑完才能回灌，那就没有回灌了。
取代了原来硬编码的 `f.id === "result"`。

# 修订 v5 · 2026-08-31（深夜）

三件事：**去行话** · **计划瘦身、步骤加厚** · **工具分类**。

## A · 去行话

产品负责人的原话：「we have put a lot of strange jargons everywhere which would
never appear in any product」。他点名的：定几个点，定在哪儿 / 你排的时间：本周 /
印记做的 / 挑一版 + 写清楚理由，才能往下走 / OPTIONS / 这一步你判断：在「够用」和
「做得完」之间，你站哪儿 / 你选的路 / 路线。

他给了三个示范，规律很清楚：**步骤名 = 名词性的方法名**（学术、克制、可迁移），
**说明句 = 平实直接的指令**。

| 旧 | 新 |
|---|---|
| 路线 | 项目计划 |
| 你选的路 | 已选方案 |
| 印记做的 · 你来判断 | 印记的产出 · 需要你确认 |
| 这一步你判断 | 决策要点 |
| 填完它会发生什么 | 这一步的作用 |
| OPTIONS / DRAFT / BUILD / FORM | 方案对比 / 内容初稿 / 页面构建 / 问卷调研 |
| 材料 / 分工（页签） | 成果 / 方法 |
| 挑一版 + 写清楚理由，才能往下走 | 请选择一个方案并说明理由后继续 |

工具卡全部改名：立项分析 · 问题界定 · 关键词定义 · 案例调研 · 结构拆解 ·
风格定义 · 内容盘点 · 提示词设计 · 方案对比 · 原型测试 · 问题拆解 · 来源核查 ·
问卷诊断 · 样本与范围 · 同伴评审 · 权衡分析 · 发布前自查 · 实地调研 · 沟通提纲。

> 这一轮按负责人的建议请了外部模型（Gemini）做了一次措辞复核。采纳的：
> **受众分析**（不用「观众」，网页/传播语境的专业词是「受众」）·
> **同伴评审**（12–15 岁的学生不是「同行」）· **权衡分析** · **样本与范围** ·
> **提示词设计**（AI 协作语境里的行业标准词）· **原型测试**（去掉「最小」，
> 少一层认知负担）。
> 拒绝的：把负责人自己提的「质疑工具 / 审查工具」改名（那是他的词），以及把
> 「沟通与协调」改成「利益相关者沟通」（对初中生过于公司化）。

## B · 计划瘦身，步骤加厚

**计划页每一步只有：序号、名字、一句话。** 之前每个节点都印着
你带来 / 印记做 / 决策要点，还带一个排时间的输入框。

两个问题。七块规格说明不是「审阅」，是「扫一眼」，而扫一眼扫过去的计划比不给
更糟。**排时间这件事更是仪式**：让一个十三岁的人在还不知道每一步要干什么的时候
给七个步骤填日期，得到的是七个瞎猜。负责人的原话是「that is ridiculous」——
**整个功能已删除**。

细节搬到了**步骤本身**（`StepIntro`），一次只出现一步：

- **目标** — 这一步是干什么的。
- **分工方案** — 印记做 / 你来做 / **然后**。
- **决策要点** — 这一步属于她的判断。

🚨 「然后」这一行不是装饰。「你来做 X」是派活；「你来做 X，然后把 Y 交回来，
我按它继续」才是分工——**交汇点才是她那一半对机器那一半有意义的原因**。不交汇的
分工只是两个人各干各的。

## C · 工具分类（`ToolKind`）

负责人的提议：计划工具 / 决策工具 / 框架设计工具 / 质疑工具 / 审查工具 /
反思工具。采纳，并加了一类：**调研工具**——「去现场问真人」和「质疑手上已有的
东西」是两种不同的动作，而产品现在有三件调研器械（实地调研、案例调研、问卷调研）
没有地方放。

十九张卡按七类归入，工具箱在「方法」页签里，标出哪些在本项目计划内。

🚨 **分类只有在使用的那一刻可见才有意义。** 活在设置页里的分类没人看，所以标签
印在卡片本身上（「计划工具 · 约 12 分钟」）和工具箱里，别的地方一概不印。
分组由 `CardSpec.kind` 派生，新卡自动落到它那一格——两处维护的分类迟早会自相矛盾。

# 修订 v6 · 2026-08-31（深夜二）

## A · 世界：一屏

底下那一整条控制台删了：八个领域筛选、已过滤/为什么是这五条/原型数据三个 chip。
**五个东西不需要筛选器**——把五条筛成两条，这个控件花掉的注意力比它省下的多，
它存在只是因为控制台有空位。

日期变成**标题下方的一条轴**（左上），它回答的是「我在看哪一天」，那就该挨着
日期，而不是待在页面另一头的控制台里。

🚨 **透明度没有跟着杂物一起删。** 两段说明加上原型数据披露，收进了计数器旁边的
一个 ⓘ。规则是「省略要说出来、学生找得到」，不是「省略要占掉四分之一屏」。

## B · 兴趣树：底部工具坞删掉，时间轴上移

读 / 写 / 做 / 聊 那条悬浮坞删了——左边主导航已经有这四个入口。

时间轴移到姓名下方，和世界的日期轴同位置、同行为。刻度改成**相对起点**的相对词，
并且只显示真的有东西的刻度。完整的设计讨论（两年以上怎么办、「起点」指哪天、
假期留不留空白）写在 `docs/2026-08-31-pbl-tool-model.md` 第 5 节。

**顺带修掉一个真 bug：** 十六个关键词全部出生在最后两个刻度上，前两个刻度回放
出来是一棵空树——**一段没有生长的成长回放**。新轴会丢掉空刻度，正好把它照了出来。
数据已铺开成 3 / 4 / 5 / 4。

## C · PBL：对话是默认，面板要自己挣来

之前每一步都是同一个样子：右侧滑出面板，三到五个输入框。两个毛病——

1. **它违反了我们自己的铁律③。** 侧栏里五个 textarea 就是把五个问题同时问出来，
   正是这条铁律要防的事。我们在对话里守着它，在工具里破了它。
2. **它无聊。** 连续填七步表单，学生会把项目理解成作业。

现在 `CardSpec.surface` 分两种：

- **`chat`（默认）** — 印记问一句，等她答，再问下一句。答完最后一句，卡自动
  提交、回灌、计划推进。和面板填完的卡在「成果」里长得一模一样（同一个
  `finishCard`），否则过程即数据对一半工具就悄悄失效了。
- **`panel`** — 输入是对话行装不下的：表格、并排比较的选项、要拼装的图。

判断题只有一道：**做完之后，它会变成她之后反复回去看的一个对象吗？**

新增 **受众画像**（人物卡）作为面板一侧的样板：脸、名字、身份年龄、什么时候打开、
想找到什么、你希望他什么感受。六栏本来都能在对话里问完，但那样得到的是六段散在
聊天记录里的答案，而不是一个她能指着问「陈老师真的会读这一段吗」的人。
个人主页的第一步现在开的是它。

十九件工具里五件走面板（受众画像、案例调研、内容盘点、方案对比、问卷调研…），
其余走对话。

**工具库是开放的**：渲染是 schema 驱动的，所以印记可以在项目进行中现场输出一份
规格、造一件新工具。设计依据见 `docs/2026-08-31-pbl-tool-model.md`。

## D · 修掉的小 bug

- `_例如：_` 的下划线被原样打给了学生——`Bold` 只认 `**`，别的 markdown 记号
  会把自己印出来。

# 修订 v7 · 2026-08-31（收尾）

## A · 阅读室和写作间从原型里删掉

两个房间在 lite 里**已经做好了真实版本**。留一份更糙的原型副本比没有更糟：它会
把评审意见引到一个谁也不打算实现的设计上，还会让人以为真实的那两个页面长这样。

删掉的是两个**浏览界面**；阅读/写作的**数据留着**——兴趣树是用它长出来的，
个人主页也从它渲染。

连带修掉两处「说了一个她去不了的地方」：
- 新闻卡的主按钮原来是「阅读」，跳原型自己的阅读室。现在主按钮是「与 AI 讨论」，
  这个原型兑现得了。
- 收藏的 toast 原来说「已收藏到阅读室的「待读」」。**这是假状态声明**，
  在一个以诚实为卖点的产品里是最不能出的一类错。现在只说真的发生了什么：
  「已收藏 ·「X」长到了你的兴趣树上」。

## B · 项目页：切换器 + 输入框

**开始新项目 / 我的项目** 两个模式，一个切换器。放在一屏里两边都变差：输入框被
挤到列表下面，而列表被读成「这一页是干这个的」——可这一页多数时候是用来**开始**
一件事的。

**开始新项目**：一个大输入框，她用自己的话说要做什么。下面是**类别气泡**——
点一个会往框里放一句开头，她再改写。
> 五选一的选择器要求她在**说出想法之前先给想法分类**；一个框只要求她说出来。

类别可以不选。ⓘ⌘+↵ 直接开始。

**我的项目**：书架，带封面。

## C · 封面

`Project.cover = { art, glyph }`：八个渐变底 × 十六个图形，在项目页头部「换封面」
里改，两下点完。

**故意不做图片上传。** 一个学生如果必须先去找一张图，她的项目才看起来像个项目，
那我们是给了她一件杂活；而且只要有一张卡是歪着拍的模糊照片，整个书架就不齐了。
一个底色加一个图形，四秒钟，拿到的是真正要紧的那个结果——**书架看起来是她的**。

它也是整个项目流程里唯一一个纯审美的选择，这一点值得刻意保留：别的每一步都在
要求她给理由，这一步允许她只是喜欢一个颜色。

## D · 顺带清掉 不是…而是

按 `copy-no-antithesis` 规则，扫掉了印记自己的话和界面文案里的
`而不是` / `不是…而是`（method / cards / examples / coach 共 9 处），改写成肯定句。
**没动**的是模拟新闻摘要和模拟文章正文——在原型的虚构里那是第三方引文，规则本身
豁免逐字引语。

顺带修掉一个错字：`他想让计算living在纸和墙上`。

# 修订 v8 · 那个网站真的做出来了（2026-08-31）

## A · 为什么要有它

个人主页项目走七步、做出一个「网站」，而在这一版之前，那个网站是假浏览器框里的
**四行字**。一个项目的成果如果从来没被真正看见，它教给学生的就是成果不重要——而这
一件成果，是她要发给一个真人的东西。

现在有 `site/BuiltSite.tsx`：一个按照常见个人网站样子做出来的页面——顶栏、状态行、
一句提问当标题、作品、写的、关于我、现在、在读、找我。内容在 `data/site.ts`。

## B · 一个渲染器，三个地方

页面构建那一步的预览、公开网址 `/eco/p/:handle`、我的主页 tab，渲染的是**同一个
组件**。

> 预览如果是另一个组件，迟早会发生「她验收的是一个东西，发出去的是另一个东西」。

## C · 内容从哪来（越靠前越是她的）

1. 她在**内容草稿**里改过的句子（印记承诺过「一个字不动」，这里是兑现的地方）；
2. 她在旧的我的主页工作台里填过的段落；
3. `data/site.ts` 里的模拟内容。

作品、写的、在读来自真实状态。**网站不列自己**：个人主页项目的成果就是这一页，
把它放进作品里，等于给访客一张指向他正在看的这一页的卡片。

## D · stage：把印记认的错变成看得见的像素

印记每一版都主动说自己哪里还不行。那些话必须**在页面上看得见**，否则只是装饰：

| 版本 | 印记说 | 页面上真的是 |
|---|---|---|
| 第 1 版 | 手机上第一屏那句话会断成三行 | 手机预览里标题 40px，确实断成三行（量过） |
| 第 1–2 版 | 药盒那一条我没有图 | 作品卡是虚线「图位 · 等你拍的照片」 |
| 第 3 版 | 换上了照片，联系方式加在最后 | 封面出现，页脚出现邮箱 |

所以预览里有**电脑 / 手机**切换：不能亲眼看手机，她写回去的反馈就只能靠猜。

窄屏是一个 **prop 而不是媒体查询**——预览框在 1400px 的窗口里只有 390px 宽，`md:`
读的是真实窗口，会把手机预览排成电脑版，正好在她要检查的那一刻骗她。

## E · 两个地址，两种观众

- `/eco/homepage`（我的主页 tab）：带导航，多一条公开链接和设备切换。
- `/eco/p/:handle`：**没有导航**。打开它的是没有账号的朋友或家长。

「以访客身份打开」开的是**新标签页**——原地跳过去会把她扔在一个没有返回路径的页面上。
项目发布后的「去我的主页看看」同理，改成进 tab 那一份。

## F · 修掉的两个真问题

- **手机预览被裁掉**：手机框是拉伸的 flex 子项，它的 `overflow-hidden`（本来只为圆角）
  把整页切在 480px，第一屏以下永远够不着。加 `items-start`。
- **一份内容两个真相**：`BuildRound.headline/lines` 是给没有渲染器的成果（花园地图、
  指示牌）用的草稿描述。个人主页那三轮已经删掉这两个字段，类型上改为可选——同一块屏幕
  留两份描述，迟早有一份会悄悄过期。

顺带：草稿里把学生叫成「知瑶」，`STUDENT.name` 是「林知遥」。统一成知遥。

## G · 留下的一个决定给你

`projects/PageStudio.tsx`（旧的六步建主页向导）**现在没有任何入口了**——我的主页 tab
改成直接进这个网站。它和个人主页项目是同一件事的两个做法，我倾向于删掉它（理由和你
让我删阅读/写作页那次一样：一个更差的重复实现会误导看原型的人），但没有替你删。

# 修订 v9 · 那个网站重做了一遍（2026-08-31）

v8 的页面被否掉了，两句评价都对：**「你见过真的个人网站吗」**、**「一个个人网站
为什么要被困在我们的设计语言里」**。

## A · 上一版为什么不像个人网站

1. **它穿的是我们自己的皮**。方案 A 的配色是 `#FBF8F4` 纸 + `#EA5140` 珊瑚——
   就是 app 的纸和 app 的主色。加上圆角卡片、渐变+图形的封面块、和 app 一样的
   字号节奏，第一眼看到的当然是一个产品界面。
2. **三个方案只换了颜色**。`hp-style` 三张卡自己写得清清楚楚：A 长页无导航、
   B 密表像档案柜、C 图先行。我只做了一个布局。她写了理由才做出的那个选择，
   在页面上看不见任何差别。
3. **文案是我们的口气**。每一块都顶着「我做过的 / 我写的」这种批改栏目名，作品卡
   有「为什么做它：」字段标签，页脚还有一句我们的教育理念。真人写自己的主页不会
   给自己的段落贴标签。

## B · 看了六个真站点

产品负责人给的参考：lilianweng.github.io（极简）、5ime.cn、d-d.design、
keyork.github.io、terrifyzhao.github.io（经典）、lixiaolai.com（好看）。

六个站点都有、而我们一个都没有的东西：

- **身份区**：头像或字标、名字、**一句话说明这是谁**、一个联系方式；
- **人话栏目名**：文章 / 项目 / 标签 / 归档 / 关于，且**只出现一次**；
- **像文章列表的文章列表**：标题、一句摘要、一行 meta（日期 · 分类 · 字数）、
  末尾「阅读全文 →」；
- **站点信息**：建站时间、篇数、最后更新；
- **页脚只有** © 名字 · 用 X 搭建。

## C · 现在是三个真的不同的页面

| 方案 | 布局 | 参考 |
|---|---|---|
| A 一句话开场 | `Essay` — 无导航、超大衬线一句话、右侧等宽资料表 | lixiaolai.com |
| B 索引式 | `Ledger` — 深色等宽，一张按日期排的密表，作品/文章/在读混在一起 | index 式站点 |
| C 一个作品打头 | `Magazine` — 头图 + 导航条 + 文章卡片 + 侧栏（头像、分类计数、标签云、站点信息） | keyork / terrifyzhao |

配色也各自搬离了 app：A 换成 `#F4F0E6` 纸 + 砖红 `#9C3B26`，B 更冷更深，
C 是杂志白 + 墨蓝 `#1B44D8`。

**`site/` 里不许 import app 的 UI kit**（`Btn` / `Panel` / 任何 `mk-*`）。
用到的那一刻，这一页就开始像做出它的那个产品。

## D · 头图是画的，不是作品缩略图

第一版把她最好的一件作品铺成头图。**头图和作品缩略图做的是两件事**：头图是在
读到任何一个字之前说明「这是谁的地方」。放作品上去，页面顶部就变成了列表的第一行。

`parts.tsx` 的 `Banner` 是这一页自己的画：黄昏天色里一盏还亮着的台灯，散落的螺丝
当星星，左边一枚垫圈和两道弧。用 SVG 画而不是找图，因为她没有照片，而随便找一张
是别人的。构图锚在底边（`xMidYMax slice`），地平线和站在上面的台灯在任何裁切里
都在。

## E · 保留下来的东西

stage 仍然把印记认的错变成像素（第 1 版手机上标题真的三行、作品图位真的空、
第 3 版才有邮箱）；窄屏仍然是 prop 不是媒体查询；仍然是一个组件三个地方用。
