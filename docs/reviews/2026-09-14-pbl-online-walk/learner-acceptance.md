# Lite PBL 完整场景试用记录

状态：试用方案，尚未执行学生试用。本文不能作为通过证据。

依据：`docs/2026-09-01-pbl-detail.md` 中的观察与问题、可修改结构、审核、分工、复盘及持续迭代；本轮产品讨论中的人物板、自由风格与意象、第一幕、自我介绍、作品展示，以及学校与社区场景。

## 执行方式

使用没有历史纠错记录的独立学生项目。开发者走查与学生试用分开记录，不能把开发者代选、代写和修复后的重试计入学生独立完成。先完成开发者全流程，再邀请学生使用。参与者用匿名编号；不为测试编造其兴趣、经历、调查结果或反馈。

每次记录版本、入口、设备、开始/结束时间、模型等待总时长、离开位置及人工帮助。遇到必须帮助的阻断可以介入，但记录介入发生在哪里、说了什么或操作了什么，不将帮助隐去。已暂停的外部调用不以其他入口重复触发。

## 场景 A：第一件作品就是个人主页

给学生的任务：制作一页你愿意展示给别人看的个人主页。可以展示正在做的尝试，无需获奖经历或成熟作品。请自己选择读者、内容和呈现方式。

| 任务 | 观察内容 | 应留下的证据 |
|---|---|---|
| 选择读者并完善人物板 | 能否从具体的人思考兴趣与关注内容；能否区分兴趣爱好和读者想看什么 | 学生选择、修改的关键词和原话；尚未访谈的判断不标为已证实 |
| 描述风格、选择意象 | 是否能表达预设选项以外的想法；AI候选是否可改、可拒绝 | 原风格描述、采用/未采用的意象及理由 |
| 可选灵感采集 | 学生是否能说出借鉴哪种效果；跳过后仍能继续 | 实际看过的参考、观察或明确跳过；不能把收藏等同于已研究 |
| 构思并生成第一幕 | 是否理解画面与互动的区别，是否看懂制作说明 | 学生核对过的说明、生成版本和等待时间 |
| 试用并修改 | 是否实际操作，能否将问题对应到版本 | 操作任务、观察、修改理由、原版与新版；未测试部分明确保留 |
| 介绍自己与展示作品 | 首次创作者能否使用自己的尝试和现有制作过程，无需重复抄写或虚构经历 | 真实正文及来源；展示内容与学生选择一致 |
| 展示完整主页 | 第一幕之后能否找到介绍和作品；返回入口是否可用 | 宽屏及窄屏实际版本，文字与点击区域检查 |
| 站内发布与更新 | 学生是否知道发布的是哪一版，旧链接是否保持正确内容 | 精确发布版本、访客读取、更新前后、撤回失效 |

开发者当前已知反例：温室版本 `2dd505f4` 在390像素宽度下首尾热区越界、相邻热区重叠。不能作为通过样例；修订需验证320/390像素布局与宽屏，保留原版作为对照。

## 场景 B：两节课，减少食堂一次性杯子

任务边界：两节课，每节45分钟，零预算，最终展示一张有真实记录的海报。不预设杯子使用情况；不能默认学生课外有时间或一定能进入食堂。

1. 学生比较至少两种可行方法，说明各自能回答什么、不能回答什么，再决定从哪一种开始。
2. 核对提纲或观察表。若访谈对象没有相关经历、记不清或无法安排访谈，流程仍允许诚实继续或重新决定，不补写结果。
3. 学生确认课内计划。实际执行前不能标成完成；计划应给整理和制作留下时间。
4. 先试问，再修改。记录原话、概括与未记清内容；测试人员不得为了走完流程制造受访者。
5. 制作海报：来源与样本范围可辨；少数同学经历不能写成全校结论。学生能更改结构和呈现方式。
6. 教师查看同一项目的进度，识别计划、执行和待帮助之处。仅学生账号走通不算教师路径通过。
7. 展示后由实际反馈启动下一轮修改；没有反馈时允许保存试用计划，不宣称效果得到验证。

困难分支分别记录：不能访谈、只有一位受访者、有人记不清、AI问题暗示答案、AI将待执行标为完成。开发者可使用明确标注的测试夹具验证分支，但夹具不计入真实调研结果。

## 场景 C：社区制作与带回成果

任务边界：四人，两次各90分钟，使用现场可用材料。先选择一个可观察的问题，如社区分类指引难查找；不了解本地规则时先核实，不凭常识补答案。

共同环节：观察问题 → 选择要帮助的人 → 比较方案 → 选择结构 → 明确分工 → 制作 → 实际试用 → 修改 → 展示与复盘。

| 成果路径 | 必须走到的终点 | 当前不能替代终点的证据 |
|---|---|---|
| 黑白折页或小册子 | 导出、真实打印、按正确面序折叠，目标读者独立查找信息并反馈 | 屏幕六面预览、无溢出测量、导出文件存在 |
| 功能网页 | 从站内规格交接到外部coding agent，制作后带回实际版本，在原项目记录试用并继续修改 | 仅下载一份提示词、填写一个未经访问的链接 |
| 实物 | 明确材料与制作条件，制作实际样品，记录功能、使用限制和实际测试 | 生图、概念图、采购建议或渲染图 |

三条路径分别验收，不从其中一条推断其他条已可用。本版按产品负责人2026-09-15的决定，不验收站内多人协作、共享项目或多账号共同编辑；学生自行安排线下协作。课堂与社区仍需观察学生个人项目的推进、真实调研及成果反馈，教师视图按个人项目验收。一人模拟学生只算开发者走查，不算真实学习效果验证。

## 教育意义与趣味：记录行为，不替学生判断

结束时请学生在作品旁回答：你希望谁看到什么？哪处是你决定的？哪条AI建议你没有采用？你实际试过什么？下一版最想改什么？允许“不知道/没有/还没试”，照实记录。

观察记录分开填写：

- **选择与解释**：指出一个自己的决定，并能对应到读者、证据或限制；仅复述AI措辞另行注明。
- **辨别与修订**：能识别假设和实际结果；发现错误时是否有可用的修改入口，修改是否落实到作品。
- **主动探索**：是否主动尝试另一种意象、比较版本或测试入口；记录触发情境，不把点击数当作兴趣。
- **继续意愿**：给出可自由结束的机会后，是否选择继续，以及学生自己的原因；不能用奖励或教师要求下的继续代替。
- **挫败与退出**：在哪个位置需要帮助、重复输入、等待或放弃；同时记录具体原因和当时作品状态。

以上是本轮产品验收观察项，不是已验证量表，不据此宣称学习效果提升。

## 判定边界

出现内容丢失、串版本、未经确认公开、虚构结果混入作品或主要流程无法继续，相关路径不能交付。解决后重走受影响的完整路径，保留失败记录。

技术检查通过只证明该检查覆盖的行为。若需要开发者持续改写输入、替学生判断或修复数据才能走通，不判为学生可独立使用。趣味与教育意义没有学生观察记录时继续标为“证据不足”。全部场景的真实终点、必要角色和恢复路径均需逐项核对，未执行项不能勾为完成。
