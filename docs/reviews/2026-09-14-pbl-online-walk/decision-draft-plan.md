# 决策草稿保存修复

2026-09-15，本机社区项目已复现：选择方案并填写部分原因，收起工具再打开后全部清空；排序可恢复。学生可能需要回看计划或成果再继续填写，当前行为会丢失思考内容。

## 行为与边界

选择、选择原因、各未选方案的原因、改变主意条件均自动保存为未确认草稿。重新打开和刷新后恢复。保存草稿不设置 settled_at，不触发工具完成，不作为已确认判断回灌陪练。已有最终决定保持不可覆盖。

草稿独立于最终 choice/why/why_not/flip 字段，避免其他列表或统计把暂选当最终决定。候选方案用稳定 ID 引用，未选原因按选项 ID 保存；排序不改变归属。新增自定义方案的未提交输入也需保留，不能只恢复已选方案。

## 实施路径

1. 在 internal/store/migrations 中新增决策草稿 JSONB 和修订号，sqlc 查询按决策 ID、未确认状态及预期修订号更新。最终确认与草稿清理在同一事务内完成，迟到草稿请求不得覆盖已确认决定。
2. 新增决策草稿读取/更新端点，复用 loadOwnedPblDecision，同时校验项目和决定归属。校验选项 ID 属于当前决定、文本长度和对象结构；拒绝已确认决定及旧修订号，不默默覆盖另一页面的内容。
3. 前端加载草稿后才启用编辑；串行保存，合并排队中的最新状态。显示保存中、已保存、保存失败；收起前等待当前写入，失败时保留输入并允许重试。确认前等待草稿写入，然后提交明确的最终判断。
4. 草稿恢复时以当前选项集合验证引用，失效选项不自动映射给另一个方案。冲突保留本页输入并提示重新加载，不丢弃用户内容。

## 验收证据

- 接口：未完成字段可保存；他人/其他项目/已确认决定不可写；旧修订号不能覆盖；草稿不进入已确认回灌；确认和迟到保存并发时最终决定不被覆盖。
- 页面：部分理由→收起→重开、刷新恢复；排序后理由不串位；切换选择后各方案理由仍属于原方案；自定义方案草稿恢复；保存失败可重试；确认后再次打开不出现过期草稿。
- 使用当前真实 Go/SQL 接口和浏览器验证；不以组件标题渲染测试代替数据与竞态验收。
