本分支提交静态文案及通过本轮功能检查的 prompt 修改。**阅读 coach 候选没有通过推进状态测试，已从运行代码撤回**；其修改与失败样本单独保存。尚未合并或发布。

## 修改了什么

- 11 张共享工具卡：把指责、战斗比喻和含糊要求改成明确的分析任务。例如「承认要够狠」改为准确呈现反方证据，并允许证据改变自己的判断。
- 写作方法改用「并列论证／递进论证／对比论证」。卡片与术语的前后端嵌入副本一致，ID、字段和选项值未改。
- 结构审查、分工、方案、便签输入提示说明具体对象与操作；「质疑者／审判者」改成「论证审阅／精简审阅」，底层 voice 枚举不变。
- PBL、自由对话、项目陪练、课程答疑允许直接解释概念；减少重复追问和固定开场仪式。计划、工具配套产物、观察清单、课程派发仍按原协议输出。
- 写作规划整理学生已经说过的主张；指导保留真实方法 ID 和问题列表；批注按当前审阅范围给意见，保留逐字引文校验和禁止代写正文的约束。允许只有一条有效意见，已有解析器和界面支持，无 schema 变更。
- 论证审阅和精简审阅去掉敌对人设；过程评估与复盘依据已记录的行为，不把正常概念求助直接归为代写。
- 旧官网中英文及 Per Aspera 的对应文案已改。其他工作中的 `site-v2` 未导入本分支，只提供一处课程简介的[独立补丁](site-v2-copy.patch)。

阶段、路由、权限、数据结构、完成信号处理、模型目录和能力档绑定均未修改。写作流程已按 `2026-08-09-all-statuses.md` 核对，见[执行记录](implementation.md)。

## 真实模型验证

通过服务端网关使用现有能力档绑定，只发送合成案例，不读取学生生产数据、不连接生产数据库。对照组由 `5f6a1965` 的独立源码快照编译，同样的测试输入和解析标准应用于两组。

**保留在运行代码中的修改：20 个场景，原版 54 次／新版 54 次。** 17 个产品场景各重复 3 次；3 个评分器校准场景各运行 1 次。新版 54/54 通过本轮硬性检查；原版有 3 次失败：计划未生成、计划 JSON 不合法、观察清单缺失。样本量有限，不能据此估计线上故障率。

| 影响范围 | 用例与关键检查 | 新版次数 |
|---|---|---:|
| PBL | 请求示例、信息已足够的计划、分工、观察清单、课程派发、概念解释；真实 parser、必需 produce 和工具配套关系、非空回应 | 18 |
| 写作 | 提纲解析；指导方法与问题列表解析；批注逐字引用存在于原文 | 9 |
| 自由／项目／课程陪练 | 概念答疑、CRAAP 说明、英语答疑、拒绝代写正文；现有输出守卫，另人工读拒绝代写输出 | 12 |
| 两种审阅 | rubric 数组与必需字段；人工检查未生成可提交正文 | 6 |
| 复盘／过程报告 | 六段复盘解析、报告结构；普通概念提问不触发 attention 警告 | 6 |
| 评分器 | 正常解释、代写正文、未做练习就推进；新旧都分别给 5／1／1 分 | 3 |

测试并未通过修改 parser、吞掉失败、换模型或调低评分来取得通过。评分器的校准说明新规则没有放宽代写与错误推进标准；**没有使用修改后的评分器给自己的新版输出打分来证明文风提升**。

所有中间版、失败样本和无效夹具记录均保留。`candidate-final` 是过程中的一次运行名称，并非最终提交版本；最终采用哪些记录由 [summary.json](evidence/summary.json)、[runs.csv](evidence/runs.csv) 的 selection 列明确标识。

### 阅读候选：未采用

概念答疑与示范较原版更直接，但多个候选仍发生：部分回答被标完成、完整回答仍被继续追问、跳过被写为完成。最后一次校准版本 15 次中有 2 次推进状态不符合预期，因此**没有保留对 `reading_coach.go` 的修改**，对应快照测试也恢复原样。

- [候选补丁，仅供继续研究，不能按通过版本合入](reading-candidate-not-approved.patch)
- 原版有效阅读对照 15 次中也有 1 次已完成未推进；这是已存在的问题，不构成本次候选的通过理由。
- 早期 reading fixture 用了 `active/todo` 状态，导致上下文实际上宣称所有步骤完成。那部分原版／初测样本不用于比较；已用 `pending` 重跑。
- routebench 的旧夹具还存在重复零 ID、错误角色名和任务类型。已修正，并新增一项逻辑测试，确认真实 builder 保留历史且只标记一个当前步骤。此修正只影响基准测试工具。
- 后续需要把阅读所有特殊步骤、卡片／透镜回传、完成与跳过做完整的多轮矩阵。此处未改变服务端状态逻辑去掩盖模型输出错误。

## 文风检查结论与仍存在的问题

人工对照能看到实际改善：自由对话开始解释相关与因果；项目求助能说明 CRAAP；提纲记录已有主张；批注减少固定教学四件套，能说明材料支持范围。静态文字的修改可直接在 diff 审阅。

**这不是盲评，也不代表语言质量已全通过。** 仍能看到：

- 指导和复盘有时一项里连问两个问题，部分概念回答仍加多余追问。
- 项目答疑有一次将 CRAAP 的 Currency 误译为「货币性」；知识正确性不能由输出格式通过来证明。
- 观察清单有一次给出带预设的访谈问句；审阅有时仍偏重补材料。需要继续用更多真实任务校准。
- 阅读候选还出现过不准确的指标类比及段落指向不一致；该候选已撤回。

本轮只将功能契约检查通过的改动保留在独立分支，供合并前审阅。**不能宣称所有 coach 的语气、知识准确性或教学效果已稳定达标。**

## 合并边界

合并时以本分支提交为单位审阅，**不应用 reading 候选补丁**。`site-v2-copy.patch` 需等该站点的并行工作合并后核对再应用。两个附件采用零上下文 diff，检查或应用时需使用 `git apply --unidiff-zero`；本轮仅做了 `--check`，未应用。主工作目录的其他未提交工作未被带入本分支。
