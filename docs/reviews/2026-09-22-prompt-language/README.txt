提示词审查与产品行为验证 · 2026-09-22

分支：codex/prompt-language-review
基线：a28affca。未合并 main、未推送、未部署。

这次修改的判断依据
------------------
提示词需要说明学生或教师正在做什么、有哪些输入、这轮要完成什么、
结果如何呈现。是否改写取决于能否改善理解、思考和操作，不能只靠词语黑名单。
角色称谓、输出字段、证据边界、学生正文归属应当清楚；没有依据的心理推测、
已退役的功能说明，以及为了过去某个失败不断叠加的绝对要求，应当清理。

范围与入口
----------
- internal/prompts：固定提示词目录；templates.json 列出定义及消费入口。
- internal/api：阅读、写作、报告、教师工具与项目的动态任务指令和上下文。
- internal/agent：Pro 陪练、课程、研究框架、评估与报告提示词。
- internal/pbl、awakening、interest、news、litegrade、liteworkspace：领域提示词。
- canonical cards/vocab 及对应 Go 镜像：模型实际收到的方法说明和触发条件。
- 未改模型路由、API 鉴权、数据库结构、输出 JSON 字段或工具参数结构。
- 旧会话原文、外部引文、真实指定的性别、教学中的故意错误示例保留。
- 本地源码审查不覆盖数据库中独立维护的全部课程内容，也不是完整浏览器验收。

具体改动
--------
1. 兴趣测试
   报告说明学生刚完成兴趣测试；兴趣名称准确概括对象或活动，采用名词/动词短语。
   标题实测：潮汐发电 / 了解潮汐发电原理 / 利用潮水发电；
   桌游 / 玩桌游 / 修改桌游规则。不再用一个问题替代兴趣名称。
   初版仍生成“可再生能源探索”，人工检查后改进了三候选的任务说明，失败输出保留。

2. 兴趣深入思考与阅读推荐
   think：有知识性、思辨性或讨论价值的问题；write：值得展开思考的写作主题；
   make：明确、可实施的行动。无需强行改变学生观点，也不预设结论。
   先由代码选最多三个相关关键词，当前关键词优先，再选最多三篇未读文章；
   无相关候选时省略 read，模型只能从提供的候选中决定是否推荐。
   当前文章元数据只有学科标签，所以代码筛选是学科相关候选，不等同于语义精确匹配；
   最终提示词仍要求模型判断是否真正有关，无合适文章则留空。
   分组排序防止上下文的稀缺学科挤掉当前兴趣；有真实目录 gambling + 电影回归测试。
   无额外模型调用；阅读级别、缓存、候选外 slug 拒绝、真实标题覆盖仍由服务端负责。

3. 写作
   段落结构反馈明确“学生已经完成拆分/标注”，依据提交结果、原文和段落作用分析，
   给出有针对性的建议；不重新要求完成同一操作，不因未用齐类别而制造缺口。
   实际结构板不收集标注理由，因此提示词只在学生另外说明时参考，不虚构输入。
   Grounding 改为“如何提出有依据的写作建议”，说明引用、材料核实与具体修改方法。
   不预设学生拿不到材料或会编造，不强迫记叙文态度变化，不把单个段落当整篇评价。
   英文写作保留必要专业术语，日常解释用学生能理解的语言。

4. 阅读
   已确认 2026-09-17 后的新计划不再安排透镜。删除系统提示中的透镜目录和召唤说明。
   保留 lens 输出字段为空；仅存在旧记录/旧组件结果时提供对应兼容上下文。
   保留当前段落工具和交互卡。任务完成依据学生已表达的内容，AI 分析不能算学生成果。
   明确求提示、索答、跳过、任务完成的差别，保留现有状态推进规则。

5. 评价、项目与教师
   评价意见依据作品实际内容，取消强制 3–5 条及至少一好一坏的配额；保留 0–5 条，
   不变更字段。引用、分数、维度、问题对应行动等校验保留。
   学习记录不足不能推断学生没有学习；报告区分真实过程与系统解释。
   PBL 分工理由对应实际 owner（学生/AI/共同），不能把所有责任都写成学生责任。
   确定性的系统步骤继续由系统完成，不增加学生确认门槛。
   新闻候选不足时要求选择的数量不超过现有条数，不再同时强求无法实现的领域覆盖。

skills / tools 的判断
--------------------
当前 internal/skills 是课程/项目契约 DAG，不是按需加载的教学说明库。
本轮没有另建同名抽象，也没有把普通回复要求改成工具调用。
- 单次任务说明：保留在所属功能的 prompt builder，按当前状态选择。
- 共享教学表达：使用已有共享提示词；不把全部教学规则附加到所有调用。
- 查询、筛选、排序：由代码或现有工具执行；本轮文章候选筛选已这样处理。
- 未来若有多个流程复用完整教学方法，可建立可选择的教学模块，再评估是否需要
  skills 加载机制。仅拆文件不会减少模型混淆，也不能自动提高教学效果。

验证与证据
----------
summary.json 汇总全部真实调用、模型、失败与成本估计。
本轮保留 154 条 Clarity 调用、3 次报告调用、7 次教师工具调用，共 164 次记录；
按目录价格和可用缓存数据估计约人民币 1.83 元，不能当完整账单。
live-records.json.gz 保存各轮生产 builder 请求、输出和 validator 结果；
包含中间版本，不能把所有调用合计当成最终版本独立成功率。
checks/ 保存离线、真实模型及基线复现日志，归档时去除行尾空白；失败记录没有被删除。

仍未达成的质量目标
------------------
本轮并非所有真实输出都通过，不能据此宣布提示词质量已全面达标。
- 最终阅读比较样本仍先解释装机与发电量的区别再提问，未保留关键判断给学生。
- 写作引导仍出现同一项里连续追问；段落结构反馈存在接近可直接使用正文的解释句。
- 阅读计划和 Pro 审阅在部分样本中未完整遵循候选范围或权威预算状态。
- 教师与家长报告有些表达偏长；数字格式并非所有样本一致。
- 旧语言检查器误报正常术语“支撑”及结构标签“主张”。保留原始失败，人工判断
  区分词语误报和实际产品问题；不把自动失败总数等同于狠话发生率。
- 旧 guide fixture 缺少 Kind/Depth，实际测试成了开头指导；末轮单独纠正并记录。
- 真实模型测试是有限合成场景，部分通用/Pro 提示词只有离线覆盖；没有全面端到端
  或学生学习效果实验。后续需围绕上述产品行为进一步验证，不能以词语替换代替。
