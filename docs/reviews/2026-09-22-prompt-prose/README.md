# 提示词正文的语气与教学指令改写

本次接续 `codex/copy-prompts-0922`，基线为上一轮交付 `e8981487`。没有合并或发布 main。提示词正文提交 `ea25be6a`，最终代码与测试提交 `5e868a9c`。

## 判断与修改

用户指出提示词自己的语言会影响教练输出。本次检查了真正传入模型的文字，包括系统指令、拼接的任务说明、方法与问题词表、默认评分表、示例和失败重试说明。源代码中的历史注释不进入请求，因此没有把它们当作本次清洗对象。

发现的实际问题包括：

| 原指令 | 本次改写方向 |
| --- | --- |
| 一条理由可以靠一件具体的事撑住 | 根据材料选择事例、推理或比较，解释各自如何说明观点 |
| 把这张表甩给她挑 | 先了解学生想表达的内容，再据此整理结构 |
| 这篇稿子现在站在哪儿 | 概述文章已有的内容和表达效果 |
| 材料是否支撑观点 | 材料是否能说明观点 |
| 每轮先引用、再推断学生的兴趣 | 只有具体内容足够时才作暂定理解；学生只说不知道时直接提供帮助 |

重写了阅读、写作规划、段落引导、批注、规划检查及重试等指令段落；删除其中的开发复盘、警告符号和情绪化理由。结构名称、材料数量要求、节点类型、引用约束、学生撰写正文的边界及模型分工保留。规划达到条件后直接进入写作，不追加提问；新增真实重试用例守住这一点。

单纯删掉所有反面措辞后，模型仍会自行使用“主张”“站得住”等词。因此最终保留一条集中的简短用词边界，其余指令用正面的任务说明与正常教学示例。这个观察说明提示词原文是值得修正的来源，但不能据此断言它是唯一原因。本轮多次改动同时发生，不是严格的单因素 A/B 实验。

## 实测发现的功能问题

- 教师批改有时生成括号结构错误的 JSON，原有有限重试也可能失败。本次仅对 OpenAI 兼容通道启用网关已有的 `json_object` 约束；评分维度、引用校验和重试次数不变。Anthropic 通道保持原方式，并用协议边界测试确认不会收到不支持的参数。没有改模型、供应商、思考档位或模型目录。
- 整稿审阅有时在数组后额外解释字数。增加完整格式示例，说明字数意见也放入规定字段，数组外不追加说明。
- 整稿审阅的旧实验直接解析首次回复，未采用生产的去围栏和重试流程。本次改为调用真实 `ProposeReview`，记录各次原始输出和累计用量。
- 兴趣对话实验原来直接检查未经清理的引号。本次与生产保持一致，先运行 `CleanReply` 和 `StripBadQuotes`，再检查交付引文；原始回复仍完整保留。这不代表原始引用总是正确。

## 验证结果

最终 **102 条**记录通过用例指定的自动检查：阅读与连续对话 50、阅读计划 4、写作规划/引导/批注 6、规划结束重试 2、段落审阅 6、教师批改 4、兴趣对话 18、通用/项目/课程陪练 8、整稿审阅 4。采用 `prose-verified` 对应调用点、`prose-review` 整稿审阅及 `prose-dialogue` 兴趣对话的完整批次。

本轮共保留 **438 条**实验记录，费用估算 **¥3.1326**，包含失败和生产重试；记录数不等于 API 调用次数。Go 全量回归通过，日志见 `checks/`。本次没有修改前端组件，因此没有重复上一轮的浏览器及前端构建。

`final-samples.json` 按每个调用点最后一次完整批次汇总，不从同批中只挑成功回复。`requests.json.gz` 保存完整请求；各 JSON 保存原始回复、模型、用量和自动检查结果。失败批次也保留，文件名不代表整批通过。样本使用合成内容，没有访问生产学生数据。

模型仍按现有能力档配置：dialogue 为 `dashscope/deepseek-v4.1-flash`，compose/review 为 `dashscope/glm-5.3`。费用按目录价格及缓存输入 20% 折价估算，不是供应商账单。

自动检查覆盖解析、引用、完成/跳过、提示与索答边界、规划开始写作、结束对话及指定措辞。人工查看主要回复后，仍能看到部分重复确认、较长交接，以及过早提示概念区别的倾向；通过这些有限样本不能等同于所有表达已经自然、所有文章都能正确教学。
