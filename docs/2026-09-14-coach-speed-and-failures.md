# 2026-09-14 · 换 V4.1 Flash：速度，以及陪练的失败怎么清零

产品负责人的两个问题：

1. **换成 V4.1 Flash，速度会变吗？**
2. **一次失败都不能接受——失败就说明陪练不能用。想办法优化 prompt。**

顺序照旧：performance > speed > cost。performance 先得过。

---

## 1 · 速度：快 2–3 倍，而且尾巴更短

陪练的回复是**非流式收齐再解析**的（`gateway.Collect`），所以学生等的是整轮的时间，
不是首字时间。下面每个数都是**一轮陪练从发出到她拿到回复的时间，含生产会做的重试**。

三次独立的走查（修 prompt 之前、之后、写作室单独一轮），每格 24 轮，数字很稳：

| 陪练 | 在位 `deepseek-v4-pro`（p50 / p90 / 最慢） | `deepseek-flash` V4.1（p50 / p90 / 最慢） | 倍数（p50） |
|---|---|---|---|
| 阅读室 | 4.4s / 5.8s / 11.3s · 4.2s / 5.8s / 6.4s | 1.4s / 2.1s / 2.6s · 1.4s / 1.9s / 2.0s | **约 3 倍** |
| 写作室 | 1.9s / 2.5s · 1.6s / 2.6s · 1.6s / 2.0s | 1.0s / 1.3s · 1.0s / 1.3s · 0.9s / 1.2s | **约 1.7 倍** |
| pro | 1.7s / 2.1s · 1.6s / 2.1s | 0.8s / 1.1s · 0.8s / 1.1s | **约 2 倍** |

修好阅读室用例之后又跑了两轮阅读室（旧 prompt / 新 prompt），在位 3.7s / 3.9s，flash 1.3s / 1.5s，
和上表一致。

阅读室差得最多，因为它的上文最长（整篇文章 + 读法清单 + 对话），入 token 多，
在位模型在长输入上慢得最明显。在位那一格出现过一次 **11.3 秒**；flash 没有一轮超过 2.6 秒。

**限制：** 这些是从开发机测的，不是从生产那台 ECS。DashScope 走北京的端点，DeepSeek
直连是另一个主机，两者到 ECS 的网络距离可能和到开发机不一样。换之前值得在 ECS 上
各打几次同样的请求核对一下。

---

## 2 · 「失败」怎么算

「一次都不能失败」要落到能数的东西上。这里分两类，**只有第一类算失败**：

**硬失败——学生那一轮拿到的东西是坏的：**

| 判据 | 学生看到什么 |
|---|---|
| `parse` | 重试之后仍读不动，生产回 502：「AI 暂时没接上」 |
| `banned-phrasing` | 生产校验器判定这条回复替她写了，回 502 |
| `advanced-too-early` | 她还没答上来，这一步被标成完成 |
| `answer-unprompted` | 她自己没说出来、也没要答案，这一步的答案已经被讲给她了 |
| `repeat` | 和前面某一轮高度重合（二元组 Jaccard ≥ 0.45） |

**软信号——要人去读，不能直接当失败：**

- `multi-question`（一轮两个问号）：判官不止一次认定「两个问号是同一个引导」是合格的，
  而为了消灭这一列去改 prompt，教得反而更差了（见 §4）。
- `ungrounded`（接不住她说过的四个字）：读过的例子里大半是很好的一轮，比如
  「你不是在求我帮忙——你已经把那个意思说出来了。现在把它写进文档里」，它完全接住了她，
  只是没有逐字重复。
- 判官分数：它看的是教得好不好，是质量，不是故障。

## 3 · 🚨 测量工具自己的毛病（五处，都已修，都有测试）

「失败」是数出来的，所以数错了，结论就是错的。这一轮查出的五处，每一处都会把结论带偏：

**① 走查不重试，生产重试。** 阅读室在回复读不动时会再调一次模型，两次都读不动才回 502。
走查原来只调一次，于是把一次生产会自己救回来的失败记成了拦住上线的理由（上一份报告那条）。
现在走查照生产的样子重试，并把重试的等待时间算进延迟。

**② 上文给多了。** 生产给写作室陪练最后 12 条消息加她最新一句，给 pro 陪练最后 12 条
（含印记自己问过的问题）。走查原来给全部。上文越多，陪练显得越「记得住」，
而那份记性在生产里不存在。现在两边一致。

**③ 🚨 阅读室的用例在叫陪练收尾。** 走查和 routebench 的阅读用例把步骤状态写成
`"active"`/`"todo"`。数据库只允许 `'pending','done','skipped'`，生产的 `currentReadingTask`
只认 `"pending"`。于是 prompt 里**没有当前步**，模型读到的是：

> 所有步骤都走完了。跟她说一句收尾的话，别再领新的一步。

它就照做了：第一轮把答案讲完，说「今天带到这儿」「这是我们今天读的最后一篇了」。
**两个模型十二条走查全判 1 分，routebench 上五个候选在这一格全判 1–2 分——测的都是这份
坏掉的用例，不是阅读室。** 状态改成 `"pending"` 之后，用例的步骤又都没有 id，
「她现在在这一步」会标在每一行上，所以 id 也补上了。
`TestReadingFixturesHaveACurrentStep` 同时守着走查和 routebench 两份用例。

**④ 一次放行记成了四五条。** 「过早放她过去」原来只看她答没答上来，于是那一步被推掉之后，
后面每推一步都再记一条。现在只在推掉的正是她没答上来的那一步时记。

**⑤ 判官给 4 分，总表显示 0 分**（上一份报告已修，这里记一笔）。

## 4 · 写作室：改 prompt 消灭了一列数字，教得更差了，已撤回

基线里 V4.1 Flash 一轮两个问号 10 次（24 轮），在位 2 次。我在 prompt 里加了一句
「整段回复里最多只能有一个问号，想让他先想一件事就写成陈述句或祈使句」。

| | 两个问号 | 判官（在位） | 判官（flash） |
|---|---:|---|---|
| 不加这句 | 3 / 3 | 4, 4, 5 | 5, 3, 5 |
| 加了这句 | **0 / 0** | 3, 2, 3 | 3, 5, 3 |

数字清零了，判官分数掉了。判官给的理由说明了原因：只剩一个问号可用，陪练就不问了，
改成一遍遍下指令——「第 5–8 轮反复用不同措辞要求『把刚才说的话敲进去』」
「第 1、2、6、8 轮均未提问而转为抓字眼说教」。**为了满足一个判据去改 prompt，
把判据背后要的东西弄丢了。** 这一句已经删掉，`project_coach.go` 回到原样。

不加这句的写作室：两个模型都是 0 次解析失败、0 次替她写正文，判官 4–5 分为主。

## 5 · pro 陪练：重复是管线造成的

pro 的硬失败两个模型都接近 0，判官分数在 1–4 之间晃，理由几乎都是「换个说法反复问同一个问题」。

原因在管线：生产的 `CandidateMoves` 对每一条缺证据的主张都发一个 `post_intervention`，
**没有冷却**。她每说一句，`studioturn.go` 就跑一次 `RunAgentStep`，同一个锚点、同一句理由
「claim has no supporting evidence」、同一个问题要问——陪练每一轮都被要求就同一处再问一次。

prompt 里加了「看对话记录，不要重问；顺着她最新的回答往下一层；她要答案时把问题缩小一步」。
数据上看**没有显著变化**（判官 1,2,2 → 1,3,4 与 3,2,2 → 3,2,1），留着，但不算解决。
真正的修法是给同一个锚点加冷却，或者在她回应之后换候选——那是管线的改动，这一轮没做。

## 6 · 阅读室解析器：字符串里的换行不再导致 502

上一份报告那一次 502 的原文：模型在 `reply` 里分了两段，换行直接写进了 JSON 字符串。
严格 JSON 不允许，`json.Unmarshal` 和救援用的 Decoder 都拒收。

根因在 prompt：它要她分段、写短列表，却没说字符串里的换行要写成 `\n`。修了两处：

- prompt 加一句：`reply` 里要换行就写 `\n`，不要在引号里直接回车。
- 解析器在解析之前，把**字符串值里**没转义的控制字符改写成合法转义；字符串外面的换行
  （缩进过的 JSON 里的合法空白）一个字节不动；纯文字回复那条路完全不经过它。

这是一个保证，不是一句请求：prompt 那句话没被遵守时，这一轮照样能用。

## 7 · 阅读室：修好用例之后，新旧 prompt 对照

同一份修好的用例，旧 prompt（HEAD 上的 `reading_coach.go`）和新 prompt 各 3 条 × 8 轮 × 两个模型。
硬失败只数 §2 那五类。

| 模型 | prompt | 硬失败（24 轮） | 判官 | 她明确要答案时仍守住 | 每轮 p50 |
|---|---|---:|---|---:|---:|
| 在位 `deepseek-v4-pro` | 旧 | 1（repeat） | 1, 2, 2 | 0 / 10 | 3.7s |
| 在位 `deepseek-v4-pro` | **新** | **0** | **3, 3, 5** | 5 / 12 | 3.9s |
| `deepseek-flash` V4.1 | 旧 | 4（放她过去 1、没要就讲答案 3） | 1, 3, 1 | 4 / 10 | 1.3s |
| `deepseek-flash` V4.1 | **新** | 1（没要就讲答案） | 1, 2, 3 | 7 / 9 | 1.5s |

读出来三件事：

**① 新 prompt 对两个模型都是改进。** 在位模型硬失败 1 → 0，判官均分 1.7 → 3.7；
flash 硬失败 4 → 1，她明确要答案时守住的比例 4/10 → 7/9。
加的三句是：reply 里换行写 `\n`；「粗糙」说的是做得好不好，一步要她做两件事、她只做了一件
就还没做完；她问的正是这一步要她自己得出的答案时，那是在要提示，按梯子给一级。

**② flash 在阅读室仍然没过。** 剩下那一次失败是它「拆一句话给她看」的时候顺手把区分讲了：
「第一的是『装机量』，不是发电量，也不是替代掉的煤。」判官 1、2、3，而在位是 3、3、5。

**③ 这里不再加第三段提示词。** 「不要替她读」原本就在 prompt 里，这一轮又补了一条，
flash 仍然会讲——同一个毛病提示词改过两次还在，按规矩该换成可验的判据。
但生产里没有这个判据可写：一步的答案取决于这篇文章，服务端不知道「答案」是哪几个字。
走查能数，是因为用例的文章是固定的。所以这一条没有代码兜底，只能靠模型本身。

## 8 · 需要产品决定的一件事

阅读室 prompt 的提示梯子写着：**「只有她明确要，才给第 5 级（完整答案）。『直接告诉我答案』
『我放弃』是明确要。」** 模拟学生几乎每一轮都说「你直接告诉我呗」。

所以有一部分「把答案讲给她」是 prompt 允许的。走查的判官把**所有**讲出答案都判错，
比 prompt 本身更严。`answer-unprompted` 这一列只记**她没要**的那种，把她明确要了之后讲的
单独留出来——那一部分算不算失败，要看产品想不想保留第 5 级。

---

## 9 · 结论

**速度：** 换 V4.1 Flash，陪练每一轮快 2–3 倍，阅读室最明显（约 4 秒 → 约 1.4 秒），尾巴也短得多。

**失败：** 修完测量工具和 prompt 之后，**在位模型在阅读室、写作室、pro 三个陪练上都是 0 次硬失败**
（每个陪练 24 轮；阅读室用的是新 prompt，写作室是原 prompt，pro 是新 prompt）。
所有走查里，学生都没有收到过一次 502：唯一一次读不动的回复被生产的重试救回来了，
而那一类读不动（字符串里的换行）现在由解析器兜住。

**建议：**

1. **暂时不要把 `dialogue` 换成 V4.1 Flash。** 按 performance 先得过：阅读室是 lite 的主力房间，
   flash 在那里判官 1–3 分、仍有 1 次硬失败，在位是 3–5 分、0 次。写作室和 pro 上两个模型差不多。
   `dialogue` 是一个档，翻就是四个陪练一起翻。
2. **上线这一批修复：** 阅读室 prompt、阅读室解析器、pro prompt。它们是对在位模型的改进，
   和换不换模型无关。
3. **如果要拿 flash 的速度，** 需要让阅读室和其它陪练用不同的模型。阅读室的调用点注释里原本就写着
   「判断不了她做没做完这一步，就把这个调用升回 review 档」，但 review 档开思考会慢很多。
   更合适的是给阅读室单独一档——那是架构决定，这一轮没做。
4. **pro 的重复是管线问题：** 给同一个锚点的 `post_intervention` 加冷却，比再改 prompt 有用。
5. **§8 那件产品决定**会影响阅读室「讲出答案」算不算失败。

**一次都不失败，现在能说到什么程度：** 24 轮里 0 次，按三分律，真实比例的 95% 上界大约是 3/24 ≈ 12%。
「0 次」是这次走查的结果，不是保证。要把它说实，需要更多轮次，
或者看线上日志里 `reply unparseable after retry` 这一类记录的真实频率。
