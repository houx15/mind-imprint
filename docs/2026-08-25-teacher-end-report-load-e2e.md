## T-01 · Report load failure — the real bug (FIXED)

### Reproduction (before fix)
Teacher → Demo Class → 周报 → Phoebe's card → 看能力报告 → **"报告加载失败 · 这份能力报告暂时无法加载，请稍后重试。"**

### Investigation
The fetch **returned `200 OK`** with a well-formed `{report, status:"ready"}`
envelope — so it was never auth/404/network. Running Phoebe's real payload
through the actual `@mind-imprint/contracts` `EvaluationReport` Zod schema
produced **exactly 12 issues**, all identical in shape:

```
depth.0..5.evidence   :: invalid_type :: Expected array, received null
autonomy.0..5.evidence :: invalid_type :: Expected array, received null
```

### Root cause — a contract asymmetry
- Go's `evalreport.Validate` (`apps/api/internal/evalreport/validate.go`) is
  deliberately shallow: it checks only `version` / `reportId` / `projectId` /
  `student.id`. Its own comment: *"Deep-shape truth lives in packages/contracts
  (Zod); Go only guards the outer envelope."* A `nil` Go slice → JSON `null`
  passes this gate untouched.
- The TS Zod schema is that deep-shape truth, and `evidence: z.array(...)`
  **rejected** `null`.
- Phoebe's report (generated by an older binary that serialized empty evidence
  as `null`) is served `ready`, reaches the client, and `EvaluationReport.parse`
  throws → the fetch's `catch` sets `failed` → "报告加载失败".
- Both the teacher view (`TeacherReportView`) and the **student's own page**
  (`EvaluationReportPage`) share `parseEnvelope`, so this blanked the report on
  both sides, for every stored report with empty evidence.

The current generator (`reportgen.go`, `make([]…, 0, …)`) and the placeholder
already emit `[]`, so the `null` is purely legacy stored data — no data
migration is warranted.

### Fix (`56296cc9`)
`packages/contracts/src/evaluationReport.ts` — `DepthDimResult.evidence` and
`AutonomyDimResult.evidence` now `z.array(EvidenceItem).nullish().transform(v =>
v ?? [])`, mirroring the **existing** tolerance the `Abstract` list fields
already carry for exactly this "one empty optional field must never blank the
whole report" reason. Regression test added
(`test/evaluationReport.test.ts` — legacy null-evidence shape → coerced to `[]`).

Chose the Zod layer (not a Go change) because the architecture explicitly makes
`packages/contracts` the deep-shape authority, and this instantly renders every
affected stored report with zero migration.

### Verification
- Phoebe's **real** prod payload: `EvaluationReport.safeParse` → **PARSE OK**
  after the change (was 12 issues before).
- `packages/contracts`: 336 tests pass; typecheck clean.
- `apps/web`: 1256 tests pass; typecheck clean.
- **Live (after deploy `web @ 452a7025`):** teacher → Phoebe → 看能力报告 now
  renders all 9 sections (基本信息 … 风险提示) with her real research question and
  综述 prose. A second, older report (2026-08-14 EE) also renders. No failure,
  no stuck spinner.

## T-02 · The "plain one-sentence" student abstract (design, not a bug)

The class page's per-student card (`ClassWeeklyView` `FocusCard`) renders three
fields: **lead** (LLM prose, bold) + **evidence** (deterministic fact) + **action**
(线下 nudge). The prose prompt (`compose_weekly.go`, rule 3) asks the model for a
`lead` that is *"one sentence saying what happened"* — so when the evidence is
already a complete activity sentence ("本周完成 2 份能力报告。"), the `lead` just
echoes it, and the card reads as the same sentence twice.

This is the deliberate post-activity-migration shape: the weekly card is an
**activity** note (登录/报告/课程/对话 counts), not a substance summary of the
student's thinking — the substance lives in the full 能力报告. Making it richer is
a product decision (it touches 铁律② "不操纵" — per-student weekly substance
summaries edge back toward evaluative framing), so it's surfaced for direction
rather than changed unilaterally.

## Verified robust (no bug)
- Roster table (`全部学生`), student detail, usage records, weekly prev-week nav,
  class switching, breadcrumb back — all fine.
- Auth: teacher routes gated `RequireRole("teacher","admin")` + class ownership +
  per-student membership + project-ownership; no leak, no misroute.
- Report view is read-no-call: teacher never triggers generation (only polls).
  A report that is genuinely `generating`/absent shows the honest
  生成中/还没有报告 states — not the failure state (that path was the T-01 bug).
