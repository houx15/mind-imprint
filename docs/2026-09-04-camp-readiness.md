# 四天营 · 开营前该修的东西

模拟学生走查的结论。走查本身、每一步的记录和截图见
`apps/lite-web/e2e/camp/`，跑法在 `camp.spec.ts` 的注释里。

## 这份结论是怎么来的

四个学生由一个模型扮演（qwen3.8-max，不是印记那条 deepseek）。它每一步只拿到
两样东西：**这一屏渲染出来的字，和能按的按钮**。没有项目 id、没有接口、不知道
产品有几关、不知道「视觉基调」按下去会发生什么。每步它给出「我知道现在该干什么
吗」（clarity 1-5）、「这一屏在帮我吗」（support 1-5）和一处「看不懂的地方」。

营里有老师：学生连着三步说不清该干什么，老师就介入——一级只说今天的目标，
二级报坐标（「左边那栏有『项目』」），三级替她点。**老师介入的次数就是这份
走查的主结论**：一个二十人的营，老师要走过去多少次。

### 它答得了什么、答不了什么

答得了：**字面上说不说得清**——一句提示指向的东西在不在屏幕上、一个报错说的
名字找不找得到、印记说给你的东西到底有没有出现。

答不了：**看上去像不像可以点**。它拿到的是一个没有版面的按钮清单，一张大卡片
和一颗小按钮在它眼里一样大。它曾连点同一张受众卡 23 次，而「确认选择」就在
旁边亮着（查了那一步记录的按钮状态，确认是亮的）。凡是关于视觉、布局、层次的
判断，仍然只能靠人看截图。

## 一、最该先修的一条：印记说给了，屏幕上没有

**这一条一个人身上重复了二十多次，是四天里最烧时间的地方。**

Marcus 第二天，印记反复说「这版页面和 review 卡我一起给你了」「你重新打开
review 这张卡」，而右边的审核助手一直写着「暂时没有需要审核的内容」。他的原话：

> 「界面和 AI 说的话完全对不上，我不知道是该信它还是信屏幕。」

**服务端是对的，而且是故意的。** `pbl_tool_gate.go` 那道闸：审核助手的界面本身
没有内容，摆的是印记做出来的那份成果；成果没落库就把这张卡撤掉——理由写在文件
头，「她少看见一个工具卡，比看见一个点开是空的工具卡好得多」。运行日志里能看到
它确实撤了：

```
WARN pbl turn: 印记 offered a tool whose surface would be blank; dropping it  tool=review
```

**问题是撤掉之后谁也不知道。** 学生不知道（她只看到印记说给了，然后满屏幕找），
印记也不知道（回灌里没有这件事），所以它下一轮照样再说一遍。Marcus 在这个循环里
耗掉约 35 步、8 次三级介入（老师直接替他点），第二天没走完。

同一个形状还有两处：

- 「站点采集那张卡里已经放了六个现成的链接，你直接点进去就行」——那六个链接要
  按了「开始任务」之后才存在。她照字面在屏幕上找六个链接，找不到，判定这张卡
  不存在。
- 「你看这两张受众画像卡片，选一个」——卡片没递出来。

**建议：** 和 2026-09-04 那次「印记看不见页面状态」同一个修法——把这道闸的结果
写进下一轮回灌：「你上一轮想递『审核助手』，但你没有交出可审的成果，那张卡没有
出现在她屏幕上。」印记要么补上成果，要么别再说给过了。

> 这也是 [[prompt-output-must-be-verifiable-2026-09-03]] 那条的又一次印证：
> prompt 里写「工具和产出同一轮一起给」是请求，闸是保证，**而保证拦下来的东西
> 必须回灌给它**，否则它会永远重复同一句。

## 二、报错指向一个界面上没有的名字

上线时报：

> 后台错误：请先在「视觉基调」里定下配色和风格

而屏幕上没有任何按钮、菜单或标签叫「视觉基调」。Marcus 在第一天问了 7 次、
第二天又问了 10 次：

> 「我不知道『视觉基调』是个按钮、个菜单还是个概念，页面上也没看到这个词。」

「后台错误：」这个前缀也是给我们看的，不是给她看的。

**建议：** 报错里指到的东西必须是她当下点得到的：要么把「视觉基调」做成这条
报错里可以直接点开的入口，要么改成她屏幕上真有的那个名字。

## 三、话少的学生会被问住

林知遥（设定：内向、答得短）第一天：印记连着约十轮追问食堂细节——倒了几盘、
勺子怎么翻、同桌说了什么——她答「没数过」「真的没注意具体多少盘」，印记接着
问下一个细节。她最后打出来的是：

> 「那我要怎么选啊」

这一天用了 **6 次老师介入，其中 4 次是老师直接替她点**，仍然没走完。

对照 Marcus（话多、爱展开）第一天只用了 **1 次**介入就走完了。

**这条对营最要紧**：产品目前更适合愿意大段讲自己的学生。营里一定坐着答两个字
的人，而她恰恰最需要被带着走。

**建议：** 追问要有上限。同一件事问过两轮她还答不出细节，就换一条路——给她两三个
具体选项挑，或者直接把工具递出去让她在里面动手，而不是继续问。

## 四、第一天她不知道该进哪扇门

新账号落地在「今日探索地图」——五条科学新闻。屏幕上没有一处提到主页或项目。
四个人第一天都在这里绕过，绕的时间从 4 步到 30 步不等：

- 有人一直翻新闻，以为要看完才能开始：「不确定是不是必须把这 5 条都看完才能做主页」；
- 有人拐进了「我的树」的兴趣引导（选向导、确认连接、提交兴趣信号），在里面走了
  十几步才发现不是今天要做的事；
- 有人干脆问「完全找不到开始做个人主页的入口」。

同一条路不同轮次要 **0 到 4 次**老师介入才走得出去——不是每次都坏，是**不可靠**。

**建议：** 落地页上给「你还没有主页」一个明确的位置。这是新账号唯一能做的事，
而现在它在第四个图标后面。

## 五、探索地图会整天打不开，而重试没用

第一屏报：

> 今天没有星图　生成失败：select reply is not the expected object: unexpected end of JSON input

按「重试」没有任何变化。学生原话：**「不知道是不是我弄坏了什么。」**

两个原因叠在一起：

1. `news/select.go` 的 `sliceJSONObject` 还是「第一个 `{` 到最后一个 `}`」——
   模型回的内容被截断时，切出来的是一段坏 JSON。这正是
   [[three-journeys-acceptance-2026-09-04]] 里 `pbl/jsonwire.go` 已经换掉的那种取法。
2. `explore.go` 的章盖在生成之前（这是对的，防止每个打开的学生都触发一次抓取
   加一次模型调用），但**失败也照样 `FinishNewsDay`**，于是之后 `GetNewsDay`
   一路早返回，`live.reload` 读到的还是那条失败记录。

**今天六次启动里撞上两次。** 对营来说这是最差的形状：**早上第一个打开 app 的
学生替全班掷这个骰子**，掷坏了，二十个人一整天看的都是这行英文报错，产品里没有
任何按钮能救回来。

**建议：** 三处一起改——取 JSON 改成数括号（照搬 `firstJSONObject`）、报错里带上
模型原样回的那段（第 8 条：动词+失败 + 后台原话，现在这段只在响应体里，
slog 里没有，线上查不到）、以及让「重试」在 `planet_count = 0` 且 note 是生成
失败时真的重来一次（给个次数上限，别把防雪崩那层拆了）。

## 六、做完的项目没有能拿走的东西

产品负责人 2026-09-04 问的：做完之后有没有一份好看、生动、让人愿意转发的东西，
以及有没有地方看到她真做出来的那个成果。

现在：**只有主页有**（二维码 + 链接 + 撤回）。其他项目做完之后产出的是复盘六段的
答案，留在房间里，没有页面、没有分享链接、没有导出。`public/reports/{token}`
是阅读面 atom 报告的，PBL 项目接不上。实物成果没有地方放照片——`pbl_artifact`
的 `image`/`site` 是印记的产出交给她判断，不是她拍的东西。

值得注意的是**那套机器已经有了而且做得不错**：`src/reports/ReportPoster.tsx`
（海报 PNG，html-to-image）、`SharePanel.tsx`（二维码 + 分享 token）、
`PublicReportPage.tsx`（陌生人打开只看到这一份东西）。它只是从来没有接到项目上。

**建议（按营的用法排）：**
1. 项目复盘完 → 生成一份项目报告，走现有的 poster + 分享 token + `/s/:token`；
2. 成果按类型给不同的展示位：网页给二维码和链接（已有）、实物给照片、
   文档给导出；
3. 照片需要一条学生侧的上传路径，现在 PBL 那边一条都没有。

## 七、两处小的

- **落地页首屏 23 秒。** 冷账号第一次打开 `GET /api/v1/explore/today` 实测
  23.4 秒才有东西可点。
- **星图那次模型调用的成本记不进去。** `llm_call.user_id` 是
  `NOT NULL REFERENCES users(id)`，而 `explore.go:286` 传 `uuid.Nil`（这次调用
  不属于任何学生，是一天一次的公共开销），于是每天那行成本都插不进去：
  `insert or update on table "llm_call" violates foreign key constraint`。
  `atom_id` 在 0094 已经放开成 nullable 并处理了，`user_id` 没有。怎么记要先定：
  记到当天第一个打开的人头上会让人均成本失真。

## 好的那一半

**房间本身是好的。** 每一次学生真的走进项目房间，clarity 就从 1-2 跳到 4-5：
驱动问题在页头、五步计划在右边、审核完成就开始、工具递过来就能做。四天里所有
卡住的地方，没有一处发生在「她已经在房间里、手上有一件递给她的工具」的时候。

坏的全在房间前面那一段，和印记说的话与屏幕对不上的那些时刻。
