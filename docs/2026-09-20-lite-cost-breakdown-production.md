# 线上这十天，钱到底花在哪

2026-09-20，生产库 `llm_call`，`surface='lite'`，最近 10 天。

**这份数不需要等新数据**：token 一直在库里（`prompt_tokens` / `completion_tokens`
/ `model` / `purpose` / `atom_id`），缺的只有价格。价格填进 `models.json` 之后，
过去每一行都能重算一遍。线上 `cost_estimate` 那一列的 0 不是「便宜」，是「没记」。

工具：`DATABASE_URL=… go run ./cmd/costreport -by purpose`。

## 一、总量

| | |
|---|---|
| 调用 | 5,660 次 |
| 输入 | 35,953,701 tokens |
| 输出 | 1,840,555 tokens |
| **合计** | **¥195**（按实测缓存命中）／ ¥462（全部按全价，上界） |

输入是输出的 **19.5 倍**。所以这是一个「上下文成本」的产品，不是「生成成本」的产品。

### 缓存那一档是真的，用线上数据验过

阅读陪练重发全文，但稳定块排在前面，所以第二轮起命中。实测命中 91%–99%。
担心的是 5 分钟 TTL —— 学生会思考，想久了缓存就过期了。查了真实间隔：

| | |
|---|---|
| 一次会话里的第一次调用（无从命中） | 157 |
| 距上一次 **≤ 5 分钟**（可命中） | **2,578（93%）** |
| 距上一次 > 5 分钟 | 33 |
| **间隔中位数** | **9.6 秒** |

她们答得很快。所以 ¥109 是阅读陪练的真实花费，不是 ¥376。

## 二、一次阅读 / 一次写作多少钱

| 种类 | 次数 | 平均 ¥ | 中位 ¥ | 最贵 ¥ | 合计 ¥ |
|---|---|---|---|---|---|
| **阅读** | 227 | **0.581** | 0.240 | 3.356 | 131.90 |
| **写作** | 134 | **0.374** | 0.344 | 1.139 | 50.06 |
| 项目 | 4 | 0.465 | 0.463 | 0.549 | 1.86 |

🚨 阅读的**平均是中位的 2.4 倍**，最贵一次 ¥3.36 —— 长尾很重。
平均值被少数很长的会话拉高了，优化要盯着那条尾巴，不是中位。

一次阅读：15.6 次调用、140,202 输入 tokens。
一次写作：10.0 次调用、23,464 输入 tokens。**阅读的输入是写作的 6 倍。**

## 三、钱花在哪个调用点

### 一次阅读（平均 ¥0.581）

| 调用点 | ¥/次 | 占比 |
|---|---|---|
| **`reading_coach`** | **0.4813** | **82.8%** |
| `lite_report` | 0.0427 | 7.3% |
| `reading_plan` | 0.0275 | 4.7% |
| `read_questions` | 0.0122 | 2.1% |
| 其余（段落工具等） | <0.005 each | ~3% |

**一个调用点占掉一次阅读的 83%。** 它平均每次带 11,035 个输入 token。

### 一次写作（平均 ¥0.374）

| 调用点 | ¥/次 | 占比 |
|---|---|---|
| `plan_turn`（compose / glm-5.3） | 0.1108 | 29.7% |
| `review`（review 档） | 0.0819 | 21.9% |
| `writing_turn`（dialogue） | 0.0503 | 13.5% |
| `block_guide`（compose） | 0.0436 | 11.7% |
| `block_comment`（review） | 0.0386 | 10.3% |
| `lite_report`（assess） | 0.0322 | 8.6% |

写作是**摊开**的，没有单一大头。所以写作这边一次只动一个调用点，省不下多少；
要动就动它依赖的两个档（compose 和 review 合起来占 73%）。

## 四、据此排出来的优先级（不再靠猜）

1. **`reading_coach` 就是那个目标。** 它一个人占 lite 总成本的 56%、
   一次阅读的 83%。两条路可以叠加：
   - **换档**：`dialogue` 现在绑 deepseek-v4-pro（¥12/¥24）。
     换成 deepseek-v4.1-flash（¥2/¥8）后，这一项十天从 **¥109 → 约 ¥20（−82%）**。
   - **渐进披露**：每轮只送当前这个「部分」，不送整篇。输入从 11,035 降到
     约 4,000 ⇒ 再省约六成。两条都做：**¥109 → 约 ¥7.5（−93%）**。
2. **写作看两个档，不看单个调用点**：`compose`（plan_turn + block_guide = 41%）
   和 `review`（review + block_comment = 32%）。glm-5.3 是 ¥8/¥28，
   GLM-5.3-Flash 是 ¥0.8/¥2.8 —— 十倍差价，但要先有 lite 的 benchcase 才能证明不掉质量。
3. **`lite_report`（assess，¥0.043/次阅读 + ¥0.032/次写作）** 单次很贵
   （实测一次 7,550 输出 token，其中 7,086 是推理），但一次会话只跑一次，
   所以占比不高。先不动。

## 五、这份数的边界

- 缓存命中是按**实测比例**套上去的（阅读陪练 91%），不是逐行读回来的 ——
  `cached_tokens` 这一列还没建（要动 sqlc 生成物，见
  `2026-09-20-lite-ai-cost-and-routing.md` 第六节）。间隔那张表让这个假设站得住，
  但建了列之后这份数才是逐行真值。
- 十天里 PBL 只有 4 次会话，样本太小，不要据此下结论。
- 十天 ¥195 是**当前用量**下的数（227 次阅读 / 134 次写作，基本是走查和试用）。
  真实班级上量之后按比例放大。
