# 阅读室重构 · 探索「兔子洞」地图 Design Spec

> **状态：** 设计定稿待评审（本文件即评审对象）。批准后进入 writing-plans 出实施计划，再分期 build。本轮**不写代码**。
> **日期：** 2026-08-05
> **取代：** `docs/superpowers/specs/2026-07-27-reading-together-redesign-design.md` 中「探索图谱」那一层的形态（列表/图书馆一侧保留其成果）。

**Goal（一句话）：** 把「阅读」室里那个按钮过多、概念混乱的「探索图谱」，重构成一张清晰的**两层地图**——每个问题就是一个「兔子洞」，学生钻进去、开始搜文献——同时把「列表/图书馆」切换器移到左侧、重命名加图标，让整个阅读室一眼看懂。

**为什么重构：** 当前「探索图谱」（`ExplorationView.tsx`，单文件 1198 行）把「线索/来源/分支/悬空/连接/剪枝」等六七个概念摊在一个三段式布局里，约 12 个按钮，学生看不懂在做什么。参考 ResearchRabbit（纯文献 + 引用网络可视化）后确认：我们**不是**它——我们占「思考」这一层，文献只是思考的证据。重构要借它的清晰，不借它的定位。

---

## 0. 硬约束回顾（本设计据此裁剪，违反即否决）

- **铁律①** AI 克制，绝不替学生定论：印记只**推荐/提议**，学生**确认**才落到地图上。
- **铁律②** 不操纵，触发自动、打开由学生确认：印记发现问题间关系时**提议**一条带标签的连线，学生接受/改标/忽略；不自动连、不自动填。
- **铁律④** 过程即数据：跳过、丢弃、改标都被记录。
- **占「思考」这一层，不做花哨文献管理器：** 不引入密集引用网络、不自动倾倒 citation graph、不做 Google-Docs 式排版。
- **避免行话（本轮新增，用户明确要求）：** 「兔子洞」是**内部结构隐喻 + 轻调性**，**不进 UI 按钮文案**。界面用大白话：问题 / 论文 / 笔记 / 探索 / 图书馆 / 深挖。

---

## 1. 顶层重构：两个「地方」，切换器移到左侧

阅读室从「右上角一个 列表⇄图谱 分段控件」改为**左侧竖向切换**，两个入口重命名 + 加图标：

| 入口 | 图标 | 是什么 |
|---|---|---|
| **图书馆** | 书架类图标 | 一个**收藏**：你碰过的所有论文，带**标签**与**状态（待读 / 在读 / 读完）**。是书架，不是图谱。 |
| **探索** | 网络/节点类图标 | 一个**工作区**：只干一件事——生长和浏览你的**问题地图**（下述两层模型）。 |

- 切换器从 `ReadingBlock.tsx` 头部的 `justify-end`（右）移到**左侧**。
- 「探索」为有来源项目的默认视图（沿用当前 `viewModeMemo` 逻辑）。

## 2. 核心模型：两层地图

### 2.1 顶层 = 问题的「带标签有向图」（= 兔子洞地图 / the warren）

- **节点**永远是**问题 / 关键词**（对应现有 `exploration_lead` 里 `parent_lead_id = null` 的根 lead）。**论文永远不是顶层节点。**
- **边是有标签的**（这是让顶层成立的关键——无标签只说「相关」，有标签才说清「怎么相关」，这就是**论证结构本身**）。**固定小词表**（非自由文本）：
  - `子问题`（层级由此涌现，不单独做「层级」概念）
  - `支持`
  - `反驳/张力`
  - `细化`
  - `依赖/前提`
- **谁连边：印记提议 + 学生确认。** 印记察觉「Q3 好像与 Q1 矛盾」→ 提议一条 `反驳/张力` 连线 → 学生接受 / 改标 / 忽略。无手动画边的苦役，无 AI 擅自连接。
- 顶层图**刻意保持小而可读**（节点 = 主题，约 2–8 个，不是论文），所以永远不会变成 citation hairball。

> 顶层就是**学生论证的骨架**——这一层是「思考」，是我们要占的层。评估未来可直接从这些带标签的边读出论证形状。

### 2.2 内层 = 每个问题（一个「兔子洞」）里：稀疏树

钻进一个问题节点 = 放大到它的内部：

- **主干是一棵左到右的树（溯源）：** 「我从 A 深挖出 B」= 单父节点 = 树。深挖 = 向右生长 + 折叠。
- **加少量交叉连线（cross-links）：** 仅当一篇新论文确实与地图上**已存在**的某节点相关时，画一条虚线。
- 内层节点可以是**论文**（深挖它 → 相关论文）或**子关键词**（深挖它 → 推荐论文）。

> 这是一张**稀疏图、以树为主**：多数论文只连它被挖出的父节点，交叉线只在「新论文回连到已有节点」时出现。既满足「文献研究需要图」的直觉，又永不 hairball，也**不是** ResearchRabbit（不密集导入引用网络）。

### 2.3 为什么是这个形状（数据结构依据）

- 顶层问题之间**没有单一父节点**（两个主题可以并列、重叠、互斥、互相支撑）→ 本质是图，且**带标签**才有意义 → 带标签有向图。
- 内层「我从 A 挖出 B」**每个节点单父** → 本质是树；真正的论文关联是稀疏交叉线补充。
- 两层**渲染范式统一**：都是「以树为主的稀疏图」，只建一套渲染器。顶层图节点少（主题级）用不上物理力导库；内层沿用/精修当前缩进-rail 树式布局。左到右（根在左）——因为标签是长文本（中文问题 + 论文标题），左到右单行不折行，同级（一个问题下多篇论文）纵向堆叠、纵向滚动便宜。

## 3. 核心循环 = 三个动作（这是「减按钮」的答案）

当前约 12 个按钮塌缩为**三件事**：

1. **看地图** —— 在「兔子洞地图（顶层）」⇄「钻进某个洞（内层）」之间缩放。
2. **深挖** —— 从一个问题深挖（→ 印记推荐论文）、或从一篇论文深挖（→ 相关论文）、或输入关键词 / 粘贴链接深挖。
3. **印记推荐 → 托盘 → 采纳** —— 印记挖到的论文先进一个**「刚挖到这些」托盘**（不自动落到地图上）；学生挑出要的采纳为真实分支，其余丢弃。

> 托盘而非自动落地，是铁律①/②：地图是学生的**思考**，印记不擅自往上插节点。AI 提议、学生确认，与全站「召唤卡片」同一克制阶梯。

**按钮映射（before → after）——实施计划据此裁剪当前 `ExplorationView.tsx`：**

| 当前控件 | 去向 |
|---|---|
| ＋添加来源 / ＋兔子洞 / 手动加线索 | 合并为**一个**「新问题 / 深挖」入口（动作 2） |
| 每条 lead 的 ＋分支 / ＋来源 / 深挖这条 / 连接来源 / 剪枝（5 个） | 收进节点悬停/点开的**极简菜单**；「深挖这条」= 动作 2，「剪枝/连接」降级为节点次级操作 |
| 深挖面板「深挖一层」+ 每方向「记为线索」 | 变为**托盘**（动作 3）：印记结果进托盘，采纳=记为节点 |
| 来源 ⓘ / 进入阅读室 | 保留为论文节点的两个轻动作 |

（具体保留按钮的最终形态在 writing-plans 阶段定稿，本 spec 只锁「塌缩到三动作 + 托盘」的原则。）

## 4. 图书馆 ↔ 探索：一个书架，两个视图

- **一个论文库（沿用现有 `Reference`）。** 图书馆 = 你碰过的**所有论文**的全书架，带 `tags[]` + **状态（待读/在读/读完）**。探索 = **同一批论文**按问题排列的透镜。
- **深挖一篇论文 → 自动进图书馆**（状态默认在读/待读）。一篇论文可以只在图书馆、不在任何洞里（待读）；任何在洞里的论文也一定在图书馆。**不重复存储。**
- 「待读 / 读完」只是状态字段，与「全部收藏」不矛盾。

---

## 5. 阅读 → 笔记 → 在探索页选目标（用户改法）

- 在阅读室读一篇论文、发现值得追的点：**只是记一条笔记**（大白话，无「标个洞口」之类行话），挂在这篇论文上。
- 到**探索页**，可以**从笔记里选一个目标**，把它提升为一个问题（新洞）/ 深挖方向。
- 即：**读 → 记笔记 → 稍后在探索页把笔记提升成洞。** 不打断阅读心流，不自动建洞，符合「学生确认」。

---

## 6. 文献查询 API：OpenAlex（+ 复用 Crossref）

- **搜索 / 推荐 / 论文→相关论文** 走 **OpenAlex**：免费、无需 key、~2.5 亿 works，有摘要 + related-works + 引用计数 + 不错的相关性排序，速率宽松。最契合「印记推荐真实论文」和「深挖一篇→相关论文」。
- **DOI 元数据解析**沿用**已接好的 Crossref**（`materialize/doi.go`，免费无 key）——不动。
- 「印记推荐 → 点开 → 跳到 DOI」是真的（OpenAlex 返回 DOI/landing URL），非 mock。
- 服务端调用（客户端绝不直连），每次真实 LLM/外部调用照常记档位+token+成本。

---

## 7. 初始状态与冷启动

- **用项目的驱动问题作第一个洞**：学生已在立项/proposal 设了主题（如 Phoebe「中国是否让地球更可持续？」），它成为地图上第一个兔子洞——**学生自己写的**，非 AI 臆造。
- **冷粘贴一篇论文（还没问题）** → 印记问「这篇想回答什么问题？」→ 生出一个洞来装它。**论文永不作为根节点漂浮**（守住 §2.1「根永远是问题」）。
- 不做「AI 预铺多个候选问题」（会替学生定框架，碰铁律①）。

## 8. 数据模型增量（基于现有 schema）

现有（Explore 已核实）：`exploration_lead(id, project_id, text, status[open/connected/pruned], origin[takeaway/manual/guide], source_reference_id, connected_reference_id, position, parent_lead_id)`；`reference`（含 `tags[]`, `collection_id`, `abstract`, `journal`, `author`, `year` …）；端点 `GET/POST/PATCH/DELETE /projects/{id}/exploration/leads`、`POST /exploration/guide`（唯一花 LLM）。

**需要新增/调整（细节留给 plan，此处锁方向）：**

1. **顶层问题间的带标签边** —— 新增 `question_edge`（`from_lead_id`, `to_lead_id`, `label ∈ {子问题,支持,反驳/张力,细化,依赖/前提}`, 由印记提议 `proposed` / 学生确认 `confirmed` 的状态）。当前 `parent_lead_id` 单父不足以表达顶层多重关系；顶层改由此边表成图。
2. **内层论文交叉连线** —— 稀疏 cross-link（论文节点 ↔ 已存在节点的关联边）；可复用/扩展 lead 引用关系或加一张轻关联表。
3. **论文库状态** —— `reference` 加 `reading_status ∈ {待读,在读,读完}`（图书馆按此过滤/展示）；`tags[]` 已有。
4. **笔记 → 洞** —— 阅读笔记（现有 reading_note 若在则复用）在探索页可被「选为目标」生成一个根 lead（origin 记来源=note）。
5. **OpenAlex 接入** —— 服务端新增 `internal/materialize`（或新包）里的 OpenAlex 搜索/related 客户端；深挖端点返回**候选论文进托盘**，采纳才写库。
6. **信封/契约** —— 卡 JSON 与 Zod 契约（`packages/contracts`）随新交互更新；边校验只校信封外层，内层归 Zod。

> 复用优先：`exploration_lead` 作节点、`reference` 作论文、Crossref 作 DOI 元数据——都不重写。新增集中在「带标签边 + 论文状态 + OpenAlex + 托盘」。

---

## 9. 明确不做（守住定位）

- ❌ 不做 ResearchRabbit 式**密集引用网络**导入 / hairball 图。
- ❌ 顶层不做**自由文本**边标签（只用固定小词表）。
- ❌ 印记**不自动**往地图插节点 / 不自动连边（一律提议→确认）。
- ❌ 不做花哨排版编辑器；不代学生提交；过程树只读。
- ❌ 不做 AI 预铺候选问题的「替学生定框架」。
- ❌ UI 文案不使用「洞口/warren」等行话。

---

## 10. 分期提示（留给 writing-plans）

两层可分期以降风险：

- **P-A** 内层「兔子洞」重构：三动作 + 托盘 + OpenAlex 深挖 + 论文自动进库 + 树式内层。终态 = 单个问题里的搜文献体验清爽可用。
- **P-B** 顶层带标签问题图：`question_edge` + 印记提议连线 + 缩放（地图⇄钻洞）。
- **P-C** 阅读笔记 → 探索页提升为洞；图书馆左侧切换 + 重命名 + 图标 + 状态过滤。

（分期边界最终由 plan 决定；本 spec 保证每期都能独立跑出可测的软件。）

## 11. 验收锚点（沿用 Phoebe 主动脉）

Phoebe / 「中国是否让地球更可持续？」：驱动问题成为第一个洞 → 钻进去、输入关键词/粘链接 → 印记走 OpenAlex 挖出 NASA / Nature Sustainability 进**托盘** → 采纳为树节点、自动进图书馆 → 撞反例（中国碳排放全球第一）新开一个洞、印记提议 `反驳/张力` 连线、学生确认 → 顶层图长出带标签的论证骨架 → 阅读中记笔记、回探索页把笔记提升成新洞 → 全程过程可读、评估从边读出论证形状。mockup 用真实内容。
