## Goal

A reactive, localStorage-backed persistence layer behind an isolated repository interface, so that `task` / `message` / `card_instance` survive a page refresh ("刷新不丢"). Replaces the dropped SQLite plan (roadmap §0.1). Nothing consumes the store yet — B3/B4/B5 will; this slice ships the store + the two missing contract types + a dev self-check panel, all green.

## Architecture

Two parts, in two packages:

1. **Contracts (B0 extension, `packages/contracts`):** add `Task` and `Message` Zod schemas. Today only `CardInstance`/`TraceEvent` exist as contracts; `task`/`message` exist solely as the *vestigial* `sqlite-schema.sql` logical model. The three persisted entities are `Task`, `Message`, `CardInstance` (the standard envelope, unchanged).
2. **Store (B2.5, `apps/web/src/store`):** an in-memory **immutable** `StoreState` mirrored to a single localStorage blob (`"mk.store"`), exposing `getSnapshot()/subscribe()` for React's `useSyncExternalStore` plus typed entity methods. Backing store sits behind an injectable `Storage` adapter so it is swappable (roadmap §5 parked IndexedDB-vs-localStorage; decision: **localStorage** for the demo, interface-isolated).

### Decisions locked in brainstorming (2026-06-21)

- **Storage tech:** localStorage, behind an isolated repo/adapter interface. (Roadmap §5 decision.)
- **Reactivity:** reactive now — `getSnapshot()/subscribe()` wired for `useSyncExternalStore`. B4/B5 consume a `useStore()` hook with no rework.
- **Corrupt-load policy:** missing blob → boot empty **silently** (normal first-run); present-but-invalid → boot empty + `console.warn` (fail-soft, never bricks the demo). Writes validate-then-persist and **throw** on validation failure (our own bug, not user-data corruption).

## Contract types (new — `packages/contracts/src/task.ts`)

```ts
export const TaskStatus = z.enum(["active", "evaluated"]);

export const Task = z.object({
  id: z.string(),
  title: z.string(),
  seed: z.string().nullable(),          // pasted article link / seed content; null when none
  status: TaskStatus,
  created_at: z.string(),               // ISO 8601
  last_active_at: z.string(),           // ISO 8601; bumped on any task-scoped write
});

export const MessageRole = z.enum(["user", "assistant", "system"]);

export const Message = z.object({
  id: z.string(),
  task_id: z.string(),
  role: MessageRole,                    // aligns with llm/types ChatRole → reusable as ChatRequest.messages in S3
  content: z.string(),                  // "" allowed (e.g. a pure tool-call turn)
  tool_call: z.unknown().nullable(),    // summon_card payload; real shape defined in S3, only persisted here
  created_at: z.string(),               // ISO 8601
});

export type TaskStatus = z.infer<typeof TaskStatus>;
export type Task = z.infer<typeof Task>;
export type MessageRole = z.infer<typeof MessageRole>;
export type Message = z.infer<typeof Message>;
```

Exported from the contracts barrel (`packages/contracts/src/index.ts`). Rationale:
- **Roles are `user/assistant/system`** (not 学生/AI) so a task's message list maps directly into `ChatRequest.messages` in S3, no translation layer.
- **`tool_call` stays `z.unknown().nullable()`** — S3 owns its shape; persisting an opaque value now avoids contract drift.
- `TaskStatus` is intentionally minimal (`active` → `evaluated`); extend when B6/B7 need more. YAGNI.

## Store module (`apps/web/src/store/`)

### Files

- **`schema.ts`** — `StoreState` Zod schema:
  ```ts
  export const StoreState = z.object({
    version: z.literal(1),
    tasks: z.array(Task),
    messages: z.array(Message),
    cards: z.array(CardInstance),
  });
  export type StoreState = z.infer<typeof StoreState>;
  export const EMPTY_STATE: StoreState = { version: 1, tasks: [], messages: [], cards: [] };
  ```
  `version` exists for future migration; **no migration logic this slice** (YAGNI).
- **`storage.ts`** — low-level adapter over an injectable `Storage`:
  ```ts
  export const STORE_KEY = "mk.store";
  export interface RawStorage { getItem(k: string): string | null; setItem(k: string, v: string): void; }
  export function makeMemoryStorage(): RawStorage  // Map-backed; for tests + ephemeral dev mode
  ```
  App passes `window.localStorage` (structurally satisfies `RawStorage`); tests pass `makeMemoryStorage()`.
- **`createStore.ts`** — the reactive factory (details below).
- **`useStore.ts`** — `useStore(store): StoreState` via `useSyncExternalStore`.
- **`index.ts`** — barrel (`createStore`, `useStore`, `makeMemoryStorage`, `STORE_KEY`, `StoreState`, `EMPTY_STATE`, and the store type).

### `createStore`

```ts
export interface CreateStoreOptions {
  storage: RawStorage;
  now?: () => string;     // default () => new Date().toISOString()
  genId?: () => string;   // default () => crypto.randomUUID()
}

export interface Store {
  getSnapshot(): StoreState;
  subscribe(listener: () => void): () => void;

  createTask(input: { title: string; seed: string | null }): Task;
  getTask(id: string): Task | undefined;
  listTasks(): Task[];
  updateTask(id: string, patch: Partial<Pick<Task, "title" | "seed" | "status">>): Task;

  appendMessage(input: { task_id: string; role: MessageRole; content: string; tool_call?: unknown }): Message;
  listMessages(task_id: string): Message[];   // insertion order

  putCard(card: CardInstance): void;          // upsert by card.id
  getCard(id: string): CardInstance | undefined;
  listCards(task_id: string): CardInstance[];
}
```

Behavior:
- **Construction** loads once via the corrupt-load policy below, holds the result as the current immutable `StoreState`.
- **Snapshot stability:** `getSnapshot()` returns the *same* object reference until a mutation replaces it — required by `useSyncExternalStore` to avoid infinite re-render. Mutators build a brand-new top-level `StoreState` object (new arrays for changed collections); unchanged collections may be reused by reference.
- **Every mutator:** build next state → `StoreState.parse(next)` (validate) → `storage.setItem(STORE_KEY, JSON.stringify(parsed))` → set current = parsed → call every listener. A `parse` failure here **throws** (our bug).
- **`createTask`:** `id = genId()`, `created_at = last_active_at = now()`, `status = "active"`.
- **`updateTask`:** merges `patch`, bumps `last_active_at = now()`; throws if `id` unknown.
- **`appendMessage`:** `id = genId()`, `created_at = now()`, `tool_call` defaults `null`; also bumps the parent task's `last_active_at` if the task exists.
- **`putCard`:** replaces an existing card with the same `id`, else appends (the envelope carries its own timestamps — store does not stamp it).
- **Selectors** (`listMessages`, `listCards`) filter by `task_id`; `getTask`/`getCard` find by `id`.

### Corrupt-load policy (load only)

```
raw = storage.getItem(STORE_KEY)
if raw == null            -> EMPTY_STATE          (silent: normal first run)
try parsed = JSON.parse(raw)  catch -> warn + EMPTY_STATE
result = StoreState.safeParse(parsed)
if !result.success        -> warn + EMPTY_STATE
else                      -> result.data
```

Loading never writes. (Contrast with `registry`'s fail-loud: a corrupt *data* blob with no recovery UI must not brick the demo, whereas a corrupt *registry* is a build-time authoring error.)

### React binding

`useStore(store)` = `useSyncExternalStore(store.subscribe, store.getSnapshot)`. Returns the whole snapshot; components derive what they need in render. Re-rendering all consumers on any write is acceptable at demo scale (a handful of tasks/messages/cards) — no selector memoization this slice (YAGNI).

## Testing (TDD — strong)

Backing store always injected (`makeMemoryStorage()`); `now`/`genId` injected deterministic.

**Contracts (`packages/contracts`):**
- `Task` accepts a valid object; rejects missing `status` / wrong-typed `seed`.
- `Message` accepts valid; rejects bad `role`; accepts `content: ""` and `tool_call: null`.

**Store (`apps/web`):**
- `storage`: `makeMemoryStorage` round-trips; missing key returns `null`.
- `createTask`/`getTask`/`listTasks`: created task has injected id/time, `status:"active"`; round-trips through list/get.
- `updateTask`: applies patch, bumps `last_active_at`; throws on unknown id.
- `appendMessage`/`listMessages`: messages returned in insertion order, filtered by `task_id`; `tool_call` defaults `null`; parent task `last_active_at` bumped.
- `putCard`/`getCard`/`listCards`: upsert by id (second put with same id replaces, does not duplicate); filtered by `task_id`.
- **Persistence round-trip ("刷新不丢"):** mutate via store A, construct a *fresh* store B over the same `RawStorage`, assert B reads the data back.
- **Reactivity:** `subscribe` listener fires on each mutation; `getSnapshot()` reference changes after a write, is stable across reads with no write between.
- **Load policy:** missing → `EMPTY_STATE`, no warn; non-JSON raw → `EMPTY_STATE` + warn; JSON-but-schema-invalid → `EMPTY_STATE` + warn. (Spy on `console.warn`.)

**Hook (`apps/web`, RTL + jsdom):**
- A component rendering `useStore(store).tasks.length` re-renders (count updates) after `store.createTask(...)`.

## Global constraints (carried into every task)

- **Acceptance gate:** `pnpm -r typecheck` + `pnpm -r test` both green. `vite build`/`vitest` use esbuild and do **not** typecheck — only `tsc --noEmit` (`pnpm -r typecheck`) does. Run `pnpm --filter @mind-imprint/contracts typecheck` and `pnpm --filter web typecheck` per task.
- **No backend, no key in git, no logging of secrets** (§0.1). The store holds task/message/card data only — **never** the LLM key (that's `mk.llmConfig`, a separate S2 namespace).
- **Contract = single source of truth.** Types are inferred from Zod, never hand-duplicated. Reads `safeParse`/`parse`, never `as`.
- **Standard envelope `CardInstance` is unchanged** — the store persists it as-is and does not stamp its timestamps.
- **Injectable `now`/`genId`** for determinism (same pattern as `envelopeReducer`).
