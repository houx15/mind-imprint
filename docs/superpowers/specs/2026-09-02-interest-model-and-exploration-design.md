## 2 · 三个模型

### 2.1 兴趣关键词模型（自下而上，每个学生一份）

这就是树。**它做的断言很强，必须挣得到：树上每一个词，都来自她真的做过的一件事。**
所以关键词永远和它的来源一起存，来源里带**她自己的那句话**。

```
interest_keyword   一个词           id · user_id · text_zh/en · field · strength(1..5) · note · first_seen_at
keyword_source     它从哪来（多条）  keyword_id · kind(reading|writing|project|news|quiz) · ref_id · evidence · happened_at
```

- `strength` 是**读数**，由**不同来源的条数**推出来（1 源=1，2=2，3-4=3，5-7=4，8+=5），不手填。
- `evidence` 为空的来源**不入库**。没有原话的词是装饰，抽屉里也没东西可给她看。
- 去重：新词先做归一化（去空格/标点、简繁、大小写）再和她已有的词比；命中就**加一条来源、提一档强度**，不新建。

### 2.2 学科领域模型（自上而下，全校共用一份）

**它是内容，不是用户数据，所以它是 `packages/contracts` 里一份带版本的 JSON**，
前端构建期 import，Go `go:embed` 同一批文件——和卡 JSON 完全一样的办法。
只有**边**（她的词 → 学科）进 Postgres。

```ts
interface Discipline {
  id: "statistical-inference";
  field: FieldId;                       // 挂在树的哪根主枝上
  zh: "统计推断";  en: "Statistical inference";
  asks:     "一个样本，能说多少话？";          // 它研究什么（一句问题，不是定义）
  method:   "抽样 · 置信区间 · 显著性检验";     // 它的核心方法
  exemplar: "4 平方公里的珊瑚，能不能代表一片海？"; // 一个典型问题
  aliases:  ["统计", "抽样", "代表性", "sampling", "significance"];
  syllabus: SyllabusRef[];              // ← 投影层，可以为空
}
interface SyllabusRef {
  board: "IB" | "ALevel" | "AP" | "IGCSE" | "University";
  code:  string;   // "MAA-HL-4.11" | "9709-S1" | "AP-Stats-Unit-4"
  label: string;   // "IB 数学 AA HL · 统计与概率"
  level?: string;  // HL/SL · AS/A2
}
```

**为什么「学科为骨、课程为投影」是对的兼容办法**（这是产品负责人问的那个问题的答案）：

1. **考试局会改考纲，学科不会。** 2027 年 IB 改一次大纲，是改一个数组，不是重做分类学——
   关键的是**她的关键词不动**，因为它当初连的是「统计推断」，从来不是 `MAA-HL-4.11`。
2. **一棵树服务所有学生。** 她的档案里带自己的体系；学科卡先显示她那一行，其余折到
   「其他课程体系」下面。读 A-Level 的和读 IB 的看的是同一张图。
3. **`syllabus: []` 是合法且有意义的。**「这门学科高中不教」是真话，而且对一个讲探索的
   产品来说是**有吸引力的**真话。绑死某一个考试局的分类学根本表达不了这件事。
4. **以后加 AP 是加数据，不是改结构。** 不用迁移，不用重新映射。

**主枝从六根加到七根（已决定，P2 之前都可以推翻）。** 现在的六根里**没有数学**——
对一个服务 IB / A-Level / AP 的产品这是硬缺口：统计推断、微积分、逻辑、离散数学
都没有家。加 **`formal`「数学与形式」**（数学 · 统计 · 逻辑 · 计算理论）。

代价是 `BRANCH_CURVES` 多一条贝塞尔并重排角度，而 **P2 本来就要重写布局，
所以这一刀现在切最便宜。** 若产品负责人要保持六根：`formal` 并进「科学与自然」，
P1 阶段只是 42 条数据里改一个字段，P2 阶段是一次几何改动——**P2 落地之前都是
可逆的**，所以 P1 不为这条等。

**首批范围（诚实说明）：** 七根主枝 × 6 门 = **42 门**先做完整（含双语、方法、
典型问题、别名、四大考试局对应）。42 门足以让整条链路端到端跑通，也是一次评审
看得完的量。扩到 ~80 门是 P5 之后的内容工作，不阻塞任何代码。

### 2.3 路由（那根线）

```
keyword_discipline   keyword_id · discipline_id · confidence(0..1) · how(alias|cooccur|llm|student) · rationale
```

**三档，先便宜后贵，「需要的时候」才调模型：**

| 档 | 怎么判 | 成本 | 置信 |
|---|---|---|---|
| T1 **别名命中** | 归一化后的词 / 她的原话命中某门学科的 `aliases` | 0 | 1.0，`how="alias"` |
| T2 **共现继承** | 这个新词和某个**已路由**的词共享 ≥2 条来源 → 继承它的学科作候选 | 0 | 0.6，`how="cooccur"` |
| T3 **模型判定** | T1+T2 都没过阈值时，才发一次旗舰调用 | 1 次/未命中词 | 模型给，`how="llm"` |
| — | **她自己改**（抽屉里「这个词其实是…」）永远覆盖以上全部 | 0 | 1.0，`how="student"` |

**T3 的 prompt 只带同一根主枝下的候选（约 6 门），不带全部 42 门。** 输入是这个词
＋她的原话；输出是 1-2 个 `discipline_id` 加一句理由。候选表小，prompt 就小，
判错了也只在一根枝的范围内错。

**路由成本是 O(新词)，不是 O(活动)。** 一个词路由一次就永久缓存。500 人的学校、
每人每周 5 个新词 = 2500 次路由，其中约 30% 落到 T3 ≈ 750 次旗舰调用/周。可以忽略。

**路由是双向的，三个用法：**
- 词 → 学科：在树上给她的兴趣一个学术名字（P2）
- 学科 → 词：这门学科下面她已经有哪些词（P2 抽屉）
- 学科 → 空：她最强那根枝旁边、**一个词都没有**的学科 = 「你的树上还没有这根枝」（P5）

## 3 · 采集器：关键词从哪来

**只在真的完成了一件事时触发，绝不定时跑。**

| 触发点 | 已存在的位置 | 喂给采集器什么 |
|---|---|---|
| 阅读完成 | 有 `reading_takeaway` 行时 | 标题 + 她的收获 + 她用透镜挑出的句子 |
| 写作完成 | `writing` 定稿 | 标题 + 她用的结构 + 她自己的正文 |
| 项目进入复盘 | `pbl_project` 转 `lookback` | 立题 + 她做过的决定与理由 |
| 地图上「先收藏」 | P4 | 该条新闻自带的 `keywords` |
| 兴趣测试完成 | P3 | 兴趣锚点 + 她写的「为什么」 |

一次完成 = **一次模型调用**，返回 1-3 个关键词，每个必须带**她自己的一句话**作证据；
没带证据的丢掉。产出走 §2.1 的合并规则，然后立刻过 §2.3 的路由。

⚠️ 这里没有 JSON schema 强约束（`apps/api` 现在的办法是 prompt 要求 JSON + 容错解析器，
见 `internal/api/reading_questions.go:130`）。采集器沿用同一个办法，**解析失败就
不长词并把错误记下来**——绝不编一个像样的词出来（[[ai-errors-must-surface-never-fake]]）。

## 4 · 五期

### P1 · 双模型 + 路由地基（纯后端）
- `packages/contracts/disciplines/` —— 42 门的 JSON + Zod 契约 + 构建期校验器
  （field 必须是七根之一；同一考试局内 code 唯一；别名跨学科唯一）。
- 迁移 `0116_interest_model.sql`：`interest_keyword` / `keyword_source` / `keyword_discipline`。
- `internal/interest/` —— 纯领域逻辑：`Router`（T1/T2/T3）· `Harvest`（prompt + 解析）·
  `Merge`（归一化与去重）。**不碰 DB**，照抄 `internal/pbl` 的分层。
- `internal/api/interest_*.go` —— HTTP + sqlc 胶水，`liteOnly` 中间件。
- 三个采集触发点接上。
- `GET /api/v1/interest/tree` —— 她的词 + 来源 + 已路由学科 + 按主枝的汇总。
- 测试：路由三档各自的边界、合并去重、分类学校验器、采集解析容错。

### P2 · 兴趣树接真数据（前端）
- 树读 `GET /interest/tree`。
- **布局要算出来**：原型里 `at.{t,spread}` 是手摆的。真关键词必须由
  `hash(keyword_id) + strength` 决定性地算位置——同一个词每次刷新落在同一个地方，
  否则「这张图就是你的模型」这句话立刻不成立。
- 抽屉加「学科」一行（她的体系在前，其余折叠）；`继续深挖` 由 P1 的路由生成。
- 空树 → P3 的邀请。

### P3 · 觉醒协议 · 兴趣测试
- 独立路由、独立的深色科幻底（参考 `docs/reference/explore_interest.html`）。
- 六屏：建立连接 → 世界的暗面 → 选导航员 → 兴趣锚点 → 兴趣钩子/学科透镜 → 反方压力测试 → 结果。
- **结果写回 §2.1 同一条路**（`kind="quiz"`），树从此不为空。过程即数据（铁律④）。
- 第一次打开树时自动邀请；可重做，**重做是「再长几个词」，不是清空重来**。

### P4 · 探索地图接真新闻
- 每天一批、每校一份：抓取 → 政治/冲突**入库前**过滤 → 去重 → 打分取前五 →
  一次模型调用出双语文案 + 钩子问题 + keywords → 落库。
- 每条经同一个 Router 归到一门学科。
- ⚠️ **P4 第一个任务是探源可达性**：Nature / Science / NASA / ESA / WHO / IEA 的 RSS
  在北京的 ECS 上能不能拉到。拉不到，整期的选型就得换，先测再设计。

### P5 · Hooks（两屏上的动机出口）
- 树上：「你的树上还没有这根枝」——她最强主枝旁边零关键词的学科，配一个具体的第一步。
- `继续深挖` 四颗气泡（想一想 / 去读 / 去写 / 去做），每个关键词各不相同。
- 地图上：先收藏 → 阅读室「待读」置顶；与 AI 讨论；阅读。

## 5 · 边界与不做

- **`/eco` 原型不动。** P2 在 lite 的真路由上另建，原型留作对照，等 P5 落地后由
  产品负责人决定删不删。（[[lite-must-not-break-pro]]：只碰 lite 自己的文件，
  新迁移从 `0116` 起，绝不新建已存在的文件。）
- **不做**：学科图的可视化浏览界面（探索地图保持新闻星图）· 嵌入向量检索
  （42 门用别名表就够，上向量是没必要的复杂度）· 跨学生的兴趣比较或排名。
- **密钥**只在 `apps/api`；采集与路由的每一次调用都记 `llm_call`（surface="lite"）。
