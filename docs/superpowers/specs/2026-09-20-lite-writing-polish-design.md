## 0 · 十条意见，以及它们真正的根

同事给了十条。代码里查下来，它们收敛到**四个根**：

| # | 同事的原话（摘） | 根 |
|---|---|---|
| 1 | 论点被拖入到子论点后就没法拖出来 | A · 图只能往深里挂 |
| 2 | 思维导图的生成逻辑有点问题，部分论据的标题不规范 | B · 图没有骨架 |
| 3 | 这个是总结，不是分论点 | B · 图没有骨架 |
| 4 | 需要增加一个对于行文方式的思考和梳理部分 | D · 缺一步 |
| 5 | 分段写作要组织段落内文本结构；保留思维导图；几种写法不规范 | D · 缺一步 + 方法库 |
| 6 | 深入一层没有针对当前段落进行指导 | C · 段落级调用看不见整篇 |
| 7 | 建议太吹毛求疵、模板化、每次刷新变成新的 | C（模板化）+ 独立（刷新覆盖） |
| 8 | 被禁止的交互回应太生硬 | 独立 |
| 9 | 分析第一段时不知道例子写在第二、三段，也不知道开头只是引子 | C · 段落级调用看不见整篇 |
| 10 | 请印记看一看：分级反馈、排除后文已承接、取消优点+不足模板… | C · 段落级调用看不见整篇 |

四个根：

- **A** —— `useMindMapDrag` 只调用过 `onMove(id, over, "child")`。
  `outlineMove.ts` 里的 `"after"`（兄弟）模式**没有任何调用点**，
  落在空白处是空操作。所以每一次拖动只能往深里挂一层，挂进去就出不来。
- **B** —— 图没有骨架。模型自己挑 `parentId`、自己用散文写 `role`，
  下游（`slots.ts` / `writing_blocks.go` / `writingGuideAppliesTo` /
  `rootInsertPosition`）再拿关键词把意思猜回来。截图里那个 `结尾` 挂在
  `中心论点` 底下（深度 1），而 `slots.ts` 只在 `o.depth === 0` 时认结尾，
  于是它落进最后那个 `else`，印成 **「分论点 3」**。标题错是摆放错的下游。
- **C** —— 段落级的每一次模型调用都只看得见这一段。
  `buildWritingCommentPrompt(wr, label, text)` 拿到的全部上下文是：题目、
  语言、目标字数、方法表、**这一段的正文**。没有提纲、没有别的段落写了什么、
  没有这一段的角色、没有它自己上一次的意见。所以「开头只是引子」和
  「例子在第二、三段」在结构上不可知，它对着它看得见的那点东西作出的判断
  是对的，作出的结论是错的。
- **D** —— 没有「行文」这一步，方法库把论证**结构**和论证**方法**混在一格里。

## 1 · 分三轮

每一轮是**一个机制**，各自可独立上线、独立走查。

| 轮 | 意见 | 这一轮建的那个机制 |
|---|---|---|
| R1 | 1、2、3、7、8 | 图的骨架（`kind` 闭表）+ 拖得出来 + 引导不再被覆盖 |
| R2 | 6、9、10 | **整篇上下文块**，段落级的每一次调用都吃它 |
| R3 | 4、5 | 行文这一步 + 方法库规范化 + 段落页保留思维导图 |

顺序是有依赖的，不是偏好：**R2 的「识别当前段落作用」要求角色可靠**，
而角色可靠正是 R1 建的东西。R3 的段落内结构引导要用规范化之后的方法表。

### 与 `docs/2026-08-09-all-statuses.md` 的一致性

那份文档写的是 pro 的「写作项目」流程（立题／管理／阅读／写作／回顾），
lite 这个房间（结构／段落／成稿）不是它描述的那条流程。仍然逐条对过，
结论是**支持，不冲突**，并且它补了两条本设计该吸收的要求：

- §6 statement complete：「for each claim, we need evidence, analysis,
  **limitation**, how it **correlates with others**」——
  R2 的正文段检查表据此加入「限制」和「与其他段的关系」两项。
- §6：「then guide students to write a paragraph that describes the full
  论证结构」—— R3 的行文这一步与之对应。

## 2 · R1 · 图有一副骨架（意见 2、3）

### 2.1 `kind`：一张闭表，深度由它算出来

迁移 **0182** 给 `writing_outline` 加一列 `kind text not null default ''`。
`role` 保留，只作老行的兜底显示。

| kind | 深度（强制） | 父（强制） | 屏幕上的标题 |
|---|---|---|---|
| `opening` | 0 | —（排在最前） | 开篇 |
| `thesis` | 0 | — | 中心论点 |
| `point` | 1 | 中心论点 | 分论点 |
| `evidence` | 2 | 前面最近的 `point` | 论据 · 你见过的事 ／ 论据 · 你找来的材料 |
| `counter` | 1 | 中心论点 | 反方观点 |
| `rebuttal` | 2 | 前面最近的 `counter` | 对反方的回应 |
| `gap` | 2 | 前面最近的 `point` | 待补的材料 |
| `closing` | 0 | —（排在最后） | 结尾 |

这副骨架就是同事那张参考图（`中心论点 → 分论点1..n → 论据1..2`，
外加 `开篇 → 论证 → 结尾` 那一行）。

**模型返回 `kind`，不再返回 `parentId`，不再自己写 `role` 散文。**
`insertPlanNode` 从 `kind` 算出深度和父节点。于是「结尾挂在中心论点底下」
这个摆法**不再可表示**，而不是摆错之后被纠正。意见 3 在结构上消失。

`论据` 的两个后缀由 `source` 定：非空 = 她找回来的材料，空 = 她自己见过的事。
这既满足「论据的标题要规范」，也保住了那条区分本身（它承重：
下一轮印记正是照着 `source` 去查这份材料）。

标题是名词，用的是语文课上的正式词（AGENTS.md 界面文案规则 1、6）。

### 2.2 顺带修掉的一个真 bug

`writingPlanShapeOf` 只按深度数材料。截图里那个「暂时还没找到的材料」
是深度 2，于是**它被当成一条真材料计入 `Material`**，可以把
`ready()` 推过线，而她手上一条材料都没有。`gap` 不计入。

### 2.3 老行怎么办

0182 用今天已经存在的那几张关键词表（`writingOpeningRoleWords` /
`writingClosingRoleWords` / `writingExampleRoleWords`）把 `role` 映射成 `kind`，
按深度兜底：深度 0 无匹配 → `thesis`，深度 1 → `point`，深度 ≥2 → `evidence`。
**一行都不丢，一行都不移动位置。** 老行的深度保持原样（迁移只写 `kind`，
不重排），避免一次迁移把已经在写的稿子的卡片顺序换掉。
新的深度强制只作用于**此后新增和她拖动的节点**。

### 2.4 下游

`slots.ts`、`writing_blocks.go`、`writingGuideAppliesTo`、`rootInsertPosition`
改读 `kind`，四处的关键词猜测整段删除。两份卡片派生（TS 与 Go）仍然逐条一致，
`slots.test.ts` 与 `writing_blocks_internal_test.go` 各加一条
「结尾在深度 1」的回归用例。

## 3 · R1 · 拖得出来（意见 1）

`useMindMapDrag` 补上缺的那一半：

- **落在空白画布上** → 升到最上层（今天：静默无事发生）。
- **悬在卡片上三分之一** → 「放到它旁边」（`"after"`，那个一直没人调用的模式）；
  **中段／下三分之一** → 「放到它底下」（`"child"`）。
  被悬停的那张卡要**在她松手之前**显示将发生的是哪一种。
- 挪完之后 `kind` 与新位置不符的，**改写 `kind`**（把一条论据拖到最上层，
  它变成分论点，标题当场变）。2.1 的不变量对她的手动编辑同样成立，
  而且她看得见自己刚才做成了什么。

`outlineMove.ts` 是纯函数、已有测试，新增的 promote / sibling 两类用例照旧写在那里。

## 4 · R1 · 引导不再被覆盖（意见 7 的一半）

今天 `guideWritingBlock` 调 `SetWritingOutlineGuide`，旧的那份直接没了。
这就是「每一次刷新就会变成新的东西」。

- 按钮改名 **「换一组问题」**；存的结构变成 `{current, previous}`，
  引导框上给一个「看上一组」。她读过的东西不消失。
- 重新生成时把上一组问题喂回去，要求**换一个角度看同一块**，不是重抽一次。
- **模板化那一半**：`writingGuideQuestionRules` 改写 —— 举例是若干条路之一，
  `道理论证` 是一条正当的路，不得要求每一处分析后面都跟一个例子。
  并套用这个房间已有的那条反馈优先级（`writing_comment` 的「只说最上面那一层」）：
  **这一块非空时最多两个问题。**

## 5 · R1 · 被禁止的请求要说出那句话（意见 8）

服务端识别「帮我找／帮我搜／你写吧／懒得…」这一类请求，作为**一次性**的段落
注入 plan / turn / deepen 三处提示词（一次性，不做常驻 —— 常驻提示会把该做的
事挤掉，2026-09-05 的教训）。这一轮的回复要做三件事：

1. 一句话说明：印记不替你搜索，也不替你写正文；
2. 说它**会**做的那件事：说清这一条该找什么样的材料；
3. 然后往下走。不说教，下一轮不再提。

**做成可验的，不是只在散文里要求**（提示词里的「必须」是模型可以推翻的「必须」）：
检测命中时，校验回复里是否含有那句说明，缺了就重试一次。

## 6 · R2 · 整篇上下文块（意见 6、9、10）

### 6.1 一个新函数，三处调用点共用

```
buildWritingPieceContext(wr, outline, snippets, comments, thisBlock) string
```

内容：

- **这一块**：`kind`、它的职责、她给它定的要点；
- **别的每一块，按文章顺序**，各自的 `kind` 和**她在那里实际写下的内容**；
- 已写 / 目标字数；
- 教师布置的要求（`assigned_prompt`）；
- **这一块之前收到过的意见**，以及每一条她做到了没有
  （`writing_comment.SourceText` 逐字比对，0147 已经支持）。

调用点：`commentOnSnippet`、`buildDeepenBrief`、`buildWritingGuidePrompt`。
三处都已经在函数里拿到了 `at.ID`，加载提纲和片段不需要新的路由或新的查询形状。

这一个块同时解掉意见 9（开头只是引子、例子在第二三段）和意见 6
（深入一层飘到下一块去）。

### 6.2 输出契约改成同事写的那个形状

`verdict` ∈ `pass` ｜ `polish` ｜ `revise` 打头，然后是必要原因，然后是下一步动作。

- `pass` → 可以进下一段；
- `polish` → **不阻塞写作**；
- `revise` → 必须指出具体文本、它造成的影响、以及做到什么算完成。

每轮只处理一个实质问题（`writingBlockCommentMaxIssues = 1` 已经是这样）。

**取消固定的「优点＋不足」模板**：`good` 由「必填且排第一」改成**可选**。
确实有一处用对了就点出来，没有就不点，不再为了凑模板去找一条。
（原来那条「先说一条 good」有它的道理——具体的肯定本身是一次教学——
所以保留能力，取消强制。）

### 6.3 两项减法，服务端做，不写在提示词里

- 一条意见的 symptom **已经被后面某一块的正文满足**的，渲染之前丢掉
  （同事的「排除后文已承接」）；
- 与这一块之前某条意见重复、而她已经改过的，丢掉（`SourceText` 差异已有）。

### 6.4 按段落角色分派检查表

| kind | 查什么 |
|---|---|
| `opening` | 观点与题意是否对上。**不要求开头自带完整事例。** |
| `point` | 理由、证据、解释三者的关联；限制；与其他段的关系（§6 statement complete） |
| `counter` / `rebuttal` | 回应是否针对反方说的那一点 |
| `closing` | 是否收束全文 |

不把例子、解释、让步机械拆成独立分论点。
全文重复与理由是否充分，结合整篇判断。

### 6.5 卡住时换一种帮法

连续两轮没有新增信息 → 改用选项、句式或简短示范。
判据数轮数，不靠模型感觉——`writingPlanStalled` 已经是这个形状，复用它。

### 6.6 材料要求跟着任务走

两处要改，因为**同事说的那个 500 字的例子是写死的，不是提示词漂移**：

- `writingPlanNeedOf` 今天无论多长都至少 2 条分论点 + 1 条材料；
- plan 提示词另外写着：人群／趋势／政策／因果类话题**必须**有「她找来的材料」。

改成：材料要求跟着目标篇幅和教师要求走；**仅在教师要求或论证确有缺口时**
才引导检索。这一处放宽了 2026-09-12 刚收紧的一道闸，是有意的，
理由是同事给的那条验收标准（500 字任务不默认强制多条理由和调查数据）。

### 6.7 不许编

区分她确认过的事实与 AI 的建议；不补造经历、数据、引用。
这一条今天已经由 `validateCommentPoints` 的逐字引文校验守着一半
（引文编不出来），另一半（`text` / `action` 里编一份数据）沿用
`writing_plan.go` 已有的那条禁令，并入 6.1 的上下文块一并说明。

### 6.8 对话与卡片同步

她在对话里改了立场、改了某条分论点的名字或顺序，卡片要跟着变。
R1 的 `kind` 让这件事可判：卡片是从提纲派生的，提纲变了卡片就变；
需要补的是**完成状态**（`pass` 之后那张卡标「已完成」）。

## 7 · R3 · 行文这一步（意见 4）＋ 方法库（意见 5）

> **实现之后的订正（2026-09-20）。** 建的时候和下面这份设计有两处不一样，
> 都是动手才看见的：
>
> 1. **方法库没有「拆成两张表」，而是加了一层。** 原计划写「把并列论证 /
>    递进论证挪到论证结构」—— 做不得：`TestWritingPlanSystem_NamesOnlyRealMethods`
>    逐字钉着提示词散文里引的每一个名字，而且显式要求「并列论证」存在。
>    改成**只增不改**：现有条目补一个 `category` 字段，另加四条论证方法
>    （引用 / 比喻 / 类比 / 归谬）和四条论证结构（总分式 / 并列式 / 层进式 /
>    对照式，`applies_to: "whole"`）。顺带把 `point_causal` 的正式名称从
>    「因果」补成「因果论证」—— 查过没有任何提示词引它。
>    🚨 `point_parallel`（并列论证）和 `struct_parallel`（并列式）不是重复：
>    前者说一段里几条理由并排，后者说整篇的分论点地位相同。教辅里也分两层。
>
> 2. **行文这一步不新建表。** 它就是那张结构图换一种用法：顺序用已有的
>    `position`，每块的方法进 `writing_outline.method`，整篇的结构进
>    `writing.structure_key`（那一列自模板选择器被删之后就没人写过）。
>    🚨 0184 还必须放开 0099 写在列定义上的 `CHECK (stage IN …)` ——
>    只改 Go 的枚举，她第一次保存就撞一个数据库层的冲突。

### 7.1 第四步

`结构 → 行文 → 段落 → 成稿`。`writing.stage` 加一个取值 `flow`，
`StageMap` 加一格。**仍然是地图不是关卡**（`writing_stage.go` 的既有裁定：
往前往后跳都是 200）。

这一步是一块**能用手摆的板**（AGENTS.md 铁律②、[[interaction-means-a-board]]）：
排分论点的顺序、定整篇的论证结构（总分式／并列式／层进式／对照式）、
定开篇怎么开、结尾怎么落、给每条分论点标上它要用的论证方法。
**不写正文内容**——同事的原话是「并非填充内容」。

### 7.2 方法库规范化

今天 `methods.json` 把论证**结构**（并列论证、递进论证 —— 其实是并列式、层进式）
和论证**方法**混在同一格里，并且缺了引用论证、比喻论证、类比论证、归谬论证。
照同事给的那两页教辅拆成两张表：

- **论证结构**（总分式／并列式／层进式／对照式）→ 行文这一步用；
- **论证方法**（举例／引用／对比／比喻／因果／类比／归谬）→ 段落这一步用。

`vocab.Method` 加一个 `layer` 字段区分两者。
**改这张表之前要对一遍提示词散文里逐字出现的每一个方法名**
（`writing_plan.go` 顶上那条 🔑 注释），否则提示词会在同一口气里教模型造词。

### 7.3 段落页

- 左栏顶部放思维导图缩略图，当前这张卡高亮，点开放大（同事截图里的红箭头指这里）；
  引导整体下移。左栏本来就能折起，不占正文宽度。
- 引导框的「常见的几种写法」改成**段落内结构**：分论点句 → 论据 → 分析 → 回扣。
  依据是同事那页教辅的「分析段内层次」。
