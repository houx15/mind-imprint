# 印记 · 智能写作工作室（Agentic Writing Studio）设计 spec

> 日期：2026-08-07 · 状态：设计定稿（待用户复核）
> 上游权威：`AGENTS.md`（四条铁律）、`docs/思维印记_Demo_PRD.md`、`docs/superpowers/specs/2026-08-06-design-system-design.md`（设计系统）。
> 关联记忆：multi-agent 架构方向（一条连续的印记 + 脊梁）、backend platform 架构。

## 0. 一句话

把当前「四个房间的 tab 切换」重构成 **一条 AI 引导的连续线索 + 一根贯穿项目的「项目计划」脊梁**：左侧常驻「印记」对话（可翻转左右），右侧「交互区」由 AI 与切换器共同驱动、按阶段变形；提案要点与项目计划都由 **AI 起草 → 学生确认** 而来，成为写作时随手可见的参考与被 AI 引导的路线。

本次是对 **既有能力的重新编排 + 升级**，不是从零重建。绝大多数数据与房间已存在（见 §9）。

## 1. 北极星与铁律对齐

- **AI drives, you can override（已定）**：AI 主动为你打开下一个视图，但交互区左上角**常驻切换器**始终可跳到任意视图并跳回。驱动是**引导性的、可撤销的**，不是强制——不违背铁律②「不操纵」，也守住用户北极星「平台清楚、我始终知道怎么交互」。
- **提案要点、项目计划均遵循「AI 起草候选 → 学生确认/编辑 → 落库」**：等同工具卡契约「触发自动、打开/入库由学生确认」。AI 从**你说过的话**里提炼候选，你确认后它才成为你的——AI 绝不代定论、绝不代写正文（铁律①）。
- **一次一问**：对话短、不啰嗦（铁律③）。
- **过程即数据**：跳过、让 AI 直接答、拖动视图，都被记录（铁律④）。

## 2. 外壳布局（interactive parts shell）

两块互相独立：

1. **印记 chat**：常驻 bar，可翻转左右，默认左。**复用现有 `AiPanel`**（已支持 flip / collapse / portal 契约）。
2. **交互区（interactive parts）**：印记之外的整块区域，内容由 **AI + 切换器** 共同决定，按阶段**变形**：
   - 立题聊阶段：交互区 = 宽对话承载区 + 一条**灰色 next-steps 状态条**（提案→读文献→写作→复盘，全灰待亮）。
   - 单面板阶段：阅读室 / 探索图谱 / 项目计划文档，各自占满交互区。
   - **写作阶段：交互区分裂为两个「可拖拽相对宽度」的子面板**——左 = 参考（`提案要点 / 阅读笔记 / 批注` 三 tab），右 = 写作区。
3. **切换器**：交互区**左上角常驻**，暴露当前脊梁的各阶段视图；高亮「你在这一步」。这是「AI 驱动」的兜底安全网。

```
┌────────┬──────────────────────────────────────────────┐
│ 印记    │ [切换器: 计划·写提案·阅读室·…]  ← 常驻左上角      │
│ chat   │ ┌───────────────┬ ⟷ ────────────────────────┐ │
│ bar    │ │ 提案要点/阅读   │  写作区                    │ │
│ 翻转    │ │ 笔记/批注 tabs │  [textarea + Markdown 预览] │ │
│ 默认左  │ │ (参考子面板)   │  选中文字 → 问印记          │ │
│        │ │               │  可拖拽分隔线               │ │
└────────┴─┴───────────────┴────────────────────────────┴─┘
   交互区按阶段变形：宽对话 · 单面板(阅读/计划) · 两栏(写作)
```

## 3. 脊梁：项目计划（living plan）

- 每个项目**一条**贯穿始终的 plan。AI 从提案要点**起草** → 学生**确认/编辑** → 成为脊梁。
- 顺序阶段（写提案 → 读文献 → 写作 → 打磨 → 复盘 → 答辩准备…），覆盖「读—写—回顾」完整节奏。可**随时 revisit / 编辑**。
- **驱动两件事**：① 印记的阶段引导（「下一步该写提案了」）；② 交互区切换器的「你在这一步」高亮。
- **全文写作阶段：同一条 plan 生长**，不新建第二条——一个项目一条脊梁（对齐「一条连续的印记 per project」）。
- 数据基础复用 `plan/generate`（现已产出 5–9 任务、~18 天时间线的 plan_items）；升级点 = 从「甘特看板」变为「驱动引导与切换器的脊梁」，并接上「AI 起草→确认」的确认闸。

## 4. 提案要点 notes

- **固定 section 集（先固定、后适应）**：`研究问题/目标` · `动机与意义` · `活动计划` · `资源与文献` · `可能的反例/张力`。
  - 前四项与现有 `putProposal` 的 `目标/缘由/活动/资源` 近乎 1:1；第五项为新增（对齐验收主动脉里的「撞反例 / 让步段」）。
- **捕获（铁律①的关键）**：当你在对话里说到某段属于某个 section 的想法，AI **提出候选 note**（「要不要把这条记进『目标』？…」），**你确认/编辑后才落库**。等同工具卡「入库由学生确认」。
- **挑战**：AI 会在恰当时刻挑战——尤其 `目标`（好研究问题的定义：可回答、有范围、非是非题）与 `活动计划`（易遗漏项：写提案、读文献、写作、打磨、复盘、答辩准备）。挑战是**引导性的一次一问**，不阻断。
- **喂给写作**：写作阶段左参考面板的第一个 tab 常显提案要点，随手可见。

## 5. Agentic 流转（决策层 + 阶段闸）

- **决策层**（服务端，扩展现有 summon_card 决策接缝）每轮在**一次一问**的前提下决定：留在对话 / 提出候选 note / 发起挑战 / 提议「生成项目计划」/ 打开阅读室或探索图谱 / 推进脊梁到下一步。视图/阶段意图与 `summon_card` 一样，走**单函数接线**，前端据此变形交互区。
- **AI 的视图切换是引导性的**：切换发生时给出可见理由（「我先带你去写提案，随时能切回」），学生可用切换器**撤销 / 切走**。
- **阶段闸（何时提议进下一阶段）——本 spec 决策**：
  - **提案 → 生成计划（前置条件：四项必填 section 全部完成）**：`研究问题/目标`、`动机与意义`、`活动计划`、`资源与文献` 四项**各有已确认内容**后，方可生成项目计划——计划正是从这四项生成，缺一不可；四项齐全前，`生成计划` 既不 offer、也不可手动触发。
  - 四项齐全 → 印记 **offer**「要不要生成项目计划？」，学生也可此时**手动**触发。**offer 不自动跳转**；生成前学生可继续补要点。
  - 印记会就 `目标` 与 `计划` 发起挑战（引导性、一次一问），但挑战**不作为额外闸**——只有「四项完成」这一条前置。
  - `可能的反例/张力` 为第五 section：鼓励但**非必填、不作闸**（写作撞到反例时 AI 也会再提）。
- 阈值（「最小完整度」）保持**透明、可解释**，不做隐形评分门槛。

## 6. 写作阶段

- **两栏可拖拽**：左参考 tabs（提案要点 / 阅读笔记 / 批注）| 右写作区。**复用现有写作房间**：textarea + Markdown 预览 + 自动存草稿 + 选中问印记。
- **全文写作的多状态**：起草 / 整稿体检 / 分段打磨——**复用现有 WA（整稿体检）/ WB（完成并导出）/ WC（就这一段）**，作为写作区内的状态，不新造机制。
- 硬约束不变：**AI 绝不代写正文**（只陪想、查论证与结构、一次一问）；**不做花哨排版编辑器**；**不代学生向学校提交**。成品可导出（.docx）带走；过程树只读。

## 7. 找材料（reading entry from writing）

- 写作中需要材料 → 与印记说 → AI 依据你**有没有具体材料**打开对的入口：
  - 手上有某篇论文/链接 → **阅读室**（逐句共读）。
  - 只有关键词 / 方向 → **探索图谱（兔子洞地图）**。
- **全部复用现有阅读室与探索图谱**（含本轮修好的 422 粘贴回退）。产出的阅读笔记回到写作阶段的「阅读笔记」tab 可见。

## 8. 批注（review）

- **先（本轮范围）**：写完后印记做整稿体检，comments 落到写作阶段左参考面板的 **`批注` tab**（概览级：结构/论证/清晰度的建议）。
- **后（deferred）**：`批注原文`——把批注**内联锚定**到具体段落/句子（类似阅读室的 hang-card-on-sentence）。

## 9. 复用 vs 新建（落到现有代码）

**复用（已存在）：**
- `AiPanel`（翻转/折叠/portal 契约）— `apps/web/src/studio/ai/`
- 写作房间三态 WA/WB/WC、导出 — `apps/web/src/workspace/blocks/WritingBlock.tsx`
- 阅读室 + 探索图谱 — `apps/web/src/studio/reading/`、`.../blocks/exploration/`
- 提案四维 CRUD — `apps/api/internal/api/workspace_plan.go`（`putProposal`）
- 计划生成 — `apps/api/internal/api/workspace_plan_generate.go`（`plan/generate`）
- 卡片契约、决策层 summon_card 接缝、连续会话（migration 0038）、对话摘要（0041）

**新建：**
- **交互区 morphing shell**：按阶段变形 + 两栏可拖拽 + 常驻切换器（前端）。
- **提案要点**：第五 section（反例/张力）；「AI 从对话提炼候选 → 确认」的落库路径与前端确认卡片；写作时的参考面板呈现。
- **计划脊梁**：`AI 起草→确认` 的确认闸；plan 驱动「引导 + 切换器高亮」；plan 生长到全文的语义。
- **决策层的视图/阶段意图**：在现有 turn loop / summon_card 接缝上新增「打开视图 / 推进阶段」的引导性意图 + 可撤销。

## 10. 分期（每期一份独立 spec→plan→build，均为可用切片）

1. **P1 · 外壳**：交互区 morphing shell + 常驻切换器 + 写作两栏可拖拽 + 印记翻转（复用）。既有房间塞进新壳。**终态 = 今天的全部能力 + 新导航**（纯前端为主）。
2. **P2 · 提案要点**：AI 从对话提炼候选 → 学生确认；固定 sections（含反例/张力）；挑战闭环；喂写作。
3. **P3 · 计划脊梁**：AI 起草 → 确认；驱动切换器高亮 + 阶段引导；生长到全文。
4. **P4 · Agentic 流转**：印记驱动视图/阶段切换（offer + 始终可撤销）；一次一问收敛；阶段闸（§5）。
5. **P5 · 打磨**：灰色 next-steps 状态条、`批注原文` 内联锚定、全文多状态细化。

## 11. 迁移（旧四房间入口）

**清爽切换（非并存）**：P1 的新壳**取代**四房间的 tab bar——四个房间不再是并列 tab，而是活在新交互区里、经切换器 + AI 抵达。与上一轮「whole-UX 重构」一致（学生端整体替换，不留两套导航）。旧 tab 入口不保留。

## 12. 开放/待定（进 plan 阶段再定的实现细节）

- 决策层视图/阶段意图与现有 turn loop 的**具体接线**（工具名、payload、落库信封）。
- 「最小完整度」判定与**挑战轮次**的具体实现（避免变成隐形评分）。
- 切换器暴露的**视图集**随脊梁阶段动态变化的取值规则。
- 两栏可拖拽宽度的**持久化**（复用 `mk-studio-*` localStorage 惯例）。

## 13. Non-goals（守铁律，明确不做）

- ❌ AI 代写正文 / 花哨排版编辑器 / 代学生提交。
- ❌ 上瘾式游戏化（连胜、排行榜、徽章、推送）。
- ❌ 硬锁流程：阶段闸只 offer、不强制；学生始终可用切换器接管。
- ❌ 隐形评分门槛：阶段推进的判定保持透明可解释。
