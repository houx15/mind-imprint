# 印记 · Agentic Studio 编排器重构（orchestrator redesign）

> 日期：2026-08-07（修订）· 状态：设计草案，待用户复核
> **取代** `docs/superpowers/specs/2026-08-07-agentic-writing-studio-design.md` 的「外壳」部分（§2 布局、§5 流转、§6 写作两栏、§11 迁移）。仍有效：提案要点模型（§4）、计划数据、房间（§7–9）、四条铁律。
> 触发：用户指出原外壳（固定四房间切换器 + 常驻写作两栏 + 固定参考三 tab + 落地即看板）是**错的心智模型**。

## 0. 一句话

把 studio 重构为一个 **agent 编排器**：**印记 = 项目的管理者（类 Cowork，但为学生开工具、绝不替学生做）**，持有项目 **status**，随任务推进把当下这一步的**工作台配置好**、在对话里**叙述并继续引导**；交互区的**宽度随所开工具变形**；参考面板由印记**按当下情境动态组装**，不是锁死的 tab。

## 0.5 北极星：产品 = agent，不是「功能 + 助手」（本次重构的根本诊断）

用户诊断（一针见血）：**现在这东西还是「一堆功能 + 一个 AI 助手」。** 目标是把它**倒过来**：

- **印记就是产品**——一个**真正的 guider / helper**、一个**运行你整个研究项目的 agent**。房间（提案要点、计划、阅读室、探索图谱、写作、体检、复盘）是**它的工具**，不是并列在它旁边的一堆功能。
- 类比：Cowork 不是「带 AI 助手的编辑器」，而是「**用编辑器的 coding agent**」。这里同理——不是「带 AI 对话的写作 studio」，而是「**用这些房间的研究 agent**」。
- **要实现这个，必须有一套真正的 agentic 框架**（一个 agent 循环：持有 status → 规划 → 决定下一步 → 配置工具 → 叙述并引导 → 一次一问），**而不是每个房间各自一段脚本化的 coach prompt**。这是后端的核心新增，见 §8。
- **判定标准**：如果学生的体感还是「我在用一堆功能，旁边有个助手」，就没做到；要做到「**印记在带着我把这个项目做完，它需要什么就给我摆出什么**」。

## 1. 心智模型：印记是编排器（类 Cowork）

- **Cowork 类比**：agent 拆解任务、逐步推进、按需开终端/编辑器/浏览器，人可随时自己插手改文件。
- **这里的差别**：学生**必须自己想、自己查、自己写**——所以印记**不替你做**，而是在对的时刻**把对的工具台配置好交给你**，并叙述 + 继续引导。
- **关键：不是「印记帮你点了个按钮开房间」，也不是「印记 offer 一个按钮、你确认」。** 而是 **印记推进到某一步，配置这一步的工作台是「推进」的自然组成**，然后印记叙述并接着引导。示例语气：
  > 「现在要写了？写作面板我给你开好了，左边把你读过的材料都列出来了。下一步，我们先快速聊聊你的提纲。」

## 2. Status 是脊梁

- 项目在印记管理下，有一个 **status**（当前步 + 已完成的步）。默认序列（**可调**）：
  `立题讨论 → 提案要点成形 → 生成计划 → 写提案（中途 ⇄ 阅读室 / 探索图谱）→ 提案体检 → 写正文（多状态）→ 复盘`
- **Status 决定三件事**：① **resume**（打开项目落在哪）· ② **工作台配置**（开什么工具、左侧放什么参考）· ③ **布局宽度**。
- Status 由印记 **agentic 地驱动推进**，持久化在项目上（新增数据）。

## 3. 布局随工具变形（宽度是变量，不是固定两栏）

- 新项目 → **只有对话，全宽，没有交互区**。
- 讨论出几条提案要点 → 交互区**滑入 ~半宽**（提案要点）。
- 需要阅读室 / 写作 / 项目计划 → 交互区**变宽**，对话收成 **slim rail**。
- 宽度跟着「印记当前开了什么工具」走。切换有过渡动效。

## 4. Resume 落在 status（不再落地即看板）

- 打开一个**还在讨论提案**的项目 → 落在**对话**里接着聊（**绝不**落在项目管理看板）。
- 打开一个**在写作**的项目 → 落在写作台 + 对话 rail + 左侧材料。
- 修复了当前 bug：老项目落地即空 AI 栏的看板。

## 5. 参考面板：印记的、动态的（不是锁死三 tab）

- 左侧参考 = **印记认为你此刻会去查的东西**，动态组装：
  - 你收集的**材料 / 片段**（今天那个浮动「材料」框——**收进左侧**，不再浮动）；
  - 此处**相关的阅读笔记**；
  - **提案要点**——**仅当相关**（写提案时相关；写正文时通常不强推）；
  - **批注**——**仅当印记已体检过**你的写作（没体检就没有批注）。
- **写提案 vs 写正文 → 不同的参考集**。反例：写正文时不该强行摆着提案要点。

## 6. 学生随时接管（像 AI 编码时自己改文件）

- 学生可**手动切到任意视图 / 自己编辑**（材料、写作、计划、阅读……）。
- **手动浏览不改印记的 status**；点「继续印记」时**回到 status 所在的那一步**，与状态保持一致。
- 铁律②：印记引导、推进，但学生**永远能绕开**，不强制、不操纵。铁律①：印记**绝不代写正文**。

## 7. 从当前实现（已上线）到目标——改什么

| | 现状（已上线 @840f8df） | 目标（本 spec） |
|---|---|---|
| 导航 | 固定四房间 Segmented 切换器 | status 驱动 resume + 印记推进步骤（切换器降级为「手动接管」入口） |
| 布局 | 常驻两栏写作 + 交互区总在 | **morphing 宽度**：chat-only → 半 → 宽 |
| 参考面板 | 固定 提案要点/阅读笔记/批注 三 tab | 印记**动态组装**；浮动材料框收进来；批注仅体检后出现；分阶段不同 |
| 落地 | 老项目落地即项目管理看板（AI 栏空） | resume 落在 status（讨论中 → 对话） |
| 印记角色 | 每房间各自的 coach / 看板无 coach | **一个常驻编排器**，永远在，随步骤配置工作台 |

**复用（已有，保留）**：印记连续对话（container-held thread，`StudioChatContext`）· 提案要点数据 + AI-propose→confirm（`dimSuggestion`）· 计划数据 `plan_items` + `plan/generate` · 阅读室 / 探索图谱 · 写作台三态（大纲/片段/正文、整稿体检、导出）· 卡片契约 · recap-in-chat。

## 7.5 P2 · 「聚焦但自由」的交互区 + 五段切换器（本期落地，用户定稿 2026-08-07）

**原则（聚焦但自由）**：交互区只显示**当前步骤的产物**（提案要点 / 计划 / 写作框 / 阅读室），外加学生**可选的直接操作**——绝不放任何**重复印记职责**的按钮。印记常驻对话、由它推进每一步并在对话里叫号（「现在我们来写」「我来生成计划」），所以交互区里任何**触发阶段流转、"聊聊 X"、或重复导航**的按钮/面板/文案都是冗余，删。判定标准：学生看到交互面板，**一眼知道此刻该做什么**；若想参考/探索，随时可点开自由查看。

**「自由」的一半必须可发现**：直接操作（点开编辑笔记、调整/导出计划、选中提问、请印记体检）是**一等可见**的 affordance，不是隐藏手势；五段切换器是随时可用的手动接管入口（副入口，非主导航）。

### 删除清单（P2 执行，冗余 chrome）
- **阶段流转触发**（印记在对话里叫号，非按钮）：`生成项目计划`+regen+「四项聊清楚就能生成」提示、`写开题报告（可选）`、`NextStepGuide`「下一步…去写作/去回顾 →」整个组件、写作头 `去回顾 →`。
- **"聊聊 X" / 第二个 coach 面**（印记 rail 常驻）：`聊聊计划`、阅读室浮动 `问印记·找资料`（FloatingCoach 整块）、写作「和印记聊聊哪里还站不住」文案。
- **导航 / 房间入口文案**（印记路由）：`查看我的题目` 面板、「点『进入 →』去对应房间」文案 + 每张计划卡 `进入 →`、写作头 `看开题 →`/`已归档·看回顾 →`、回顾锁提示 + `去写作房间 →`、写作参考空态「回到『立项』和印记聊聊」。
- **语言切换**：`中/EN`（注意：CreateProjectDrawer 里的作文目标语言项目设置 ≠ 此项，保留）。
- **阅读室 create/record 框**：`记下问题` 输入、`从笔记新建问题`、`用我的研究问题开始` 种子。

### 保留（直接操作，可选、不强制）
- 提案要点：点开**编辑内容**；计划：**调整/重排、导出**；写作：**写作框、选中提问、请印记体检整稿**。
- `让印记看看我的开题`、`让印记找找问题之间的关系`、`开始共读`/`进入阅读室`（打开某来源）、`完成写作`（锁稿）、`定稿并开始评估` —— 都是对**产物**的直接操作，保留。

### 歧义裁决
- `完成写作`：**保留锁稿动作**，去掉其「去回顾 →」路由（印记叫号复盘）。
- `PlanSpine`：**保留只读**「你在这一步」指示，去掉点击跳转。

### 五段切换器（手动接管入口）
`提案 / 管理 / 阅读 / 写作 / 回顾`。今天的 `立项`(key `plan`) 段内部把**提案**(FormingPhase) 与**管理**(BoardPhase) 揉在一起 → P2 **拆成两段**（`BlockKey` 增至 5 键）；整稿体检仍是**写作房间内**的动作，不单列；`回顾` = 今天第 4 段（复盘 + 评估）。resume 的 `openTool` 映射同步扩到五面。

### 布局随工具变形（morphing width，本期真正落地）
`widthTier` 已存（chat/half/wide，`WidthForTool` 派生）。P2 把它**应用**到布局：chat-only 全宽对话（**无交互区**）→ 半宽（提案要点等）→ 宽（写作/计划/阅读，对话收 slim rail）。带过渡动效（设计系统动效四原则）。

## 8. 待实现 / 待定（进 plan 阶段细化）

- **★ 真正的 agentic 框架（后端核心，§0.5 的落地）**：把「每房间各自一段 coach prompt」换成**一个 agent 循环**——印记在一次交互里能：
  1. **读全局 status + 项目状态**（提案要点、计划、材料、写作、体检）；
  2. **规划 / 判定下一步**（该继续讨论？该生成计划？该去写？该开阅读室？）；
  3. **用工具**：一组结构化的 agent 动作（`set_status`、`open_tool(room)`、`curate_reference(items)`、`propose_note`、`summon_card`、`request_review`…）——tool-use / function-calling 式接线，前端据此配置工作台；
  4. **叙述 + 引导**：在对话里说清「我配了什么、下一步做什么」，一次一问。
  与现有 `summon_card` 单函数接线同源，但从「单个卡片提议」升级为「**驱动整个项目推进的 agent 循环 + 工具集**」。旗舰模型；决策绝不降级。
- **Status 状态机**：存储（项目上的 status 字段/表）+ 由上面的 agent 循环推进（而非散落在各房间的规则）。
- **交互区宽度档位**（0 / 半 / 宽）+ 切换过渡；对话 full ⇄ rail。
- **参考面板动态组装规则**：印记按 status + 当前段落选什么；学生可 pin/unpin；材料/片段从浮动框迁入。
- **「继续印记」交互**：手动接管后如何回到 status。
- **手动接管入口**（切换器/plan）的形态——降级为副入口，不再是主导航。
- 印记推进时的**叙述语气**（叙述已配置好的工作台 + 引导下一步，一次一问）。

## 8.5 硬约束（Global Constraints）

- **仍遵守设计系统**：整个重构继续遵循 `docs/superpowers/specs/2026-08-06-design-system-design.md`——accent 随人、7 马卡龙、字体尺度、圆角、动效四原则、Lucide 图标、AI 四态/召唤卡/composer、Voice&Tone、插画规范。Tailwind gotcha 照旧：同属性一个 class；**绝不** `bg-mk-<hex-token>/<opacity>`（渲染透明）。
- **不考虑旧数据兼容**：产品**尚未真实使用**，可**自由做破坏性数据变更**——直接改 schema / 删旧表 / 不写兼容迁移 / 不保留旧字段。以**最干净的目标数据模型**为准，不为老数据妥协。

## 9. Non-goals（守铁律）

- ❌ 印记代写正文 / 花哨排版 / 代提交。
- ❌ 强制流转：印记推进是引导，学生随时可接管、status 不被打扰。
- ❌ 把交互区做成固定不变的多栏——宽度必须随任务变形。
- ❌ 上瘾式游戏化。
