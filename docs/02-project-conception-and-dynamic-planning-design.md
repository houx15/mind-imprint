# PBL 深度思考工具设计 01：项目构想与动态规划

> 日期：2026-09-01  
> 关联调研：[从线头到解决方案计划](./01-idea-observation-to-solution-plan.md)

## 一、产品背景

产品的基本形态类似 Codex、Cowork 等工作型 Agent：学生提出一个目标或带来一个任务，AI理解目标、提出步骤，并与学生在持续对话中共同完成项目。AI可以研究、设计、编程、生成图片与文档、制作原型、测试和综合反馈；学生保留问题选择、需求定义、优先级、成功标准和最终接受或拒绝权。

项目型学习并不要求所有产物都由学生亲手制作。需要保留的是学生对项目的认知控制：学生能够搭建和修改结构、把模糊想法表达清楚、审查AI的理解与产出、比较不同方向，并明确作出决定。

本设计聚焦项目开始及早期演化阶段：

- 学生完全没有想法时，AI如何帮助他从生活和现实世界中发现线头；
- 学生已经有观察、兴趣、问题或解决方案时，AI如何从其当前状态继续；
- AI如何生成一份可以立即开始、但允许不断变化的项目计划；
- 项目执行过程中，新的观察和证据如何触发专门的思考Session；
- 每次重要计划变化如何邀请学生共同审阅和决定。

## 二、核心产品判断

### 1. 构想和执行不设严格分界

学生不需要先把问题完全定义清楚，才能创建项目。项目可以从一张照片、一句抱怨、一个兴趣、一个问题、一个现成方案或一个外部任务开始。

AI可以根据当前已知内容创建项目v0.1，把观察、调查、理解和重新定义问题直接列为早期步骤。学生可以边做边想；第一次制作也可以是帮助理解问题的原型。

### 2. 主体验仍然是项目对话与执行

观察日记、便利贴、Problem Tree、问题转换和方案合并等交互均为主项目中的专门Session或辅助空间，不取代主要的Agent对话、项目步骤和工作成果。

### 3. AI规划必须是动态规划

第一次计划只是根据当前理解提出的暂定计划。完成步骤、得到证据、发现矛盾或改变目标后，AI应重新评估计划，并向学生解释建议修改什么、为什么修改。

### 4. 深度思考以计划变化为结果

Thinking Session不能只产生一份孤立的反思记录。一次有效Session应当至少产生以下一种结果：

- 新增或修改项目问题；
- 区分证据与猜测；
- 改变目标人物或需要；
- 形成新的How Might We；
- 生成、组合或淘汰方案；
- 修改项目步骤、优先级、成功标准或测试方式；
- 明确保留原计划的理由。

### 5. 学生不承担长篇输入负担

学生可以通过语音、照片、绘画、短句、选择、排序、连接、移动和修改关键词参与。AI负责转录、整理和生成长文本；学生负责纠正、比较、重组和决定。

## 三、整体产品结构

```text
观察日记 / 学生输入 / 外部任务
                ↓
        AI判断学生当前状态
                ↓
   创建项目v0.1或建议Thinking Session
                ↓
          学生与AI执行步骤
                ↓
   新观察 / 新证据 / 矛盾 / 关键决定
                ↓
        专门的Thinking Session
                ↓
            Plan Checkpoint
                ↓
 学生接受 / 修改 / 保留原计划 / 创建分支
                ↓
          更新项目计划并继续执行
```

系统由五个主要部分组成：

1. **观察日记**：项目之外持续捕捉现实世界材料，并可生成项目线头；
2. **主项目对话**：学生与AI讨论目标、执行任务和审阅成果；
3. **动态项目计划**：记录当前目标、步骤、依赖、未知和复查节点；
4. **Thinking Session**：针对具体认知任务提供不同于普通对话的交互；
5. **Plan Checkpoint**：把思考和证据转换成学生可审阅的计划变化。

## 四、学生状态与路由

系统不先问“你有没有想法”，而是从学生输入和项目历史判断当前状态。状态可以随项目变化，不是学生的固定标签。

| 当前状态 | 典型输入 | AI的默认动作 |
| --- | --- | --- |
| 没有方向 | “我不知道做什么” | 启动寻找线头Session |
| 有兴趣或感受 | “我最近很在意浪费” | 帮助连接具体场景和观察 |
| 有一条观察 | “食堂每天剩很多饭” | 展开问题并选择一次现实求证 |
| 有问题 | “为什么新生总是迟到？” | 区分开放/封闭问题，确定调查方式 |
| 已有解决方案 | “我想做一个校园导航App” | 拆开观察、假设和预设答案，建议现实检查 |
| 目标较清楚 | “我要给新生做一个校园导航工具” | 直接创建暂定计划，把验证和选择放入步骤 |
| 外部指定任务 | “老师要求做气候变化项目” | 帮助学生找到自己的切入点、受众和行动方向 |
| 正在执行但卡住 | “我们做不下去了” | 判断卡在信息、理解、方案、决策、协作还是执行 |
| 新证据改变理解 | “访谈结果和我们想的不一样” | 启动reframe并提出计划差异 |

AI的路由应满足：

- 不让所有学生完成同一套启动问卷；
- 不因学生缺少问题证据而拒绝创建项目；
- 不因学生已经有方案而强迫他从零完成完整设计思维流程；
- 明确告诉学生当前哪些内容是暂定的；
- 允许学生跳过AI建议的Session，但在计划中保留相应未知和风险。

## 五、观察日记

### 1. 产品定位

观察日记是项目之外的低压力捕捉空间。它的目的不是训练长篇写作，而是帮助学生逐渐形成“留意现实、保存疑问、回看模式”的习惯。

学生可以记录：

- 一张照片；
- 一幅画或场景草图；
- 十秒语音；
- 一句“我不明白为什么……”；
- 一个让自己烦恼、惊讶、感动或反复想到的瞬间；
- 看到别人费力完成的动作；
- 一个临时办法、变通方式或已有解决方案；
- 一条新闻、网页、数据或实物线索。

### 2. 观察提示

AI可以按学生年龄、环境和已有兴趣提供一次性观察任务，例如：

- 找一个大家已经习惯、但其实很奇怪的现象；
- 找一个有人正在费劲完成的动作；
- 记录一个让你想问“为什么必须这样”的规则；
- 找一个做得很好、也许可以帮助更多人的地方；
- 描绘一件事发生前、发生时和发生后的样子；
- 记录一个你和别人看法不一样的时刻。

观察任务应允许在两分钟内开始，不要求学生提前选择项目主题。

### 3. AI从日记中发现线头

AI可以定期提出模式假设：

> 你最近三次记录都和“新生不知道该去哪里”有关。这可能是一条值得继续的线头。你想展开、继续观察，还是先留在日记里？

AI不能把重复记录直接转化为固定兴趣、能力或人格标签。学生必须能够：

- 确认AI看到了重要联系；
- 修改AI的概括；
- 认为这些记录彼此无关；
- 暂存线头；
- 将线头发展成项目。

## 六、没有想法的学生：寻找线头Session

### 目标

让学生从自己的生活和现实世界中获得一至三条愿意继续探索的线头，并形成一个可以立即开始的项目v0.1。

### 过程

#### 1. 选择发现入口

学生选择一个轻量入口：

- 从自己最近反复想到的事情出发；
- 从身边环境出发；
- 从一个想帮助的人出发；
- 让AI提供一次观察任务；
- 从过去的观察日记中寻找。

这只是寻找线头的方式，不是项目类型选择。

#### 2. 描绘、观察或记录

学生完成一个短任务，并通过语音、图片、画或短句提供材料。AI不要求学生解释完整原因。

#### 3. AI与学生共同提取线头

AI将材料整理成若干简短候选，例如：

- 午餐后有很多没吃完的食物；
- 新生不知道垃圾怎样分类；
- 图书馆安静区经常有人讨论；
- 值日生有一种有效的分工方式。

学生删除、纠正、补充或合并，然后选择一条“我愿意多知道一点”的线头。

#### 4. 问题发散与选择

学生先提出问题，AI随后扩展。问题不立即回答。学生练习：

- 识别能打开更多故事的问题；
- 识别可以查清、测量或验证的问题；
- 在开放与封闭形式之间转换；
- 识别已经把解决方案写入问题的表达；
- 选择一个回答后可能改变项目方向的问题。

#### 5. 完成一次现实求证

AI根据焦点问题建议二至三个动作：观察、访谈、资料查证、小实验、体验模拟或已有方案分析。学生选择并完成一个。

#### 6. 选择项目意图

根据目前材料，AI可以提出不同的项目意图：

- 调查清楚一个现象；
- 解释或表达一个判断；
- 尝试改变一个现实状况；
- 设计并测试一种服务、流程、作品或工具。

媒介不在此阶段预设。

#### 7. 创建项目v0.1

AI生成一段简短暂定目标，并提出动态计划。计划应明确：

- 当前已经知道什么；
- 仍在猜测什么；
- 第一轮准备做什么；
- 在哪个节点重新决定方向。

## 七、已有想法的学生

### 1. AI先拆解而不否定

例如学生说：

> 我想做一个帮助学生管理作业的AI App。

AI可以识别：

- 关注的事情：作业管理；
- 可能的人物：学生；
- 已经预设的方案：AI App；
- 仍未知：谁最需要、目前怎样处理、真正困难是什么。

AI应尊重学生想立即开始的意愿，同时明确哪些判断仍是暂定的。

### 2. 按风险选择动作

- 目标和受众清楚：直接规划；
- 范围太大：建议聚焦Session；
- 只有方案、没有现实依据：建议现实检查Session；
- 涉及多个原因和人物：建议理解问题Session；
- 学生坚持先制作：把第一版定位为学习型原型，并预设测试与reframe步骤。

### 3. 将理解活动写入计划

AI不要求学生在开工前完成所有调查。暂定计划可以是：

1. 快速做出一个最小概念版本；
2. 找几位可能用户实际尝试；
3. 观察他们在哪一步真正需要帮助；
4. 用Who / Need / Why重新定义需要；
5. 比较继续做AI App、简化工具或改变流程；
6. 学生决定正式方向；
7. AI协助实现和测试。

## 八、持续Reframe框架

面向学生时，使用四个容易理解、可以反复调用的问题：

### What：发生了什么？

聚焦具体观察：谁在做什么、什么时候发生、哪个瞬间值得注意。

### Why：为什么可能发生、为什么重要？

产生原因、动机和意义的解释。此处答案默认是待验证假设，除非已有证据支持。

### How：怎样进一步理解？

选择观察、访谈、查询、实验、体验或比较等求证方式，而不是立即进入解决方案。

### What might we do：我们可能采取什么行动？

在理解暂时可用后进入方案空间，探索信息、行为、环境、流程、服务、作品、数字产品或其他机制。

当方向逐渐聚焦时，AI再将相关材料整理成一个正式的How Might We。一个合适的How Might We应：

- 指向具体的人和情境；
- 来自前面的发现；
- 保留多个可能答案；
- 不提前规定App、海报、视频等媒介；
- 足够具体，可以行动；
- 不窄到只剩一个答案。

四个问题不是一次走完的固定流程。测试方案后，学生可能重新回到What，修正对现实的描述。

## 九、共同头脑风暴、Merge与方案发展

### 1. 发散

AI和学生都可以提出方案。AI应主动覆盖不同改变机制：

- 消除不必要步骤；
- 改变信息出现的时间或方式；
- 改变空间、流程或规则；
- 改变人的行为或协作关系；
- 使用已有资源；
- 提供一种服务或行动；
- 制作表达作品；
- 制作数字、实体或AI工具。

AI不能默认把问题变成App。

### 2. Merge

学生可以选择几条方案执行：

- 组合两个不完整想法；
- 保留机制，替换媒介；
- 做一个不用新技术的版本；
- 从另一人物视角修改；
- 将大方案缩成可测试的小版本；
- 要求AI生成不同规模或不同约束下的版本。

### 3. 比较

比较标准应在AI推荐“最佳方案”之前由学生确认。标准可以来自：

- 是否回应目标人物的需要；
- 是否作用于重要原因；
- 能否在当前时间和资源内行动；
- 是否会给其他人增加负担或风险；
- 是否容易制作低成本原型；
- 是否能够获得真实反馈；
- 学生是否愿意持续投入。

AI可以说明权衡和未知，不能用缺少依据的总分替学生作决定。

### 4. Next Bet

方案阶段的终点是一项暂定的下一轮尝试，而不是最终解决方案。Next Bet至少说明：

- 当前关注的人和需要；
- 选择的方案方向；
- 仍未验证的关键假设；
- 第一版要做出的原型、行动或调查；
- AI和学生各自承担什么；
- 找谁测试；
- 什么现象支持继续；
- 什么现象意味着需要修改或放弃。

## 十、动态项目计划

### 1. 计划版本

每份计划都有版本号，例如v0.1、v0.2。版本变化记录的是理解和决定的变化，不是每次任务状态更新。

### 2. 步骤信息

每个步骤至少包含：

- 步骤目标；
- 为什么现在需要这一步；
- 学生负责什么；
- AI可以完成什么；
- 依赖的证据或决定；
- 当前状态；
- 完成后是否需要Plan Checkpoint。

步骤状态可以是：

- 已确定；
- 暂定；
- 等待调查结果；
- 等待学生决定；
- 已完成；
- 已修改；
- 已取消。

### 3. 触发重新规划的事件

出现以下情况时，AI应评估是否修改计划：

- 学生改变目标或兴趣；
- 新观察与原假设矛盾；
- 出现新的目标人物或利益冲突；
- 方案测试失败或产生意外使用方式；
- 任务范围、时间、资源或权限发生变化；
- 连续多次执行失败；
- 学生或AI发现计划跳过关键问题；
- 项目进入需要选择、接受或拒绝的节点。

机械性的进度更新不触发共同审阅，例如“将已完成步骤标为完成”。

## 十一、Plan Checkpoint：共同审阅计划变化

每次重要重规划都通过一个简短、可审阅的Plan Checkpoint完成。

### 1. 我们刚刚学到了什么？

列出具体的新观察、测试结果或决定。

### 2. 它改变了什么？

指出受影响的目标、人物、需要、方案、成功标准或步骤。

### 3. AI建议怎样修改计划？

使用清楚的差异表达：

```text
删除：重新设计地图内容
新增：观察学生是否能看到地图
修改：先测试入口提示，再决定是否重做地图
```

### 4. 提出一个有张力的判断问题

问题必须引用当前项目证据，例如：

> 原来认为新生看不懂地图，但观察中有四位新生根本没有发现地图。你认为应该修改问题，还是保留两个解释继续调查？

### 5. 学生决定

学生可以：

- 接受修改；
- 修改AI建议；
- 保留原计划；
- 同时尝试两个方向；
- 创建一条思考分支；
- 暂不决定，先补充证据。

涉及问题选择、目标人物、需求、优先级、成功标准、成果方向或重大范围变化时，AI必须取得学生明确决定。

## 十二、Thinking Session机制

### 1. Session合同

每个Session必须定义：

- 触发条件；
- 从主项目带入的材料；
- 希望学生完成的认知动作；
- AI可以完成的工作；
- 中间证据；
- 结束条件；
- 返回主项目时建议修改的内容。

### 2. 首批Session

| Session | 触发场景 | 核心动作 | 输出 |
| --- | --- | --- | --- |
| 寻找线头 | 完全没有想法 | 描绘、观察、记录、聚类 | 候选线头 |
| 问题发散与选择 | 有现象但不知道问什么 | 生成、开放/封闭转换、排序 | 当前焦点问题 |
| 现实检查 | 已有方案但缺少依据 | 事实/猜测拆分、现实求证 | 证据与关键未知 |
| 理解与Reframe | 人物、原因或需要不清 | What / Why / How、Who / Need / Why、可选Problem Tree | 问题视角与How Might We |
| 方案工作坊 | 已有How Might We | 发散、Merge、比较、发展 | 方案方向与Next Bet |
| Plan Checkpoint | 新信息影响计划 | 查看差异、判断、接受或拒绝 | 新计划版本或保留原计划 |

## 十三、学生与AI的权限边界

| 工作 | 学生 | AI |
| --- | --- | --- |
| 捕捉观察和兴趣 | 提供真实经历、照片、语音、材料 | 提示观察、转录和整理 |
| 提出问题 | 生成、修改、选择重点问题 | 扩展、分类、提示问题中的预设答案 |
| 形成解释 | 判断哪些解释值得继续 | 提出多个解释，标记证据与假设 |
| 现实调查 | 接触真实场景和人物，完成不能被AI替代的活动 | 设计观察、访谈、问卷或实验工具 |
| 方案生成 | 提出、重组、评价和决定 | 研究、生成、扩展、组合和模拟方案 |
| 成果制作 | 定义要求、审阅、接受或拒绝 | 设计、写作、编程、生成媒体和测试 |
| 计划维护 | 决定目标、优先级、成功标准和重大变化 | 发现依赖与风险，提出动态计划和差异 |

## 十四、AI识别浅层思考的信号

AI不以输入字数判断深度。需要关注：

- 学生把猜测描述成亲眼观察；
- 用AI生成的persona代替真实人物证据；
- 目标人物始终是“所有人”；
- 问题中已经包含唯一方案；
- 所有方案只是同一产品的功能变化；
- 选择标准在学生选定喜欢的方案后才出现；
- 方案与学生自己确认的需要或标准矛盾；
- 计划只有成功路径，没有可能推翻方向的结果；
- AI完成了关键判断，学生没有明确接受、修改或拒绝；
- 新证据出现后，问题和计划没有任何变化，也没有保留原判断的理由。

AI发现这些信号时，不要求学生写长篇解释，而是提出一个具体矛盾和一个可执行动作，例如：

> 你写的是“同学们不想排队”，但访谈原话是“排队没关系，不知道吃什么才烦”。要修改问题，还是保留原判断并继续调查？

## 十五、年龄与能力脚手架

脚手架根据学生当前表现调整，不只依据年龄。

| 专业概念 | 儿童表达 |
| --- | --- |
| 开放问题 | 能打开更多故事的问题 |
| 封闭问题 | 能查清楚的问题 |
| Observation | 我真的看见或听见的 |
| Assumption | 我现在猜的 |
| Stakeholder | 这件事影响到谁 |
| How Might We | 我们可以怎样让它变好 |
| Success criterion | 发生什么就说明有帮助 |

低龄和初学者主要使用语音、照片、绘画、排序、选择和情境故事；高龄或熟练学生逐渐加入证据质量、利益冲突、系统因果、伦理限制、可证伪假设和更自主的计划修改。随着学生表现出稳定能力，AI应减少提示和候选答案。

## 十六、首版范围

首版只验证从线头到动态项目的核心闭环：

```text
多模态观察日记
→ AI建议候选线头
→ 学生选择是否展开
→ 问题生成、转换和选择
→ 一次现实求证
→ What / Why / How与证据/猜测区分
→ How Might We
→ AI与学生共同头脑风暴
→ Merge、比较和Next Bet
→ 创建项目v0.1
→ 执行后触发Plan Checkpoint
→ 学生审阅并生成项目v0.2
```

首版暂不包含：

- 复杂的实时多人协作；
- 完整教师评分后台；
- 积分、徽章和排行榜；
- 大型无限画布；
- 覆盖所有方法论的工具库；
- 自动发布到公共平台；
- 把AI推断的兴趣固化为长期标签。

## 十七、首版验证问题

产品试点应观察：

1. 没有想法的学生能否从自己的观察中形成愿意继续的线头？
2. 学生是否能够纠正AI对日记和项目的概括？
3. 学生是否会在新证据出现后修改问题、方案或计划？
4. AI生成的方案是否覆盖不同改变机制，而不集中为App？
5. 学生能否解释为什么接受、组合或拒绝AI建议？
6. Plan Checkpoint是否帮助学生理解计划变化，还是造成频繁打断？
7. 学生能否区分观察、猜测、他人观点和AI推断？
8. 随着项目增加，学生是否逐渐主动使用What / Why / How / What might we do？
9. 学生换到新项目时，是否能以更少脚手架完成相同认知动作？

不应把完成率、在线时长、文字长度或最终作品精美程度单独视为深度思考证据。

## 十八、尚待决定

1. 观察日记是独立长期区域，还是主Agent中的一种可调用视图？
2. AI在什么频率下可以主动提醒学生记录或回顾，避免变成打卡负担？
3. 项目v0.1诞生前，最低需要一条学生确认的线头，还是还需要一次现实求证？
4. 当学生坚持立即制作时，哪些高风险项目必须先完成安全、隐私或现实验证？
5. Plan Checkpoint的频率如何根据项目时长和学生能力调整？
6. 计划差异由AI自动生成后供学生审阅，还是高龄学生应先提出自己的修改？
7. 如何保存被淘汰但未来可能重新启用的问题和方案，同时避免项目材料过载？
8. 科学探究、艺术创作、公共行动和产品设计是否共享同一套项目构想状态，还是需要不同终点？
9. 如何让观察日记与学生长期兴趣地图建立联系，同时避免固定化标签？
10. 哪些信息应进入教师视图，既能判断过程，又不把学生的私人日记全部暴露？

## 十九、证据与成熟度边界

本文件是根据现有PBL、设计思维、青少年社会创新和创业课程调研形成的产品设计，尚未经过学生使用、课堂试点或学习效果验证。首版实现前仍需通过情境走查和小规模用户研究检验学生是否愿意记录、能否理解计划变化，以及AI建议是否真正帮助学生保留项目控制权。
